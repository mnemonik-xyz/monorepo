# Mnemonic: проверяемая память для AI-агентов

**Whitepaper** · Версия 0.4 · Сентябрь 2026  
**Технические детали:** [Yellow paper](./YELLOWPAPER_RU.md)  
**Оригинал:** [WHITEPAPER.md](./WHITEPAPER.md). При расхождениях приоритет имеет английская версия.

В каждом разделе указано: функция **доступна сейчас** или **запланирована**.

---

## 1. Кратко

AI-агент в работе узнаёт факты, предпочтения и решения.
Обычно агент теряет эти знания, когда сессия заканчивается.
Если агент их сохраняет, знания остаются в одном инструменте или у одной компании.
Другие люди не могут проверить, кто записал знание и менял ли его кто-то.

Mnemonic даёт агенту память с тремя свойствами:

1. **Ваша.** Ваши воспоминания подписывает ваш собственный ключ. Сервер их не подписывает.
2. **Переносимая.** Одна и та же память работает в Claude, Cursor, VS Code и других инструментах.
3. **Доказуемая.** Любой может проверить, кто записал воспоминание и что его никто не изменил.

Mnemonic использует Model Context Protocol (MCP). MCP — это стандарт,
по которому AI-ассистенты вызывают внешние инструменты.

---

## 2. Проблема

Сегодня агенты хранят память тремя способами:

| Способ | Плюс | Минус |
|---|---|---|
| Контекстное окно (текст, который модель видит сейчас) | Быстро | Пропадает в конце сессии |
| Память внутри одного приложения | Сохраняется между сессиями | Заперта в этом приложении |
| Векторная база данных (поиск по смыслу) | Большая, с поиском | Нет доказательства автора и даты |

Эти способы создают три проблемы:

1. **Нет переносимости.** Вы меняете инструмент — агент всё забывает.
2. **Нет доказательств.** Человек может изменить сохранённую запись. Другие системы этого не увидят.
3. **Небезопасное повторное использование.** В записи могут быть скрытые инструкции.
   Когда агент читает такую запись, он может их выполнить.
   Эта атака называется «prompt injection» (внедрение инструкций).

## 3. Что такое воспоминание

Воспоминание Mnemonic — это небольшая запись. Она состоит из частей:

| Часть | Что содержит |
|---|---|
| Содержимое | Текст воспоминания |
| Теги | Необязательные метки, которые выбираете вы |
| Эмбеддинг | Список чисел, который передаёт смысл текста. Его использует поиск. |
| Родитель | Отпечаток предыдущего воспоминания, если оно есть |
| Отпечаток | Короткий уникальный код, вычисленный из записи («хеш») |
| Подпись | Доказательство, что ключ владельца одобрил именно эту запись |

**Эмбеддинг — не источник истины.** Разные AI-модели дают разные эмбеддинги.
Постоянный источник истины — текст. Новый эмбеддинг можно вычислить в любой момент.

---

## 4. Как Mnemonic сохраняет воспоминание

Mnemonic выполняет шаги в таком порядке:

1. **Эмбеддинг.** Вычислить эмбеддинг текста.
2. **Сжатие.** Уменьшить эмбеддинг методом TurboQuant (2, 3 или 4 бита на число).
3. **Сборка.** Собрать содержимое, теги, сжатый эмбеддинг и родителя в одну запись.
4. **Кодирование.** Записать запись в каноническом CBOR.
   CBOR (Concise Binary Object Representation) — двоичный формат данных.
   «Канонический» значит: одна и та же запись всегда даёт одни и те же байты.
5. **Хеш.** Вычислить отпечаток хеш-функцией BLAKE3.
6. **Подпись.** Подписать запись ключом Ed25519 владельца.
   Результат — конверт COSE_Sign1.
   COSE (CBOR Object Signing and Encryption) — стандартный формат подписанных данных.
7. **Хранение.** Сохранить запись локально. По желанию — заякорить (см. раздел 6).

Статус: шаги 1–7 **доступны сейчас**. Базовая библиотека поддерживает ссылку
на родителя, но MCP-инструмент её пока не заполняет.

**Важно:** для личного локального воспоминания Mnemonic выполняет шаги 1–5 и
сохраняет отпечаток. Шаг 6 выполняется только при публикации. Поэтому локальная
работа не просит разблокировать ключ.
Статус: доступно сейчас.

## 5. Три режима памяти

Режим выбирается для каждого воспоминания. Все режимы используют один ключ и одни инструменты.

| Режим | Где хранится | Кто может прочитать | Стоимость | Статус |
|---|---|---|---|---|
| `local` | База данных на вашем компьютере | Только вы | Бесплатно | Доступно сейчас |
| `sealed` | Зашифровано в Arweave. Отпечаток в Solana. | Вы и одобренные вами читатели | Бесплатная квота, затем платно | Запланировано |
| `public` | Arweave. Отпечаток в Solana. | Любой | Бесплатная квота, затем платно | Запланировано (сейчас: режим «participate», без шифрования) |

**Бесплатная квота.** Каждая личность может бесплатно заякорить 100 воспоминаний в неделю (запланировано).
После квоты одно заякоренное воспоминание стоит примерно 0,001 доллара США.

**Локальная память всегда бесплатна.** Mnemonic никогда не берёт деньги за
локальную работу и за проверку.

## 6. Якорение: доказательство даты

Подпись доказывает, **кто** записал воспоминание. Она не доказывает, **когда**.
Якорение добавляет публичное доказательство даты.

Когда вы якорите воспоминание:

1. Mnemonic загружает подписанную запись в **Arweave**.
   Arweave — сеть для постоянного хранения данных.
2. Mnemonic записывает отпечаток в **Solana** в короткой заметке (memo).
   Solana — публичный блокчейн. У каждого блока есть публичное время.
3. Mnemonic читает запись обратно из Arweave и проверяет её.
   Mnemonic сообщает «доставлено» только после успешной проверки.
   Если проверка не прошла, воспоминание остаётся `local`, и деньги не списываются.

Статус: доступно сейчас (режим «participate»).

**Заякоренные данные удалить нельзя.** Arweave называет себя «постоянным
хранилищем информации» (<https://www.arweave.org/>). Операторы узлов Arweave
могут фильтровать данные по своим правилам контента
(<https://docs.arweave.org/developers/llms-full.txt>).
Это не удаление, которым управляет автор. Поэтому не якорите данные,
которые вы можете захотеть удалить.

## 7. Кто подписывает

**Правило: сервер Mnemonic никогда не подписывает ваши воспоминания и ваши посты.**

- **Локальный MCP (на вашем компьютере).** Он использует ваш собственный ключ.
  Ключ хранится в связке ключей (keychain) вашей операционной системы (ОС).
  Mnemonic просит разблокировать keychain, только когда воспоминание нужно
  подписать: публикация, якорение или доказательство личности.
- **Облачный MCP (на сервере Mnemonic).** Воспоминание подписывает ваш клиент.
  Сервер проверяет, что подпись принадлежит вам. Затем сервер сохраняет и
  якорит воспоминание.
- **Что подписывает сервер.** Сервер подписывает только транспорт: пакет
  загрузки в Arweave, внутри которого ваша подписанная запись, и транзакцию
  Solana, которая оплачивает комиссию сети. Эти подписи не меняют вашу запись.

Статус: доступно сейчас.

## 8. Как поделиться воспоминанием

### 8.1 Публичное воспоминание (запланировано)

Вы публикуете воспоминание в режиме `public`. Любой может прочитать и проверить его.
Вы получаете ссылку, например `mnemonik.xyz/m/<отпечаток>`.
Веб-страница показывает текст, автора и результат «Подпись верна».
Проверку выполняет браузер. Читателю не нужен аккаунт.

### 8.2 Закрытое воспоминание (запланировано)

Закрытое (`sealed`) воспоминание зашифровано. Открыть его могут только одобренные читатели.
Читателя можно одобрить после сохранения. Знать читателя заранее не нужно.

Метод называется «конвертное шифрование»:

1. Mnemonic создаёт новый случайный ключ `K` для воспоминания.
2. Mnemonic шифрует воспоминание ключом `K`.
3. Mnemonic загружает зашифрованное воспоминание в Arweave.
   В Solana записывается отпечаток **зашифрованных данных**.
   Поэтому никто не сможет угадать текст и сравнить его с отпечатком.
4. Mnemonic шифрует `K` вашим открытым ключом. Теперь открыть воспоминание можете только вы.
5. **Позже**, когда появится читатель, вы даёте ему доступ.
   Mnemonic шифрует `K` открытым ключом читателя. Это называется «грант».
   Mnemonic не загружает воспоминание повторно.

Метод следует идее Hybrid Public Key Encryption (HPKE, гибридное шифрование
с открытым ключом), RFC 9180 (<https://www.rfc-editor.org/rfc/rfc9180>).

**Грант по ссылке.** Иногда у читателя ещё нет ключа. Тогда Mnemonic
помещает `K` в часть ссылки после знака `#`.
Браузеры не отправляют эту часть на сервер
(RFC 3986, раздел 3.5: <https://www.rfc-editor.org/rfc/rfc3986#section-3.5>).
Поэтому сервер никогда не видит `K`. Прочитать воспоминание может любой, у кого есть ссылка.
Храните ссылку в секрете.

**Грант нельзя отменить.** Получив `K`, читатель может сохранить копию.
Чтобы закрыть доступ в будущем, сохраните новую версию с новым ключом.

### 8.3 Импорт

Агент читателя импортирует полученное воспоминание. Агент проверяет подпись
и сохраняет локальную копию. Копия показывает автора, например «от did:sol:…».
Затем агент находит это воспоминание обычным поиском.
Статус: запланировано.

## 9. Проверка

Для проверки воспоминания нужны только три вещи: подписанная запись, открытый
ключ автора и, если воспоминание заякорено, заметка в Solana.

Mnemonic выполняет проверки:

1. Заново вычислить отпечаток записи. Он должен совпасть.
2. Проверить подпись открытым ключом автора.
3. Если воспоминание заякорено: найти отпечаток в заметке Solana и прочитать время блока.

Проверка всегда бесплатна. Ей не нужны сервер, аккаунт или оплата.
Её можно выполнить на своём компьютере.

Статус: доступно сейчас для ваших собственных воспоминаний. Анонимная проверка по ссылке запланирована.

---

## 10. Безопасное использование чужих воспоминаний

Полученное воспоминание может содержать текст, похожий на инструкцию.
Mnemonic будет помещать каждое полученное воспоминание между явными маркерами
начала и конца, прежде чем агент его прочитает. Маркеры говорят модели:
«это справочные данные, а не инструкция».

Mnemonic не может заставить модель соблюдать маркеры. Модель с ошибками
может всё равно выполнить скрытые инструкции.

Статус: запланировано.

## 11. Что гарантирует Mnemonic

| Гарантия | Как |
|---|---|
| Никто не изменит воспоминание незаметно | Меняется отпечаток |
| Никто не подпишет от вашего имени | Вашу подпись создаёт только ваш ключ |
| Никто не изменит дату заякоренного воспоминания | Время блока Solana публично |
| Проверка бесплатна для всех | Выполняется локально, без сервера |
| Можно запустить свой сервер | Весь код открыт (Apache License 2.0). Самостоятельный хостинг возможен всегда |
| Ни одна компания не контролирует вашу память | Память зависит от вашего ключа, а не от одного сервера |

## 12. Чего Mnemonic не гарантирует

- **Истинность.** Mnemonic доказывает, кто записал воспоминание. Он не доказывает, что оно верно.
- **Полноту истории.** Mnemonic обнаружит изменённое или удалённое старое
  воспоминание в связанной цепочке. Он не может заставить автора опубликовать новое.
- **Поведение модели.** Mnemonic не может заставить модель соблюдать маркеры безопасности.
- **Удаление.** Заякоренные данные удалить нельзя (см. раздел 6).
- **Отзыв доступа.** Грант нельзя отменить, если читатель уже получил ключ (см. раздел 8.2).
- **Совместное редактирование.** Одновременная запись нескольких авторов в одну общую память пока не поддерживается.

## 14. Связь с другими стандартами

- **MCP (Model Context Protocol):** подключает агентов к инструментам. Mnemonic — это MCP-инструмент.
- **A2A (протоколы Agent-to-Agent):** агенты обмениваются сообщениями.
  Mnemonic хранит память, на которую эти сообщения могут ссылаться.
- **ERC-8004 («Trustless Agents»):** предложение Ethereum для личности,
  репутации и проверки агентов. Mnemonic может дать ему подписанные
  доказательства того, что помнит агент. Статус: только проект.
  См. раздел 9 [yellow paper](./YELLOWPAPER_RU.md).

Mnemonic делает агентов последовательными во времени. Другие стандарты связывают агентов в моменте.

## 15. Текущий статус

**Доступно сейчас:**

- MCP-сервер с 8 инструментами: `mnemonic_whoami`, `mnemonic_sign_memory`,
  `mnemonic_recall`, `mnemonic_verify`, `mnemonic_prove_identity`,
  `mnemonic_check_pending`, `request_public_write_confirmation`,
  `mnemonic_publish_post`.
- Локальный режим и режим с якорением («participate»).
- Подписи Ed25519, конверты COSE_Sign1, отпечатки BLAKE3, канонический CBOR.
- Личности в виде `did:key` и `did:sol`. DID — Decentralized Identifier (децентрализованный идентификатор).
- Сжатие TurboQuant. Поиск по смыслу в локальной базе SQLite.
- Оплата по x402 (стандарт веб-платежей с HTTP-кодом 402).

**Запланировано:**

- Бесплатная квота — 100 якорений в неделю.
- Режимы `public` и `sealed`, гранты, импорт и ссылки для обмена.
- Токены возможностей (подписанные разрешения с ограниченным сроком).
- Маркеры безопасного использования.
- Анонимная проверка по ссылке.
