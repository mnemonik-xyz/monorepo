# User Spec: Agentic Swap — агентские атомарные свопы поверх HTLC

## Что делаем

Даём ИИ-агентам и людям один протокол для внебиржевых (OTC) кросс-чейн свопов:

1. **Переговоры** — агенты обмениваются запечатанными A2A-сообщениями Mnemonik
   (RFQ → QUOTE → COUNTER → ACCEPT). Каждое сообщение подписано до шифрования и
   после него, привязано к получателю, сессии и nonce. Типы сообщений и машина
   состояний переговоров — часть слоя свопов (Warrant), а не Mnemonik.
2. **Авторизация** — каждое действие с деньгами (accept, lock, reveal) проходит
   через Warrant: детерминированный верифицированный эвалюатор возвращает
   Allow / Deny / Ask. Ask уходит человеку.
3. **Расчёт** — существующий HTLC-движок площадки (первая цель — Flo.tc) без
   изменений. Агент управляет им только через policy signer.
4. **Аудит** — переговоры, ордера и on-chain события якорятся через Mnemonik.
   Один экран отвечает: почему сделка случилась и была ли она разрешена.

## Зачем

- LLM-агент не должен напрямую двигать деньги. Он предлагает, решает
  проверяемый код.
- Контрагенту нужно доказательство условий сделки без доверия к посреднику.
- Владельцу нужна политика: лимиты, пары, контрагенты, отклонение от цены
  оракула, и право вето.

## Граница интеграции

Mnemonik даёт транспорт, идентичность, шифрование, подпись и якорение и ничего
не знает о конкретном приложении. Интеграция (своп, инвойсы, что угодно) сама
определяет свои типы сообщений, машины состояний и политики в собственном пакете
поверх публичного API / SDK. Новая интеграция не требует изменений в
`mnemonic-core`. В ядро попадает только то, что нужно всем.

Агент (LLM-процесс) не держит ни ключей, ни средств. Средства и ключи принадлежат
владельцу — человеку или компании, от имени которых действует агент. Policy
signer работает в окружении владельца: отдельный процесс рядом с агентом, HSM,
KMS, TEE или кошелёк самого владельца. Средства никуда не переводятся.

## Что уже есть

- Mnemonik: запечатанные A2A-сообщения, гранты, цепочки по `context_id`,
  якорение, MCP-инструменты `mnemonic_attest_a2a` и `mnemonic_recall_a2a`.
- Warrant: верифицированный (Verus) трёхзначный эвалюатор — пока только для
  инвойсов.

Подробно: [gap-analysis.md](gap-analysis.md).

## Чего нет

В Mnemonik (обобщённо, один раз для всех интеграций — [tech-spec.md](tech-spec.md)):

- Nonce, срока действия и тега протокола приложения в запечатанном A2A-сообщении.
  Подпись открытого текста с привязкой к получателям уже есть (PR #276). Эти поля
  несёт подписанный payload интеграции.
- Проверки отдельной COSE-подписи из TypeScript (WASM/SDK).
- Интерфейса `Signer` для ключей в HSM / KMS / TEE; ротации ключей.

В слое свопов (Warrant, без изменений в `mnemonic-core`):

- Типов сообщений переговоров, swap intent и машины состояний переговоров.
- Атомов политики для свопов и обязательных проверок безопасности цепочек.
- Policy signer, который подписывает транзакции только при Allow.

## Чего не делаем

- Не меняем HTLC-контракты и движок расчёта площадки.
- Не переносим в свопы zkVM, Groth16 и эскроу-контракты Warrant.
- Не решаем проблему «бесплатного опциона» HTLC — только ограничиваем её.

## Критерии готовности

- Два агента договариваются и проводят своп на тестовых сетях (Bitcoin regtest,
  локальный EVM, локальный Solana) без участия человека в рамках политики.
- Каждая обязательная проверка безопасности имеет отрицательный тест.
- Секрет HTLC не попадает в логи, промпты и транскрипты.
- Аудитор восстанавливает цепочку «условия → ордер → транзакции» из якорей.
