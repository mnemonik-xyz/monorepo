# Task 1: Freeze the negotiation schemas and add the feature skeleton

## Description

Fix the exact shape of `AGSWAP_INNER_V1`, the five payloads and the CAIP
identifier rules before any implementation. Add the cargo feature and an empty
module so that wave 2 tasks do not edit the same shared files.

## What to do

1. In `tech-spec.md`, write the final field list, types and limits of
   `AGSWAP_INNER_V1` and of each payload (`rfq`, `quote`, `counter`, `accept`,
   `reject`, `expire`). Amounts are integers in base units. Identities are bare
   base58 Ed25519 keys ("Identity encoding").
2. State the CAIP-2, CAIP-10 and CAIP-19 forms that the parser accepts, with
   one example per chain family (Bitcoin, EVM, Solana).
3. State the reason codes for `reject`. Free text is not allowed.
4. Add feature `agswap-experimental = ["a2a-experimental"]` to `core/Cargo.toml`.
5. Add `core/src/codec/agswap/mod.rs` with empty `inner`, `intent` and
   `transcript` submodules, gated by the feature, and register it in
   `core/src/codec/mod.rs`.

## TDD anchors

- `codec::agswap::tests::feature_compiles` — the empty module builds.

## Done when

- `cargo build -p mnemonic-core --features agswap-experimental` succeeds.
- `cargo build --workspace` without the feature still succeeds.
- `decisions.md` records the frozen schema version.
