# Task 5: WASM exports and SDK wrappers

## Description

Expose the generic helpers to TypeScript. `core/src/wasm/mod.rs` is a common
conflict point; no other task in this wave touches it.

## What to do

1. Add `a2a_seal_signed_inner` and `a2a_open_signed_inner` to
   `core/src/wasm/mod.rs`, gated by `a2a-experimental`. Convert errors to
   `JsValue` only at this boundary.
2. Add `verify_cose_payload(cose_bytes)`. It calls `verify_artifact`, rejects the
   input unless the signature is valid, and returns the payload bytes and the
   base58 `kid`.
3. Add typed wrappers in `packages/sdk/src/a2a.ts` (`sealSignedInner`,
   `openSignedInner`) and `packages/sdk/src/cose.ts` (`verifyCosePayload`), and
   a `NonceStore` next to the existing local A2A state.
4. Follow the key handling of the A2A path in `packages/sdk/src/client.ts`. Do
   not add a new path that passes a raw secret where a `Signer` could be used.

## TDD anchors

- SDK test: seal in one client, open in a second client, payload equal.
- SDK test: replayed message rejected by the nonce store.
- SDK test: `verifyCosePayload` rejects a changed payload byte.

## Done when

- `npm run build:wasm:sdk` and `npm test -w @mnemonik-xyz/sdk` pass.
- The SDK README documents the new functions as experimental.
