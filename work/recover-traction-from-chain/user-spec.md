# Восстановление traction-метрик из блокчейна

## Что случилось

При переезде на новый сервер была потеряна SQLite-база. Публичные счётчики
на лендинге (Users / Memories / On-chain) и страница Analytics обнулились,
хотя реальная история протокола существует: каждый `participate`-write
навсегда записан в Arweave (COSE-конверт) и Solana (SPL Memo).

## Что хотим

Показывать на странице реальные накопленные числа, восстановив их из
цепочки — без ручного восстановления базы. Пользователь явно предпочёл
GraphQL-подход: цепочка — источник истины, без дублирования данных в БД.

## Что сделано

- Сервер периодически опрашивает Arweave gateway GraphQL по кошельку
  оператора + тегу `App-Name: mnemonic-protocol` и строит снапшот всей
  якорной истории (id, день блока, producer).
- `/stats` и `/analytics/attestations` объединяют снапшот с локальной БД:
  цепочка отвечает за anchored-записи, БД — за local-only строки.
- Новые загрузки получают теги `Producer` и `Created-At`, чтобы в будущем
  вся статистика собиралась одним GraphQL-запросом без скачивания payload.

## Ограничения (честно)

- `local`-записи жили только в потерянной БД — их не восстановить.
  «Memories (Saved)» теперь нижняя граница (= anchored + новые local).
- Пользователи, писавшие только в local-режиме, не восстанавливаются.
- Записи через stdio-путь подписаны серверным ключом — считаются одним
  «пользователем».

## Включение

`CHAIN_STATS_WALLETS=<base58-адрес(а) серверного кошелька через запятую>`.
Нужен только ПУБЛИЧНЫЙ адрес — приватный ключ для этой фичи не требуется
и не должен появляться в конфиге.
