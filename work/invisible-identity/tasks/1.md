# Task 1: Add `keyring` + `crypto_box` deps to `mnemonic-core`

## Description

First task in the feature. Adds the two new Rust crates needed for Wave 1 (`keyring` for OS keychain access, `crypto_box` for x25519 ticket wrapping in Wave 4), verifies they compile cleanly into the workspace, and re-exports the minimum surface from `core/src/lib.rs` if needed.

This is the smallest possible diff that gets the workspace ready for Tasks 2-4. No functional code yet — just dependency declarations and a compile gate.

## What to do

1. **Pre-condition check:** Run `cargo search keyring` and `cargo search crypto_box` from the workspace root. Confirm both crates exist at versions `>=2.0` and `>=0.9` respectively. If either is unavailable or has had a major-version bump that breaks the API expected by tech-spec, stop and document the deviation in `decisions.md`.

2. **Edit `core/Cargo.toml`:**
   - Under `[dependencies]`, add `keyring = "2"`.
   - Under `[dependencies]`, add `crypto_box = "0.9"`.
   - No feature flags. Both deps are mandatory core functionality.

3. **Verify compile:** Run `cargo build -p mnemonic-core` from the workspace root. Must exit 0 with zero warnings about unused dependencies (we're not using them yet — Rust allows declared-but-unused deps; warnings would come from clippy with `-D warnings`).

4. **Skip lib.rs re-exports for now.** They land in Task 2 when `KeyStore` trait is defined.

## Acceptance Criteria

- [ ] `core/Cargo.toml` contains `keyring = "2"` and `crypto_box = "0.9"` under `[dependencies]`.

## Notes

- If `crypto_box` is already a transitive dep through `solana-sdk` or another crate, this task explicitly promotes it to a direct dep per Deviation 3. Promotion is intentional, not redundant.
- Do not yet touch `mcp/Cargo.toml` — the mcp side will use these crates only via `mnemonic-core` re-exports (added in Task 2).
- `keyring` may pull in platform-specific transitive deps (`security-framework` on macOS, `secret-service` on Linux, `windows-rs` on Windows). This is expected and not a separate dependency to manage.
- If `cargo build -p mnemonic-core` fails with linker errors about D-Bus or Secret Service libraries on Linux, the CI container needs `libdbus-1-dev` installed. Add to `.github/workflows/ci.yml` as part of this task if so.
