# Task 7: TS `identity.ensure()` + entrypoint wire-up

## Description

Mirror of Wave 1 Task 3 on the Node side. Implements the same five-path bootstrap algorithm in TypeScript and wires it into the CLI entrypoint so any command that needs identity bootstraps silently.

## What to do

1. **Create `packages/cli/src/identity/ensure.ts`** with:

   ```ts
   export interface KeyStores {
     os: KeyStore | null;
     file: KeyStore;
     identityPath: string;
     readmePath: string;
   }

   export async function ensure(): Promise<Identity> {
     return ensureWithStores(defaultStores());
   }

   export async function ensureWithStores(stores: KeyStores): Promise<Identity>;
   ```

2. **Algorithm** — identical to Task 3:
   - Read `identity.json`. If ENOENT → CREATE path.
   - Parse. If `'secret' in parsed` → LEGACY: migrate to keychain if available, else keep file.
   - Else (`keychain_ref` present) → STUB: require os; pull secret.
   - On error after partial side-effect: rollback (keychain.remove() if file rewrite failed).

3. **Stderr line** on creation/migration: use `console.error(...)`, single line, per Decision 7 strings. Suppressed under `--quiet` flag or `MNEMONIC_QUIET=1` env.

4. **Write `~/.mnemonic/README.txt` exactly once** with the content from tech-spec §Data Models. Use `fs.writeFile(path, content, { flag: 'wx' })` — fails if exists, ignored gracefully.

5. **Wire into `packages/cli/src/index.ts`:**
   - Before any command dispatch (after argv parse), check the command name.
   - Skip `ensure()` for: `--help`, `-h`, `--version`, `-V`, `identity status` (status must run even with no identity yet, to print "no identity present"), `init --force` (init explicitly manages identity).
   - For all other commands: `await ensure()` and bind the resulting `Identity` to the command's context.

6. **Unit tests** in `packages/cli/test/identity/ensure.test.ts`:
   - Same five scenarios as Task 3, mirrored.
   - One additional test: entrypoint skip-list — `--help` runs without calling ensure.

## Notes

- `Identity` type already exists in `packages/sdk/src/identity/keypair.ts`. Reuse it.
- `defaultStores()` constructs the production stores: `new OsKeyStore()` + `new FileKeyStore(path.join(os.homedir(), '.mnemonic/identity.json'))`. If `homedir()` returns falsy, throw with a clear error.
- Path constant for README: `path.join(os.homedir(), '.mnemonic', 'README.txt')`.
- The skip list for `ensure()` is centralized in one constant at the top of `index.ts`: `const ENSURE_SKIP_COMMANDS = new Set(['--help', '-h', '--version', '-V'])`. Subcommand check (`identity status`) is harder — easiest impl: check if argv[2] is `identity` and argv[3] is `status`.
- If `init --force` was preserved from `work/mnemonic-cli/`, route it through a separate path that calls `ensure()` AFTER warning the user about overwriting.
- Stderr line strings (exactly):
  - `mnemonic: identity created did:sol:<base58> stored in OS keychain`
  - `mnemonic: identity created did:sol:<base58> stored in ~/.mnemonic/identity.json (OS keychain unavailable: <reason>)`
  - `mnemonic: legacy identity migrated to OS keychain`
