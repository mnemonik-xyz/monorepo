# Task 3: `identity::ensure()` — five-path bootstrap algorithm

## Description

Heart of the Rust side of Layer 1. Implements the silent bootstrap algorithm exactly as specified in tech-spec.md §Architecture "Bootstrap call path (Rust mcp-server)". Replaces `load_or_create_keypair(path)` entirely (Decision 4 / Deviation 4).

The function must handle all five code paths cleanly: (a) create when absent, (b) read stub + keychain, (c) read legacy + migrate, (d) read legacy + keep on file-fallback, (e) error recovery (file rewrite fails after keychain set).

## What to do

1. **Create `core/src/identity/ensure.rs`** with:

   ```rust
   pub fn ensure() -> anyhow::Result<Identity> { ensure_with_stores(default_stores()) }

   pub fn ensure_with_stores(stores: KeyStores) -> anyhow::Result<Identity>;

   pub struct KeyStores {
       pub os: Option<Box<dyn KeyStore>>,    // None = skip OS path
       pub file: Box<dyn KeyStore>,          // always required
       pub identity_path: PathBuf,           // ~/.mnemonic/identity.json
       pub readme_path: PathBuf,             // ~/.mnemonic/README.txt
   }
   ```

   `ensure_with_stores` is the test seam — production calls `ensure()` which wires the default OS + file stores.

2. **Implement the algorithm:**

   ```text
   IF identity_path exists:
     parse JSON
     IF has "secret" key → LEGACY path
       IF os available → migrate: os.set(entry); rewrite file as stub; if rewrite fails: os.remove(); return Err
       ELSE → keep legacy: return Identity from file
     ELSE has "keychain_ref" → STUB path
       require os available
       entry = os.get()? — if None, file points at missing keychain entry: return Err with actionable message
       return Identity { pubkey from file, secret from entry }
   ELSE absent:
     generate new keypair
     IF os available → os.set(entry); write stub file; write README; emit stderr line; return Identity
     ELSE → file.set(entry); write README; emit stderr line; return Identity
   ```

3. **Write `~/.mnemonic/README.txt` exactly once on creation** — content per tech-spec §Data Models. Use `OpenOptions::create_new(true)` so re-runs don't overwrite a user-edited file.

4. **Emit exactly one stderr line on creation** via `tracing::info!` (stderr-bound subscriber configured by mcp). Strings per Decision 7. Suppressed if env `MNEMONIC_QUIET=1` (mirrors `--quiet` flag from CLI).

5. **Remove `load_or_create_keypair(path)`** from `core/src/identity/mod.rs`. Compilation will fail in `mcp/src/main.rs` — that's Task 4's job to fix.

6. **Unit tests** (in `core/src/identity/ensure.rs` as `#[cfg(test)] mod tests`):
   - `ensure_creates_when_absent` — `MemoryKeyStore` empty + tempdir for files. Expect keypair generated, keychain entry set, stub file written, README created, stderr line.
   - `ensure_reads_existing_stub` — pre-seed `MemoryKeyStore` and stub file. Expect same pubkey, no stderr line, README untouched.
   - `ensure_migrates_legacy_to_stub` — pre-seed legacy file, empty keystore. Expect keystore.set called, file rewritten in stub shape, same pubkey, single stderr line `legacy identity migrated...`.
   - `ensure_falls_back_to_file_when_keychain_unavailable` — `MemoryKeyStore` rigged to return `PlatformUnavailable`. Expect legacy file written, file mode 0600, stderr line includes `keychain unavailable: <reason>`.
   - `ensure_rolls_back_on_partial_failure` — `MemoryKeyStore` accepts; file rewrite forced to fail (read-only tempdir). Expect keychain entry removed before error returns, legacy file (if it was the input) intact.

## Notes

- Path resolution: use `dirs::home_dir()` (already a transitive dep) for `~`. If `home_dir()` returns `None`, return an error with a clear message rather than panic.
- The "stub points at missing keychain entry" error is recoverable from the user's side (`mnemonic identity pull-from-webapp` or manual file edit). Error message should mention this.
- The `created_at` field in the stub file uses `chrono::Utc::now().to_rfc3339()`. Format check: should match `2026-05-21T10:23:45.000Z`.
- `ensure_rolls_back_on_partial_failure` is the trickiest test. Easiest way: implement the rollback as a `defer` pattern: `let mut rollback = Some(|| { os.remove() });` and call `take().unwrap()()` on success path; on error path, rollback runs in Drop.
- Do NOT cache the secret in the returned `Identity` if Deviation 1 (lazy access) is honored. Instead, `Identity` should carry a `SecretAccessor` closure that calls `keystore.get()` lazily. For Task 3 simplicity, you may eagerly cache the secret in the struct — Task 4 will tighten this if it causes issues in mcp startup.
