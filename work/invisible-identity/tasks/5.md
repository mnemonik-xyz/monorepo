# Task 5: Add `@napi-rs/keyring` + companions to `packages/cli`

## Description

Wave 2's foundation. Adds the three new Node dependencies (`@napi-rs/keyring`, `qrcode-terminal`, `@noble/curves`) to `packages/cli/package.json`, verifies prebuilt N-API binaries exist for the CI matrix, and validates the install on Node 20 + Bun (the cross-runtime targets per `work/mnemonic-cli/`).

This task is `depends_on: []` because it's independent from Wave 1's Rust work — both waves can proceed in parallel until they converge in Wave 3's interop tests.

## What to do

1. **Pre-condition check:** Verify `@napi-rs/keyring` has prebuilt binaries for the CI matrix platforms:
   ```
   npm view @napi-rs/keyring versions --json
   npm view @napi-rs/keyring dist.tarball
   ```
   Then check `optionalDependencies` of the latest version include all of:
   - `@napi-rs/keyring-darwin-arm64`
   - `@napi-rs/keyring-darwin-x64`
   - `@napi-rs/keyring-linux-x64-gnu`
   - `@napi-rs/keyring-linux-arm64-gnu`
   - `@napi-rs/keyring-win32-x64-msvc`

   If any are missing, document the deviation and decide: fall back to build-from-source (`node-gyp`) or block the task.

2. **Edit `packages/cli/package.json`:**
   - Add to `dependencies`:
     - `"@napi-rs/keyring": "^1.0.0"` (or the verified-available major)
     - `"qrcode-terminal": "^0.12.0"`
     - `"@noble/curves": "^1.4.0"`
   - Do NOT touch `peerDependencies` or `optionalDependencies`.

3. **Install and verify:**
   ```
   cd packages/cli
   npm install        # or bun install per project preference
   node -e "const k = require('@napi-rs/keyring'); console.log(typeof k.Entry)"
   node -e "const q = require('qrcode-terminal'); console.log(typeof q.generate)"
   node -e "const c = require('@noble/curves/ed25519'); console.log(typeof c.ed25519)"
   ```
   All three must print a non-`undefined` type.

4. **Cross-runtime smoke:**
   ```
   bun -e "import {Entry} from '@napi-rs/keyring'; console.log(typeof Entry)"
   ```
   Bun must also load the package. If it fails, document and gate `OsKeyStore` behind a runtime check in Task 6.

5. **Update `package-lock.json` / `bun.lockb`** and commit alongside `package.json`. Lockfile drift is a CI failure mode.

## Notes

- Project uses workspace-level `npm install` from repo root in CI. Verify it picks up the new deps via the workspace path resolution.
- If `@napi-rs/keyring` postinstall step downloads a binary and the CI has no network during install, fall back to `npm install --foreground-scripts` or pre-bundle the binary in CI cache.
- `qrcode-terminal` is plain JS — no native compilation. No matrix concerns.
- `@noble/curves` is plain JS — no native compilation. Pure ESM; verify `cli` package allows ESM consumption (it already does per `work/mnemonic-cli/`).
- If the project uses Bun as primary install tool (`bun.lockb` exists), prefer `bun install` over `npm install`.
