# Task 9: Cross-language keychain interop script + CI job

## Description

The single most important test in the feature. Boots a Linux container with gnome-keyring (Secret Service), drives both the Rust mcp-server and the Node CLI against the same keychain entry, and asserts byte-equality of secrets across the language boundary.

Failure here means cross-surface drift will return — Wave 4 cannot proceed until this is green.

## What to do

1. **Create `tests/cross-lang/keychain.sh`** (bash) at repo root or `work/invisible-identity/tests/`:

   ```bash
   #!/usr/bin/env bash
   set -euo pipefail

   # Steps:
   # A. Rust writes → Node reads
   HOME=$(mktemp -d)
   export HOME
   echo "=== A: Rust write → Node read ==="
   cargo run -p mnemonic-mcp -- --transport stdio <<< '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"mnemonic_whoami","arguments":{}}}' > /tmp/rust-whoami.json
   RUST_PUBKEY=$(jq -r .result.pubkey /tmp/rust-whoami.json)
   NODE_PUBKEY=$(node packages/cli/dist/cli.js whoami --json | jq -r .pubkey)
   [ "$RUST_PUBKEY" = "$NODE_PUBKEY" ] || { echo "MISMATCH: $RUST_PUBKEY vs $NODE_PUBKEY"; exit 1; }

   # B. Reset, Node writes → Rust reads
   rm -rf "$HOME/.mnemonic"
   secret-tool clear service xyz.mnemonik.identity account default || true
   echo "=== B: Node write → Rust read ==="
   node packages/cli/dist/cli.js whoami --json > /tmp/node-whoami.json
   NODE_PUBKEY=$(jq -r .pubkey /tmp/node-whoami.json)
   cargo run -p mnemonic-mcp -- --transport stdio <<< '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"mnemonic_whoami","arguments":{}}}' > /tmp/rust-whoami2.json
   RUST_PUBKEY=$(jq -r .result.pubkey /tmp/rust-whoami2.json)
   [ "$RUST_PUBKEY" = "$NODE_PUBKEY" ] || { echo "MISMATCH B"; exit 1; }

   # C. Migration: pre-seed legacy file, run Rust ensure, then Node ensure, byte-equal verify
   rm -rf "$HOME/.mnemonic"
   secret-tool clear service xyz.mnemonik.identity account default || true
   mkdir -p "$HOME/.mnemonic"
   # Write a known legacy fixture
   cp tests/fixtures/legacy-identity.json "$HOME/.mnemonic/identity.json"
   LEGACY_PUBKEY=$(jq -r .pubkey_base58 "$HOME/.mnemonic/identity.json")
   echo "=== C: legacy → Rust migrates → Node reads ==="
   cargo run -p mnemonic-mcp -- --transport stdio <<< '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"mnemonic_whoami","arguments":{}}}' > /tmp/rust-mig.json
   [ "$(jq -r .result.pubkey /tmp/rust-mig.json)" = "$LEGACY_PUBKEY" ] || { echo "MIGRATION CHANGED PUBKEY"; exit 1; }
   # File should now be stub
   jq -e '.keychain_ref' "$HOME/.mnemonic/identity.json" > /dev/null || { echo "FILE NOT MIGRATED TO STUB"; exit 1; }

   echo "ALL CROSS-LANG TESTS PASSED"
   ```

2. **Create the fixture** `tests/fixtures/legacy-identity.json` — a known legacy-format keypair (generated once, committed for reproducibility):

   ```json
   {"secret":[42,42,...,42],"pubkey_base58":"<derived from secret>"}
   ```

   Generate the fixture deterministically: seed Ed25519 with 64 bytes of `0x42`; compute pubkey; write file. Commit the script that generated it alongside.

3. **Add CI job** `.github/workflows/ci.yml`:

   ```yaml
   cross-lang-keychain:
     runs-on: ubuntu-22.04
     steps:
       - uses: actions/checkout@v4
       - name: Install gnome-keyring + tools
         run: |
           sudo apt-get update
           sudo apt-get install -y gnome-keyring dbus-x11 libsecret-tools jq
       - name: Build Rust mcp-server
         run: cargo build -p mnemonic-mcp
       - name: Build Node CLI
         run: cd packages/cli && npm install && npm run build
       - name: Run cross-lang test under dbus + keyring
         run: |
           eval "$(dbus-launch --sh-syntax)"
           echo -n "" | gnome-keyring-daemon --unlock
           gnome-keyring-daemon --start --components=secrets &
           sleep 1
           bash tests/cross-lang/keychain.sh
   ```

4. **Document** the limitation that macOS Keychain and Windows Credential Manager cannot run in CI without paid runners — they're covered by Wave 5 manual smoke. Note in `decisions.md`.

## Notes

- gnome-keyring needs a D-Bus session. In CI this is set up by `dbus-launch`. Manually on a dev box, this often already works.
- `secret-tool clear` is required for cleanup between sub-tests A/B/C — leaving a stale entry will cause B to read a wrong secret.
- The Node CLI binary `packages/cli/dist/cli.js` must exist before the script runs. The CI builds it explicitly; locally the developer must `npm run build` first.
- The Rust mcp-server stdio test relies on the integration test from Task 4 — that test must work in isolation first.
- If `MNEMONIC_QUIET=1` is not set, the script's stderr will contain the creation lines from both sides. These can be ignored (assertions are on stdout/JSON).
