# Task 13: `mnemonic identity pull-from-webapp` + `push-to-webapp` subcommands

## Description

CLI side of the symmetric ticket flow. Depends on Task 12's server endpoints existing and Task 11's `identity.ts` command file being scaffolded.

`pull-from-webapp` redeems a short_code issued by the webapp and adopts the keypair locally. `push-to-webapp` issues a ticket from CLI, prints a QR + short code, and waits for redemption (or just exits and lets the user open the URL).

## What to do

1. **In `packages/cli/src/commands/identity.ts`**, add two subcommand handlers alongside the existing `statusCommand`:

   ```ts
   export async function pullFromWebappCommand(shortCode: string): Promise<number>;
   export async function pushToWebappCommand(opts: { qrOnly?: boolean; codeOnly?: boolean }): Promise<number>;
   ```

2. **`pullFromWebappCommand`:**

   - Generate ephemeral x25519 keypair (`@noble/curves/ed25519` exports x25519 too).
   - POST `<server>/api/cli-bootstrap/redeem` with `{short_code: shortCode, redeemer_eph_pub: <base64>}`.
   - On 200: receive `{wrapped_secret, eph_pub, issuer_pubkey_base58}`. Unwrap via x25519 sealed-box (server's eph_pub + own eph_priv).
   - Construct `KeystoreEntry { secret, pubkey_base58: issuer_pubkey_base58 }`.
   - Call `keystore.set(entry)` via `OsKeyStore` (or `FileKeyStore` if keychain unavailable).
   - Rewrite `~/.mnemonic/identity.json` in stub shape.
   - Print confirmation: `mnemonic: pulled identity from webapp; pubkey did:sol:<base58>`.
   - On 410/4xx: print friendly error, exit 4 (auth/ticket error).

3. **`pushToWebappCommand`:**

   - Read local `Identity` via `ensure()` (this command goes through the normal `ensure` flow; no skip needed).
   - Pull secret bytes from keystore.
   - Fetch server's static x25519 pub: `GET <server>/api/cli-bootstrap/server-pub`.
   - Wrap secret to server's pub via x25519 sealed-box. Result: `wrapped_secret + eph_pub`.
   - POST `<server>/api/cli-bootstrap/issue-from-cli` with `{wrapped_secret, eph_pub, issuer_pubkey_base58}`.
   - On 200: receive `{ticket_id, short_code, expires_at}`.
   - Print:
     ```
     Open this URL on your logged-in webapp browser, or scan the QR:
       https://mnemonik.xyz/install?pull=<short_code>

     Or enter this short code: ABCD-1234
     Expires: <expires_at>
     ```
   - Print QR via `qrcode-terminal` unless `--code-only`.
   - Exit 0 immediately. Do NOT poll for redemption (server-driven; user sees redemption result on webapp).

4. **Register both subcommands** in `packages/cli/src/index.ts` under `mnemonic identity ...`.

5. **Unit tests** in `packages/cli/test/commands/identity-sync.test.ts`:

   - `pullFromWebappCommand` happy path — mock server returns valid wrapped secret → keystore updated → exit 0.
   - `pullFromWebappCommand` expired ticket — mock 410 → exit 4, keystore untouched.
   - `pullFromWebappCommand` bad short code — mock 404 → exit 4.
   - `pushToWebappCommand` happy path — mock server accepts → output contains short_code and URL.
   - `pushToWebappCommand` server error — mock 500 → exit 2.

6. **Integration test** in `packages/cli/test/integration/ticket-flow.test.ts`:

   - Spin up mock server (using existing `msw` or `nock` from `work/mnemonic-cli/` test infra).
   - End-to-end: push from CLI A (mocked memory keystore) → redeem from CLI B → assert CLI B's keystore now has CLI A's secret.

## Notes

- x25519 sealed-box in Node: use `@noble/curves/ed25519` for x25519 + `@noble/ciphers/salsa` for xsalsa20-poly1305. The Rust side (Task 12) uses `crypto_box`. These are interop-compatible if the same algorithm choice (`XSalsa20Poly1305 + Curve25519`) is consistent.
- If `@noble/ciphers` is not in deps, add it now (it's tiny, ~3KB). Document as a dep deviation.
- Short code via stdin: accept `mnemonic identity pull-from-webapp -` and read first line of stdin. Don't echo the code (no `console.log(code)` before redemption).
- QR printing: `qrcode-terminal.generate(url, { small: true })` prints UTF-8 block characters. If `--no-color` or non-TTY, skip the QR and print only short code + URL.
- The URL `https://mnemonik.xyz/install?pull=<short_code>` is shaped by webapp (Task 14). Confirm the path matches.
- After successful `pull-from-webapp`, the previous local identity is overwritten without backup. This is intentional — user explicitly opted in. Print a strong confirmation line so user knows their old key is gone.
- For `push-to-webapp`, the server's static x25519 pub is fetched fresh each call. Don't cache — server restart invalidates it.
