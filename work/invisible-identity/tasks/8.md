# Task 8: SDK `Keypair.fromJSON` learns both stub and legacy shapes

## Description

Updates the runtime-agnostic SDK so programmatic consumers (LangChain agents, Chrome extension, etc.) can load identity from `~/.mnemonic/identity.json` regardless of which shape it has. The SDK itself does not do keychain access — that's CLI's responsibility — but it must parse both shapes and surface a typed error when the file is a stub without a co-resolvable secret.

Parallel-safe with Task 6 and 7 (different package, different files).

## What to do

1. **Edit `packages/sdk/src/identity/keypair.ts`:**

   Find existing `static fromJSON(parsed: any): Keypair` (or similar). Replace its body with:

   ```ts
   static fromJSON(parsed: unknown): Keypair {
     if (!parsed || typeof parsed !== 'object') throw new TypeError('invalid identity.json: not an object');
     const obj = parsed as Record<string, unknown>;

     // Legacy shape
     if (Array.isArray(obj.secret) && typeof obj.pubkey_base58 === 'string') {
       if (obj.secret.length !== 64) throw new TypeError(`invalid secret length: ${obj.secret.length}`);
       return new Keypair(new Uint8Array(obj.secret as number[]), obj.pubkey_base58);
     }

     // Stub shape
     if (typeof obj.pubkey_base58 === 'string' && typeof obj.keychain_ref === 'string') {
       throw new IdentityRequiresKeystore(obj.pubkey_base58, obj.keychain_ref);
     }

     throw new TypeError('invalid identity.json: unrecognized shape');
   }
   ```

2. **Define `IdentityRequiresKeystore` error class** in same file (or a sibling `errors.ts`):

   ```ts
   export class IdentityRequiresKeystore extends Error {
     constructor(public readonly pubkey_base58: string, public readonly keychain_ref: string) {
       super(`identity.json is a stub referencing keychain entry '${keychain_ref}'; load via OS keychain`);
     }
   }
   ```

3. **Export `IdentityRequiresKeystore`** from `packages/sdk/src/index.ts` so CLI can catch it.

4. **Unit tests** in `packages/sdk/test/identity/keypair.test.ts`:
   - Legacy shape → constructs `Keypair` with correct bytes + pubkey.
   - Legacy shape with bad length → throws TypeError with length info.
   - Stub shape → throws `IdentityRequiresKeystore` with correct fields.
   - Garbage input → throws TypeError.
   - Round-trip: `Keypair.fromJSON(JSON.parse(JSON.stringify(legacyFixture)))` equals input.

5. **JSDoc update** for `fromJSON` so SDK consumers see both shapes documented.

## Notes

- This is a SDK change — no behavioral change for legacy consumers. The new code path (`IdentityRequiresKeystore` throw) is reachable only via the new stub shape.
- Do not import any Node-specific module here. SDK stays runtime-agnostic (no `fs`, no `@napi-rs/keyring`, no `os`). The CLI handles file/keychain I/O; SDK only parses.
