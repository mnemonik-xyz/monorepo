# Task 2: `KeyStore` trait + `OsKeyStore` / `FileKeyStore` / `MemoryKeyStore`

## Description

Defines the abstraction layer for identity-secret storage and ships all three implementations. After this task, the rest of `core/` (and the wave-2 Node side) has a clean interface to read/write the Ed25519 secret regardless of where it lives. No bootstrap or migration logic yet — that's Task 3.

The trait must expose the minimum needed for both keychain and file backends to satisfy: get pubkey + secret (or error), set both, remove, probe availability. The byte format inside the store is the legacy JSON shape per Decision 13 — same shape on disk and in keychain.

## What to do

1. **Create `core/src/identity/keystore.rs`** with the trait:

   ```rust
   pub trait KeyStore: Send + Sync {
       fn get(&self) -> Result<Option<KeystoreEntry>, KeystoreError>;
       fn set(&self, entry: &KeystoreEntry) -> Result<(), KeystoreError>;
       fn remove(&self) -> Result<(), KeystoreError>;
       fn available(&self) -> Result<bool, KeystoreError>;
       fn name(&self) -> &'static str; // "os" | "file" | "memory" — for status output
   }

   pub struct KeystoreEntry {
       pub secret: [u8; 64],         // Ed25519 secret key bytes
       pub pubkey_base58: String,
   }

   #[derive(thiserror::Error, Debug)]
   pub enum KeystoreError { ... }    // PlatformUnavailable, Locked, NotFound, IO(io::Error), Serde(serde_json::Error), Other(anyhow::Error)
   ```

2. **Create `core/src/identity/keystore_os.rs`** with `OsKeyStore`:
   - Wraps `keyring::Entry::new("xyz.mnemonik.identity", "default")` per Decision 1.
   - `get` calls `entry.get_password()` → JSON-decodes into `KeystoreEntry`. Maps `keyring::Error::NoEntry` to `Ok(None)`.
   - `set` JSON-encodes (key order `secret`, `pubkey_base58`, no whitespace per Decision 13) and calls `entry.set_password(&json)`.
   - `remove` calls `entry.delete_password()`.
   - `available` does a probe: tries to open the entry; returns false on `PlatformFailure`.

3. **Create `core/src/identity/keystore_file.rs`** with `FileKeyStore`:
   - Constructor takes `PathBuf` (typically `~/.mnemonic/identity.json`).
   - `get` reads the file; if shape is legacy (`{secret, pubkey_base58}`), returns the entry; if shape is stub (no `secret` key), returns `Ok(None)` (the file exists but secret isn't here — caller's responsibility to fall back).
   - `set` writes legacy-format JSON via tempfile + atomic rename. Sets mode 0600 on Unix via `OpenOptions::mode(0o600)` before write.
   - `remove` deletes the file if present.
   - `available` returns `Ok(true)` if parent dir is writable, `Ok(false)` else.

4. **Create `core/src/identity/keystore_memory.rs`** (gated `#[cfg(test)]` or `#[cfg(feature = "test-util")]`) with `MemoryKeyStore`:
   - Backed by `Mutex<Option<KeystoreEntry>>`.
   - Trivial set/get/remove. `available` always returns true unless the test rigs it false.

5. **Wire into `core/src/identity/mod.rs`:**
   - `mod keystore;` `mod keystore_os;` `mod keystore_file;` plus `#[cfg(test)] mod keystore_memory;`
   - Re-export `pub use keystore::{KeyStore, KeystoreEntry, KeystoreError};` and the concrete impls.

6. **Unit tests** in each impl file:
   - `MemoryKeyStore`: round-trip set → get → equal; remove clears; double-remove ok.
   - `FileKeyStore`: uses `tempfile::TempDir`; tests legacy-shape write/read, mode 0600 verification on Unix, atomic-rename behavior under simulated mid-write failure (using `assert_fs` or manual partial-write file fixture).
   - `OsKeyStore`: skipped in CI unless `MNEMONIC_TEST_KEYCHAIN=1` env var is set (Linux gnome-keyring container in Wave 3). Smoke test goes in Task 9.

## Notes

- Use `serde_json::to_string` (compact, no pretty-print) for byte-equal JSON. Manually verify key order by hand-rolling a `Serialize` impl or by sorting `BTreeMap` keys — `serde_json` does not guarantee struct field order across versions.
- `FileKeyStore::set` must use `tempfile::NamedTempFile::new_in(parent)` + `persist` for atomicity. Do not write to the final path then truncate-and-rewrite.
- Do not log or print any byte of `entry.secret` in any code path — including error messages. `KeystoreError::Other` should redact secrets if they end up in the error chain.
- `OsKeyStore::available` is allowed to lie optimistically — the real failure is detected on `get`/`set`. The probe is for `mnemonic identity status` UX.
