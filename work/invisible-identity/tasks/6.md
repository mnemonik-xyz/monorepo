# Task 6: TS `KeyStore` + `OsKeyStore` / `FileKeyStore` / `MemoryKeyStore`

## Description

Mirror of Wave 1 Task 2 on the Node side. Defines the `KeyStore` interface and all three implementations in TypeScript. Byte-equal with the Rust side per Decision 13 — the JSON shape inside both the keychain entry and the legacy file is identical.

## What to do

1. **Create `packages/cli/src/identity/keystore.ts`** with the interface:

   ```ts
   export interface KeyStore {
     get(): Promise<KeystoreEntry | null>;
     set(entry: KeystoreEntry): Promise<void>;
     remove(): Promise<void>;
     available(): Promise<boolean>;
     readonly name: 'os' | 'file' | 'memory';
   }

   export interface KeystoreEntry {
     secret: number[];           // 64 bytes
     pubkey_base58: string;
   }

   export class KeystoreError extends Error {
     constructor(
       public readonly kind: 'platform-unavailable' | 'locked' | 'not-found' | 'io' | 'serde' | 'other',
       message: string,
       public readonly cause?: unknown,
     ) { super(message); }
   }
   ```

2. **Create `packages/cli/src/identity/keystore-os.ts`** with `OsKeyStore`:
   - Constructor takes no args; uses fixed `new Entry('xyz.mnemonik.identity', 'default')` from `@napi-rs/keyring`.
   - `get`: `entry.getPassword()`. On `null` (no entry) → return null. On error containing "No matching entry" → return null. Else throw `KeystoreError`.
   - `set`: JSON-encode in canonical key order (`secret` then `pubkey_base58`), no whitespace. `entry.setPassword(json)`.
   - `remove`: `entry.deletePassword()`.
   - `available`: try a dummy `entry.getPassword()`; catch `platform-unavailable` (Linux no D-Bus, etc.) → return false.

3. **Create `packages/cli/src/identity/keystore-file.ts`** with `FileKeyStore`:
   - Constructor takes path string.
   - `get`: read file with `fs/promises.readFile`. If ENOENT → null. Parse JSON. If `'secret' in parsed` → return as `KeystoreEntry`. Else → null (file is stub; secret isn't here).
   - `set`: atomic write — `writeFile(path + '.tmp', json, { mode: 0o600 })` then `rename(path + '.tmp', path)`. On Windows, additionally call the existing ACL helper (already used by `work/mnemonic-cli/`).
   - `remove`: `unlink(path)` ignoring ENOENT.
   - `available`: check parent dir is writable via `access(parent, fs.constants.W_OK)`.

4. **Create `packages/cli/src/identity/keystore-memory.ts`** with `MemoryKeyStore` (no test gating — TS modules are import-gated in vitest):
   - Internal `KeystoreEntry | null` state. Trivial impls. `available` always true unless rigged.

5. **Unit tests** in `packages/cli/test/identity/keystore.test.ts` (vitest):
   - Round-trip on `MemoryKeyStore`.
   - `FileKeyStore`: uses `tmp-promise` or `os.tmpdir()`; verifies legacy-shape round-trip, mode 0600 on Unix (`fs.stat`).
   - JSON byte-equality golden: hardcode a fixture entry, serialize via `OsKeyStore`-internal logic, compare to expected exact bytes.
   - `OsKeyStore`: skipped in CI unless `MNEMONIC_TEST_KEYCHAIN=1` (Wave 3 covers it).

## Notes

- JSON canonical bytes: use a custom serializer that puts `secret` first, `pubkey_base58` second, no whitespace, no extra newlines. `JSON.stringify({secret, pubkey_base58})` happens to produce keys in insertion order in modern Node, but **do not rely on this** — explicitly construct the string: `'{"secret":' + JSON.stringify(entry.secret) + ',"pubkey_base58":' + JSON.stringify(entry.pubkey_base58) + '}'`.
- `secret` is `number[]` of length 64 in the type system, but at runtime it could be a `Buffer` or `Uint8Array` from the keychain bytes. Normalize in `OsKeyStore.get`: `Array.from(buffer)`.
- Windows ACL helper: see `packages/cli/src/util/win-acl.ts` (or similar) introduced by `work/mnemonic-cli/`. If it doesn't exist yet, use `fs.chmodSync(path, 0o600)` — Node will silently no-op on Windows. Document the limitation.
- `available()` on Linux without D-Bus: `@napi-rs/keyring` throws synchronously inside `getPassword()`. Catch the throw, classify as `platform-unavailable`, return false.
