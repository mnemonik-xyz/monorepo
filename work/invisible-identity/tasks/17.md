# Task 17: Code review across the diff

## Description

Read-only code review by a fresh agent that has not been involved in writing the implementation. Scope: the full diff of this branch against `main`. Focus on cross-cutting concerns that individual task-level code-reviewers may have missed.

Companion to Task 16 (security review) — same fresh-eyes approach, different lens (correctness + maintainability instead of security).

## What to do

The reviewer agent runs:

```
git diff main...HEAD -- core/ mcp/ packages/cli/ packages/sdk/ webapp/ tests/ .github/
```

And evaluates against the following criteria:

### Architecture coherence

1. **Hard architectural rules from CLAUDE.md still hold:**
   - Payment methods absent from `core/` (`grep -r "create_api_key\|deduct_balance\|..." core/src/`)
   - `pricing.rs` not in `core/`
   - `HashEmbedder` not anywhere
   - `core/` has no references to `mcp/`

2. **Cross-language interop preserved:**
   - The legacy JSON shape `{secret:[...],pubkey_base58:"..."}` is byte-identical between Rust and Node (verified by Task 10's golden test; reviewer re-runs it).
   - `OsKeyStore` service/account strings exactly match between languages.

3. **`identity::ensure()` / `identity.ensure()` are the only bootstrap entrypoints:**
   - No callsite directly constructs `Identity` from a file path anywhere outside the test code.

### Code quality

4. **No `unwrap()` outside tests** (`grep -rE "\.unwrap\(\)" core/src/identity packages/cli/src/identity packages/cli/src/commands mcp/src/api.rs | grep -v "#\[test\]" | grep -v test/`).

5. **`anyhow::Result` consistency** in Rust; typed errors on TS side (`KeystoreError`, `IdentityRequiresKeystore`).

6. **No silenced errors** — `.ok()` on `Result` is rare and justified; `try { } catch {}` blocks have meaningful handling.

7. **Module visibility:**
   - `KeyStore`, `KeystoreEntry`, `KeystoreError` are `pub`.
   - Implementation-only helpers are crate-private (Rust) or non-exported (TS).

### Test coverage

8. **Each of the 5 `ensure()` paths has a dedicated unit test** in both languages.

9. **Cross-lang interop test (Task 9) covers all three sub-scenarios** A/B/C and is in CI.

10. **Golden byte-equality test (Task 10) hardcodes the same EXPECTED string** in both languages.

11. **Ticket flow integration test (Task 13)** exercises sealed-box wrap/unwrap round-trip end-to-end.

### Naming and convention

12. **Conventional Commits** in all commit messages on the branch.

13. **File paths consistent:**
    - Rust: `core/src/identity/keystore.rs`, `keystore_os.rs`, `keystore_file.rs`, `keystore_memory.rs`, `ensure.rs` (snake_case).
    - TS: `packages/cli/src/identity/keystore.ts`, `keystore-os.ts`, etc. (kebab-case).

14. **`mnemonic identity status` exit codes** match Data Models table.

### Maintainability

15. **No dead code paths:**
    - `load_or_create_keypair` removed entirely (`grep -rn "load_or_create_keypair" .` empty per Decision 4 / Deviation 4).
    - No deprecated shims remain.

16. **No TODO comments without ticket references** (`grep -rE "TODO|FIXME|XXX" core/src/identity packages/cli/src/identity` — each match must reference a follow-up task or have a justified deferral comment).

17. **No new top-level dependencies beyond the 5 declared** (Rust: `keyring`, `crypto_box`. Node: `@napi-rs/keyring`, `qrcode-terminal`, `@noble/curves`).

### Documentation

18. **`README.txt` content matches tech-spec §Data Models exactly.**

19. **Public APIs have rustdoc / JSDoc:** `KeyStore` trait, `ensure()` function, `IdentityRequiresKeystore` error.

20. **tech-spec.md is up to date with any deviations** introduced during implementation (Tasks 1-14 may have appended deviation notes; reviewer reconciles).
