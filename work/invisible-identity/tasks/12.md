# Task 12: Server endpoint `/api/cli-bootstrap/issue-from-cli` + `/redeem` extension

## Description

Server side of the symmetric ticket flow. Extends the existing `BootstrapTickets` store and endpoints (introduced by `work/mnemonic-cli/` Deviation 2) with the reverse direction: CLI issues a ticket destined for webapp redemption.

**Precondition (per `decisions.md` follow-up 4):** verify that `/api/cli-bootstrap/{issue,redeem}` exist on `main` before starting. If they don't, this task absorbs their creation too — flag and decide.

Independent of Tasks 11/13/14 within Wave 4 (different files).

## What to do

1. **Verify precondition:** Run `grep -rn "cli-bootstrap" mcp/src/`. If `/api/cli-bootstrap/issue` and `/api/cli-bootstrap/redeem` don't exist, escalate to user — this task's scope expands materially. Otherwise proceed.

2. **Add endpoint `/api/cli-bootstrap/issue-from-cli`** in `mcp/src/api.rs`:

   ```rust
   POST /api/cli-bootstrap/issue-from-cli
   Headers: Authorization: Bearer <cli-jwt>   (optional — proves CLI identity but not required)
   Body:
     {
       "wrapped_secret": "<base64 x25519-sealed bytes>",
       "eph_pub": "<base64 32 bytes>",         // issuer's ephemeral x25519 pub
       "issuer_pubkey_base58": "<ed25519 pubkey of the CLI>"
     }
   Response 200:
     {
       "ticket_id": "<uuid>",
       "short_code": "ABCD-1234",
       "expires_at": "2026-05-21T10:28:45Z"
     }
   Response 4xx: standard error shape
   ```

3. **Extend `BootstrapTickets`** to carry the `origin` field:

   ```rust
   enum TicketOrigin { Webapp, Cli }
   struct Ticket {
     id: Uuid,
     short_code: String,
     origin: TicketOrigin,
     wrapped_secret: Vec<u8>,
     eph_pub: [u8; 32],
     expires_at: SystemTime,
     redeemed: bool,
     issuer_pubkey: [u8; 32],
   }
   ```

4. **Extend `/api/cli-bootstrap/redeem`** to handle both origins. Redemption flow per tech-spec §Decision 12:
   - Receive `{short_code, redeemer_eph_pub}`.
   - Look up ticket by short_code. If not found / expired / redeemed → 410 Gone.
   - Unwrap `wrapped_secret` using server's static x25519 private (in-process, generated at boot).
   - Re-wrap secret using `redeemer_eph_pub`.
   - Mark ticket `redeemed = true` BEFORE returning.
   - Return `{wrapped_secret: <new ciphertext>, eph_pub: <server's eph>, origin, issuer_pubkey_base58}`.

5. **Server's static x25519 keypair** — generate at server boot via `crypto_box::SecretKey::generate(&mut OsRng)`. Store in `McpState` or equivalent. Expose pub via `GET /api/cli-bootstrap/server-pub`:

   ```rust
   GET /api/cli-bootstrap/server-pub
   Response 200: {"server_x25519_pub": "<base64 32 bytes>"}
   ```

6. **Unit tests** in `mcp/tests/api_cli_bootstrap.rs` (or `mcp/src/api.rs` inline `#[cfg(test)]`):
   - `issue_from_cli_returns_ticket`
   - `redeem_unwraps_and_rewraps_correctly` (roundtrip with known key material)
   - `redeem_rejects_expired_ticket` → 410
   - `redeem_rejects_already_redeemed_ticket` → 410
   - `redeem_handles_both_origins` (parameterized with webapp + cli ticket)
   - `server_pub_endpoint_returns_static_key`

## Notes

- Use `crypto_box::SealedBox` if available, else `crypto_box::Box` with explicit nonce (random 24-byte nonce per wrap; include nonce alongside ciphertext in the `wrapped_secret` blob — first 24 bytes = nonce, rest = ciphertext).
- Server's static x25519 keypair lifetime = process lifetime. On restart, all in-flight tickets become unredeemable (acceptable per 5min TTL).
- Short code generator: 32-char alphabet `23456789ABCDEFGHJKLMNPQRSTUVWXYZ` (excludes confusables `01OI`), 8 chars total in `XXXX-XXXX` format. 40 bits of entropy, 5-min TTL, single-use — fine for the threat model.
- LRU eviction: cap at 1000 entries per existing `work/mnemonic-cli/`. Don't change unless evidence warrants.
- Error envelope: use existing project pattern (likely `{error: {code, message}}`). Match existing endpoints.
- `crypto_box` API check: `crypto_box::Box` (Rust) is `XSalsa20Poly1305 + Curve25519`. Verify Node's `@noble/curves` ED25519 module has compatible XSalsa20-poly1305 + x25519 — yes via `@noble/ciphers/salsa` + `@noble/curves/ed25519` (the x25519 sub-export). Confirm before final commit; if mismatch, swap Node to `tweetnacl` (smaller, well-known interop).
