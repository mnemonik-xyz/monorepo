# Task 14: Webapp `/install` page + IdentityPanel drift-warning modal

## Description

Webapp UX work for Wave 4. Two changes:

1. `/install` page generates `mcp.json` config with JWT baked into the `Authorization` header (Decision 15), and triggers a native deeplink for the selected IDE.
2. `IdentityPanel` (or equivalent component managing localStorage keypair) gains a drift-warning modal on the "Generate new keypair" path with Send-to-CLI / Download backup / Cancel options.

Independent of Tasks 11/12/13 within Wave 4 (different package).

## What to do

1. **Edit `webapp/src/pages/install.tsx`** (or wherever the install flow currently lives):

   - Detect platform via `navigator.userAgentData?.platform` with `navigator.platform` fallback (Decision 15, Deviation 5 — sort, not hide).
   - Three install buttons always visible: Cursor, VS Code, Claude Desktop. Order: detected-platform-likely first; original order if detection fails.
   - On click "Install in Cursor":
     - Read current JWT from localStorage (key `mnemonic_jwt` or per existing convention).
     - Build config:
       ```json
       {
         "mcpServers": {
           "mnemonic": {
             "url": "https://mc.mnemonik.xyz/mcp",
             "headers": { "Authorization": "Bearer <jwt>" }
           }
         }
       }
       ```
     - base64-encode the JSON.
     - Trigger deeplink: `window.location.href = 'cursor://mcp/install?config=' + base64`.
   - Same for VS Code with scheme `vscode:mcp/install?config=...`.
   - For Claude Desktop: show a modal with the config snippet + "Copy to clipboard" button + instructions for where to paste (`~/Library/Application Support/Claude/claude_desktop_config.json` on macOS, equivalent on others).
   - Show a warning banner above the buttons: "This config contains a short-lived access token. Don't share it or commit it to a repo."

2. **Handle `?pull=<short_code>` query param** on `/install`:

   - If present and user is logged in: auto-trigger `pull-from-cli` flow (companion to Task 13's `push-to-webapp`).
   - Generate ephemeral x25519 keypair in the browser.
   - POST `/api/cli-bootstrap/redeem` with the short_code.
   - Unwrap the secret in-browser.
   - Update localStorage with the new keypair.
   - Show confirmation modal: "CLI identity adopted; your webapp keypair is now the same as your CLI."
   - If not logged in: redirect to OAuth flow first, return to this query param.

3. **Edit `webapp/src/components/IdentityPanel.tsx`** (or current name — `grep -l "Generate new" webapp/src/`):

   - Wrap "Generate new keypair" button click in a confirmation modal.
   - Modal shows 4 options:
     - **Send to CLI** — issues a ticket (POST `/api/cli-bootstrap/issue`), shows short code + QR for CLI to redeem
     - **Download backup JSON** — exports current localStorage keypair as `mnemonic-identity-backup-YYYY-MM-DD.json` (legacy shape: `{secret, pubkey_base58}`)
     - **Cancel** — closes modal, no change
     - **Generate anyway** (in red/destructive style) — proceeds with key replacement
   - Above the options, a red explanatory paragraph: "This will replace your current keypair. JWTs your IDEs / CLI hold will stop working. Before continuing, you can:"

4. **Unit tests** (vitest + React Testing Library, following webapp conventions):
   - `/install` button click triggers `window.location.href` set to expected scheme + base64 config.
   - Platform detection: when `navigator.userAgentData.platform === 'macOS'`, Cursor is first button.
   - Pull-from-CLI happy path: with `?pull=XXXX`, after OAuth, redemption is called and localStorage is updated.
   - Drift-warning modal: clicking "Generate new" opens modal; clicking "Cancel" closes without keypair change; clicking "Generate anyway" replaces.

5. **Manual smoke** documented for QA (Wave 5 Task 15):
   - Visit `/install` while logged in → all three buttons present → click Cursor → Cursor opens with new MCP server.
   - Visit `/install?pull=ABCD-1234` while logged in → redemption modal → confirms.

## Notes

- UA detection on Cursor browsers might report `Chrome` (Cursor uses Electron). `navigator.userAgentData.platform` returns OS, not browser, so this should work. Fallback to `navigator.platform` (string match `'Mac'`, `'Win'`, `'Linux'`).
- The base64 encoding of `mcp.json` uses standard base64 (not base64url) — verify with Cursor's deeplink handler. If breaking, switch to base64url.
- Pull-from-CLI in browser: same crypto primitives as Task 13 (`@noble/curves` x25519). Webapp already has `@noble` via its existing identity code.
- Backup JSON download: use `Blob` + `URL.createObjectURL` + anchor click pattern.
- `IdentityPanel` modal: use existing webapp modal component (likely `Dialog` or `Modal` from project's design system).
- The Send-to-CLI flow in the modal is the companion of Task 13's `pull-from-webapp`. The modal POST `/api/cli-bootstrap/issue` returns a short_code; display it + QR; user types it on CLI.
- Strong warning text — the Generate new path is destructive. Test that the destructive button is NOT the modal's default-focus button.
