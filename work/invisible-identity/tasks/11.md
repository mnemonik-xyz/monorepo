# Task 11: `mnemonic identity status` subcommand

## Description

Drift detector. Reads local identity (via `KeyStore`) and cached JWT (from `~/.mnemonic/token.json`), decodes JWT.sub, compares to local pubkey, and prints a status report. Local-only — no network calls per Decision 11.

Independent of Tasks 12/13/14 within Wave 4 (different files, no shared state).

## What to do

1. **Create `packages/cli/src/commands/identity.ts`** (file shared with Tasks 13's pull/push subcommands later — keep that in mind for merge order).

2. **Implement `statusCommand`:**

   ```ts
   export async function statusCommand(opts: { json?: boolean }): Promise<number> {
     const fileStore = new FileKeyStore(IDENTITY_PATH);
     const fileEntry = await fileStore.get();      // legacy → entry, stub → null
     const stubMeta = await readStubFile(IDENTITY_PATH); // {pubkey_base58, keychain_ref} | null
     const localPubkey = fileEntry?.pubkey_base58 ?? stubMeta?.pubkey_base58 ?? null;
     const storageLabel = fileEntry ? 'file' : (stubMeta ? `OS keychain (${platformName()})` : 'none');

     const token = await readTokenFile(TOKEN_PATH);  // null if absent
     const jwtSub = token ? decodeJwtSub(token) : null;

     const status = computeStatus(localPubkey, jwtSub);   // 'synced' | 'diverged' | 'webapp-unknown' | 'no-identity'

     if (opts.json) {
       process.stdout.write(JSON.stringify({ local: localPubkey, jwt_sub: jwtSub, storage: storageLabel, status }) + '\n');
     } else {
       printHumanStatus(localPubkey, jwtSub, storageLabel, status);
     }

     return exitCodeFor(status);  // 0 synced/webapp-unknown, 3 diverged, 1 no-identity
   }
   ```

3. **JWT decoding** — no signature verification, just parse `header.payload.signature`, base64-decode payload, parse JSON, return `sub`. The webapp signed it; we trust the cached token. If parse fails, return null and label `jwt: malformed`.

4. **Status table per Data Models §CLI argv:**

   ```
   local identity:    H8x4...c4v  (did:sol:H8x4...c4v)
   storage:           OS keychain (macOS Keychain)
   cached JWT.sub:    H8x4...c4v
   status:            synced
   ```

   Diverged variant adds "Suggested actions" block per user-spec scenario 3.

5. **Skip the `ensure()` prefix** for this command in `packages/cli/src/index.ts` (Task 7's skip list) — status must work even before any identity exists, so it can print "no identity" rather than create one.

6. **Unit tests** in `packages/cli/test/commands/identity-status.test.ts`:
   - synced (`MemoryKeyStore` set, token.json with matching sub) → exit 0, "synced" output
   - diverged (different sub) → exit 3, "DIVERGED" output, suggested actions visible
   - webapp-unknown (no token.json) → exit 0, "webapp-unknown" output
   - no-identity (empty store + no file) → exit 1, "no identity" output
   - JSON mode → output is parseable JSON, contains all four fields
   - malformed JWT → output indicates malformed, exit 3 (treated as drift signal)

## Notes

- `platformName()` returns one of: `macOS Keychain`, `Secret Service`, `Windows Credential Manager`, `unavailable`, based on `os.platform()` + `OsKeyStore.available()`.
- JWT parse: do NOT use a full crypto lib. `Buffer.from(payload, 'base64url').toString('utf8')` + `JSON.parse` is enough.
- The `Suggested actions` block in human output is a 3-line bullet list (per user-spec scenario 3). In JSON mode, include them as an array `suggested_actions: ["mnemonic identity pull-from-webapp", "mnemonic identity push-to-webapp", "mnemonic login"]`.
- Color: use existing TTY-detection from `work/mnemonic-cli/` (the `chalk` setup or similar). "DIVERGED" in red, "synced" in green, neutral on pipe.
