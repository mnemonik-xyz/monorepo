# Task 9: Extract lineage module + cleanup

## Required Skills

Before starting, load: `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Move `lineage.rs` from `mcp/src/` to `core/src/lineage/mod.rs` and apply three bug fixes during the move. The lineage module is the final domain module extraction — the last step before test artifact migration. It depends on `codec/schema` (already in core from Task 2) for `ParentRef` and `MAX_*` constants, and on `rusqlite::Connection` which is native-only.

The three fixes to apply during extraction:

1. **Direction enum** — `direction` field in `LineageResult` is currently a raw `String`. Convert to a proper `enum Direction { Ancestors, Descendants, Both }` with `serde` derive. Update `traverse_lineage` signature to accept `Direction` instead of `&str`. Update `main.rs` caller.

2. **`chain_valid: Option<bool>`** — `chain_valid` field in `LineageResult` is currently a `bool`. Promote to `Option<bool>` where `None` = unknown / not computed, `Some(true)` = chain fully verified, `Some(false)` = chain has invalid links. Update construction sites and the 9 existing tests.

3. **DB error propagation via `?`** — current code swallows errors from rusqlite calls (via `unwrap()` or silently ignoring `Err`). Replace with `?` propagation so all functions return `anyhow::Result`. Add one new test verifying that an intentionally bad DB connection causes the function to return `Err(...)` rather than panicking.

After this task, `cargo test -p mnemonic-core -- lineage` must pass (9 existing + 1 new = 10 tests) and `cargo clippy -p mnemonic-core -- -D warnings` must be clean.

## Details

**Files and what to change:**

`mcp/src/lineage.rs` (source to read): Contains `init_lineage_schema`, `record_parents`, `get_parents`, `get_children`, `validate_parents`, `traverse_lineage`, structs `LineageResult`, `LineageNode`, `LineageEdge`. Bug locations: (a) `direction: String` in `LineageResult` and `traverse_lineage` parameter, (b) `chain_valid: bool` in `LineageResult`, (c) `unwrap()` or silent `Err` ignoring on rusqlite calls inside `record_parents`, `get_parents`, `get_children`, `traverse_lineage`.

`core/src/lineage/mod.rs` (new file): The fixed version of lineage.rs. Import path for `ParentRef` and `MAX_*` changes from `crate::codec::schema::` to `mnemonic_core::codec::schema::` (or simply `crate::codec::schema::` since we are inside the core crate).

`core/src/lib.rs` (modify): Add `pub mod lineage;` after the existing module declarations (codec, identity, embed, compress, storage, arweave, solana were added in tasks 2-8).

`core/Cargo.toml` (verify/modify): `uuid = { version = "1", features = ["v4"] }`, `anyhow = "1"`, `thiserror = "2"`, `rusqlite = { version = "0.34", features = ["bundled"] }`, `chrono = { version = "0.4", features = ["serde"] }` — all should already be present from previous tasks; confirm and add if missing.

`mcp/src/main.rs` (modify): Change `mod lineage;` to import from `mnemonic_core::lineage` instead. Update any call site that constructs a `Direction` from a string (e.g., `"ancestors".to_string()`) to use `Direction::Ancestors` / `Direction::Descendants` / `Direction::Both`. Update any code reading `result.chain_valid` as a plain bool to handle `Option<bool>`.

**Dependencies:**
- Depends on Task 8 (solana extraction complete, `core/src/lib.rs` already has solana mod, `main.rs` already importing from mnemonic_core for previous modules)
- `ParentRef` and `MAX_*` constants must already be in `core/src/codec/schema.rs` (from Task 2)

**Edge cases to handle:**
- Self-reference cycle detection: `validate_parents` must reject an artifact listing itself as a parent. Existing test covers this — keep it working.
- Max depth boundary: `traverse_lineage` must stop at `MAX_DEPTH = 64` without panic. Existing test covers this — keep it working.
- `Direction` exhaustiveness: if `main.rs` had a string-based match arm on direction values (`"ancestors"`, `"descendants"`, `"both"`), replace with an enum match on `Direction::Ancestors` / `Direction::Descendants` / `Direction::Both` that the compiler enforces exhaustiveness on.
- `chain_valid = None` should be the default/initial value when traversal result is ambiguous or not computed. `Some(false)` when an invalid link is found. `Some(true)` only when all links are verified.

**Error handling (from patterns.md):** Use `anyhow::Result` for all fallible functions. `?` propagation from rusqlite to caller. No `unwrap()` outside `#[cfg(test)]` test helpers. The new error propagation test may use `unwrap()` inside the test body to assert the expected `Err` (that is fine in test code).

**Implementation hint for DB error test:** The cleanest approach is `rusqlite::Connection::open_in_memory()` and then immediately closing it or passing a deliberately invalid path. Alternatively, construct a `Connection` and immediately close the underlying file — rusqlite's error handling will surface as `rusqlite::Error` which anyhow wraps automatically via `?`.
