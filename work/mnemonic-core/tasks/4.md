# Task 4: Extract embed module + remove HashEmbedder

## Required Skills

Before starting, load:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Move the embed module from `mcp/src/embed.rs` into the new `core/src/embed/` directory, making it a proper module of the `mnemonic-core` library crate. The move includes three structural changes on top of the straightforward file relocation:

1. **Remove HashEmbedder entirely.** HashEmbedder produces SHA-256 hashes truncated/padded to fill an f32 vector — the result is non-invertible. TurboQuant decompression of hash-based vectors returns garbage. It must not exist anywhere in `core/src/`.

2. **Introduce MockEmbedder for tests.** Replace HashEmbedder in all test code with a `#[cfg(test)]` `MockEmbedder` that returns deterministic normalized f32 vectors of configurable dimension. The vectors must be decompressible — generated as sequential floats (e.g., [0.0, 1.0, 2.0, ...] after L2 normalization to unit length).

3. **Add fastembed as an optional dependency.** `FastEmbedder` is gated behind the `local-embed` feature flag. `reqwest` with `features = ["json", "blocking"]` is needed for `OpenAIEmbedder`.

After this task, `cargo test -p mnemonic-core -- embed` must pass and `grep -r "HashEmbedder" core/src/` must return nothing. Of the 8 existing embed tests, 6 test HashEmbedder-specific behaviors (dimensions, normalization, model_id) — these must be **deleted** and replaced with MockEmbedder equivalents that test the same behaviors. The remaining 2 tests (cosine_similarity variants) can be updated in place. The 2 db.rs tests that used HashEmbedder must also be replaced with MockEmbedder equivalents.

The 2 db.rs tests that used HashEmbedder cannot use MockEmbedder — `#[cfg(test)]` items from `mnemonic_core` are invisible to external crates. They must be updated to use a minimal inline `TestEmbedder` stub defined locally in `mcp/src/db.rs`. Task 6 will migrate db.rs into core/ where MockEmbedder becomes accessible.

This is Wave 4 — it depends on Task 3 (identity extracted). Tasks 1–3 have already established the workspace structure, core crate skeleton, codec module, and identity module.

`mcp/src/embed.rs` — source file to read and migrate. Contains: `Embedder` trait with `embed`, `dim`, `provider_name`, `model_id`, `is_open_weights` methods; `HashEmbedder` (to be removed); `OpenAIEmbedder` using `reqwest::blocking::Client`; `FastEmbedder` behind `#[cfg(feature = "local-embed")]`; `build_embedder` factory; `cosine_similarity` function; `build_test_embedder` function (remove — replaced by MockEmbedder); 8 unit tests in `#[cfg(test)]` block. The existing embed() return type is `Vec<f32>` (not Result). The tech-spec shows `build_embedder` returning `Result<Box<dyn Embedder>, String>` and `embed()` returning `Vec<f32>` — keep this consistent.

`mcp/src/mcp.rs` — imports `embed::Embedder` at line 8 via `use crate::embed::Embedder;` (or similar local path). Once `mcp/src/embed.rs` is deleted this import becomes a compile error. Change it to `use mnemonic_core::embed::Embedder;`. No other changes needed in this file for this task.

`mcp/src/db.rs` — find the 2 test functions that import and use `HashEmbedder`. They are likely in a `#[cfg(test)]` block importing `use crate::embed::HashEmbedder`. **Do NOT replace with `mnemonic_core::embed::MockEmbedder`.** In Rust, `#[cfg(test)]` items defined in a library crate are not compiled when the crate is used as a dependency — external crates cannot see or import them. Attempting `use mnemonic_core::embed::MockEmbedder` will produce a compile error. Instead, define a minimal anonymous embedder inline in the `#[cfg(test)]` block of `mcp/src/db.rs` (a `struct TestEmbedder` that implements `mnemonic_core::embed::Embedder` with fixed stub values). Task 6 will move the `db.rs` logic into `core/src/storage/`, at which point those tests will live inside the core crate and can use `MockEmbedder` directly.

`core/src/embed/mod.rs` — new file. Structure:
- Top-level: trait definition, cosine_similarity, build_embedder
- OpenAIEmbedder: uses `reqwest::blocking::Client`, reads OPENAI_API_KEY
- FastEmbedder: `#[cfg(feature = "local-embed")]` only
- MockEmbedder: `#[cfg(test)]` only; stores `dim: usize`; `embed()` builds a vec of `[0.0f32, 1.0, 2.0, ..., (dim-1) as f32]` then L2-normalizes it; returns same vector for any input

**MockEmbedder normalization implementation hint:**
Generate the sequential float vec, compute L2 norm as `(sum of squares).sqrt()`, divide each element by norm. Handle dim=0 by returning empty vec. Handle dim=1 by returning `[1.0]`.

**build_embedder error behavior:**
Tech-spec Decision 4 and user-spec Scenario 1 both say: if no embedder configured → `embed()` returns `Err("no embedder configured")`. However, the existing trait has `embed() -> Vec<f32>` (not Result). Two options: (a) change embed() to return `Result<Vec<f32>>` — this is the correct approach per user-spec Scenario 1 but may require updating all callers; (b) make `build_embedder` itself return Err when provider is invalid, so callers never get a Box<dyn Embedder> that would fail. The tech-spec's public API shows `embed(&self, text: &str) -> Vec<f32>` — follow this. The "no embedder configured" error belongs at the `build_embedder` call site, not inside the trait method.

**fastembed optional dependency:**
```toml
[features]
local-embed = ["dep:fastembed"]

[dependencies]
fastembed = { version = "...", optional = true }
```
Check the existing mcp/Cargo.toml for the current fastembed version to use.

**reqwest blocking:**
`OpenAIEmbedder` uses `reqwest::blocking::Client`. This is not WASM-compatible. It is fine for Wave 4 (native only — Decision 7). The `blocking` feature must be in reqwest's features list.

**Dependencies:**
- Depends on Task 3 (identity) being complete — `core/src/lib.rs` already has `pub mod codec;` and `pub mod identity;`
- This task does not depend on compress, db, arweave, solana, or lineage modules
- `mcp/src/db.rs` is not yet moved (that is Task 6), so changes to its test imports must be done in-place

**Edge cases:**
- `MockEmbedder::new(0)` — zero dimension: return empty Vec without panic
- `MockEmbedder::new(1)` — single element: return `[1.0]` (1.0 / 1.0 = unit norm)
- Empty string input to OpenAIEmbedder: API call still made, result handled normally
- Empty string input to MockEmbedder: same fixed vector returned (input not used)
