# Task 15: Test Audit

## Required Skills

Before starting, load: `/skill:test-master` — [SKILL.md](/home/claude/.claude/skills/test-master/SKILL.md)

## Description

Full-feature test quality audit for the extracted `mnemonic-core` crate. This task runs after all implementation waves (tasks 1–11) and documentation updates (task 12) are complete. The goal is to verify that the extracted test suite is complete, correct, and properly structured before pre-deploy QA.

The audit covers eight dimensions:

1. **MockEmbedder adequacy** — replaces the removed `HashEmbedder`; must return deterministic normalized f32 vectors, support configurable dimension, and never trigger real fastembed model downloads in test mode.
2. **httpmock scenario completeness** — arweave module needs ~6 scenarios, solana module needs ~7; audit checks all happy paths and error paths are covered with no reliance on real endpoints.
3. **Storage contract tests** — `AttestationStore` and `LineageStore` trait implementations must have ~4 contract tests each verifying that trait methods work through the SQLite impl.
4. **Edge case coverage** — zero-length embed/compress, concurrent SQLite access, cycle detection in lineage, MAX_DEPTH boundary.
5. **Lineage test completeness** — all 9 existing lineage tests must be updated for the `Direction` enum and `Option<bool>` `chain_valid`; plus 1 new error propagation test.
6. **Error propagation test** — lineage errors propagate via `?` (returns `Err`, not panic).
7. **Numerical fidelity test** — compress module has a roundtrip MSE test verifying that `turboquant_plus_rs` compression stays below a threshold after the namespace migration.
8. **Test pyramid balance** — unit tests are the majority; some integration tests; no E2E tests (acceptable per spec); no benchmarks using real external data.

This task produces a written audit report only — no code is modified. The agent records findings, gaps, and a pass/fail verdict for each checklist item.

## What to do

1. **Read all `#[cfg(test)]` blocks** in `core/src/**/*.rs`. For each module (codec, identity, embed, compress, storage, arweave, solana, lineage), tally the number of test functions and categorize as: unit test, integration test, contract test, property test.

2. **Audit MockEmbedder** in `core/src/embed/`:
   - Verify it is `#[cfg(test)]` gated (not compiled into release builds).
   - Verify it returns normalized f32 vectors of a configurable dimension.
   - Verify no test imports `FastEmbedder` or `OpenAIEmbedder` without being explicitly gated behind `local-embed` feature or an integration test label.

3. **Audit httpmock tests for arweave** (`core/src/arweave/` or `core/tests/`):
   - Count test functions; expected ~6.
   - Verify coverage: `write`, `read`, `write_bytes`, `health_check`, network timeout scenario, malformed response handling.
   - Verify no test contains a real `uploader.irys.xyz` URL or a funded keypair.

4. **Audit httpmock tests for solana** (`core/src/solana/` or `core/tests/`):
   - Count test functions; expected ~7.
   - Verify coverage: `write_memo`, `read_memo`, `airdrop`, `get_tx_signers`, `confirm_tx` retry exhaustion, `health_check`, JSON-RPC error handling.
   - Verify no test contains a real Solana RPC endpoint URL or a funded keypair with lamports.

5. **Audit storage contract tests** (`core/src/storage/`):
   - Count contract test functions; expected ~4.
   - Verify they test trait methods (`AttestationStore` and `LineageStore`) through the SQLite implementation, not just the impl directly.

6. **Audit edge case coverage** across all modules:
   - embed: empty string input, zero-dimension embedder config.
   - compress: zero-length embedding, single-element embedding.
   - storage: concurrent SQLite access (two `AttestationStore` instances same file), query with no results, duplicate `attestation_id`.
   - arweave/solana: malformed JSON, HTTP 5xx, connection timeout, empty response body.
   - lineage: self-reference cycle detection, MAX_DEPTH boundary (64).

7. **Audit lineage tests** (`core/src/lineage/`):
   - Count tests; expected 9 (original) + 1 (error propagation) = 10 total.
   - Verify each test using `Direction` now uses the enum variant (not string literals).
   - Verify tests using `chain_valid` handle `Option<bool>` (not bare `bool`).
   - Verify there is a dedicated test that introduces a DB error and confirms the function returns `Err(...)`, not panics.

8. **Audit numerical fidelity test** (`core/src/compress/`):
   - Verify a test exists that compresses a known vector, decompresses it, and asserts MSE is below a defined threshold.
   - Verify the threshold is documented/named (not a magic number).

9. **Audit integration tests and benchmarks**:
   - Check `core/tests/integration_cbor.rs` and `core/tests/proptest_canonical.rs` exist and pass.
   - Check `core/benches/decompress.rs` and `core/benches/cbor_codec.rs` exist and use criterion harness correctly (`criterion_group!`, `criterion_main!`).
   - Verify benchmarks do not download external data or depend on network at bench time.

10. **Audit for `#[ignore]` tests**:
    - Run `grep -r "#\[ignore\]" core/src/ core/tests/`.
    - Any `#[ignore]` must have a justification comment explaining why and when it will be re-enabled.

11. **Audit test pyramid balance**:
    - Count unit vs integration tests.
    - Unit tests should be the majority (>70% of total test count).
    - If this ratio is violated, note it as a finding.

12. **Write audit report** as your final response. For each checklist item, record: status (PASS / FAIL / PARTIAL), count of tests found vs expected, and — for any FAIL or PARTIAL — a specific finding with file path, line range, and recommended fix.

## Details

**Audit scope — what to look for in each module:**

`core/src/embed/` — `MockEmbedder` struct, `#[cfg(test)]` attribute on the impl or mod block, `impl Embedder for MockEmbedder`, dimension field is configurable (takes a `usize` argument), vector output is normalized (unit length), tests that previously used `HashEmbedder` now use `MockEmbedder`.

`core/src/arweave/` — `#[cfg(test)]` mod with `httpmock::MockServer`, test functions covering: successful write (200 response), successful read, `write_bytes` variant, `health_check` endpoint, a test that simulates a connection timeout or server-side delay, a test that sends a malformed/non-JSON response body and verifies the error type returned. Each test must use `MockServer::start()` and configure URL override on the `ArweaveClient`.

`core/src/solana/` — same httpmock pattern. Tests must cover: `write_memo` (sends SPL memo instruction, mock returns success tx hash), `read_memo` (mock returns a valid Solana RPC `getTransaction` response), `airdrop` (mock returns `requestAirdrop` response), `get_tx_signers` (mock parses signers from tx), `confirm_tx` retry exhaustion (mock returns not-yet-confirmed until max retries), `health_check` (mock returns `getHealth: ok`), JSON-RPC error handling (mock returns `{"error": {...}}`).

`core/src/storage/` — contract tests should create a `SqliteStore` via `tempfile::NamedTempFile`, cast it to `&dyn AttestationStore` and `&dyn LineageStore`, and call each trait method through the trait reference (not the concrete type). This ensures the trait object is usable. Four tests: save + get attestation, search by embedding, add + get lineage edge, query lineage depth.

`core/src/compress/` — MSE test: create a random (or deterministic seeded) f32 vector, compress it, decompress it, compute mean squared error between original and decompressed, assert MSE < threshold. Threshold constant should be named (e.g., `const MAX_ROUNDTRIP_MSE: f32 = 0.01`).

`core/src/lineage/` — the 9 original tests (test names from `mcp/src/lineage.rs`) must all be present and updated. The new error propagation test introduces a broken SQLite connection (or a mock returning error) and asserts the function returns `Err(...)` — not panics with `unwrap()` failure.

**Dependencies:**
- Depends on tasks 11 (MCP rewiring complete) and 12 (architecture.md updated)
- All implementation tasks (1–10) must be done before this audit is meaningful
- No code changes are produced by this task — findings are reported in text

**Edge cases — specific things that might be missing:**
- Concurrent SQLite access test: two `SqliteStore` instances pointing to the same `tempfile`, each inserting concurrently from separate threads. Without a `Mutex`, this would cause `rusqlite::Error::SqliteFailure`. The test verifies the concurrent access is handled correctly (either serialized or returns a proper error).
- Cycle detection: a lineage graph where node A points to B, B points to A. The traversal must not infinite-loop; `cycle detected` or depth limit reached must be returned as `Err`.
- MAX_DEPTH boundary: insert a lineage chain of exactly MAX_DEPTH=64 nodes, verify traversal succeeds. Insert 65-node chain, verify it returns depth-exceeded error or truncates gracefully.
- Zero-dimension `MockEmbedder`: calling `embed()` with dim=0 must not panic — return `Err` or an empty vec consistently.

**Test pyramid — expected counts (approximate):**
- Unit tests: ~50–60 (codec 24 + embed 8 + compress 5 + identity 4 + storage 6 + arweave 6 + solana 7 + lineage 10)
- Integration tests: ~7 (integration_cbor 5 + proptest 1 + standalone usability 1)
- E2E: 0 (none, per spec)
- Benchmarks: 2 files (not counted as tests)

**Implementation hints:**
- Run `cargo test -p mnemonic-core -- --list` to get the exact list of registered test names before reading source. This is faster than manually grepping and will catch tests that are conditionally compiled but do register.
- For benchmark verification, `cargo bench -p mnemonic-core --no-run` confirms the bench harness compiles without running benchmarks (avoids timing overhead during audit).
- If a finding is PARTIAL (e.g., 5 of 6 httpmock scenarios present), note the specific missing scenario by name so the developer knows exactly what to add.
