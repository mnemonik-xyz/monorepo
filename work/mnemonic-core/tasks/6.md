# Task 6: Extract storage with trait split

## Required Skills

Before starting, load: `/skill:code-writing` — [SKILL.md](/home/claude/.claude/skills/code-writing/SKILL.md)

## Description

This task extracts the SQLite storage layer from `mcp/src/db.rs` into a standalone module in `core/src/storage/`. The extraction introduces a clean trait abstraction: `AttestationStore` and `LineageStore` traits defined in `core/src/storage/traits.rs`, with a concrete SQLite implementation in `core/src/storage/sqlite.rs`.

The split has an important boundary rule: payment-related methods (`create_api_key`, `deduct_balance`, `credit_deposit`, `mark_x402_nonce`, `record_attestation_cost`, `get_pnl_stats`, `get_owner_pubkey`) stay in `mcp/src/payment.rs` and are NOT included in the core traits. Core consumers need attestation CRUD and semantic search — they never need payment logic.

Authorization is also deliberately excluded from the traits: trait methods operate on the full database without per-signer scoping. This matches the existing `db.rs` behavior and is explicitly documented in trait-level rustdoc. The MCP server enforces authorization via the keypair loaded at startup.

After this task, `mcp/src/tools.rs` and `mcp/src/main.rs` import storage types from `mnemonic_core::storage::` instead of the local `db` module. The SQLite dependency moves to `core/Cargo.toml`. The `cargo test -p mnemonic-core -- storage` suite is green, and `grep -r "create_api_key\|deduct_balance" core/src/` returns empty.

## What to do

1. Create `core/src/storage/` directory with three files: `mod.rs`, `traits.rs`, `sqlite.rs`.

2. In `traits.rs`, define two public traits with full rustdoc:
   - `AttestationStore` — attestation CRUD and cosine search: `save_attestation`, `find_by_tx`, `count`, `search`. Document at the trait level: "Authorization is the caller's responsibility. These methods operate on the full database and do not enforce per-signer scoping."
   - `LineageStore` — lineage graph operations: `init_lineage_schema`, `record_parents`, `get_parents`, `get_children`, `validate_parents`, `traverse_lineage`. Same authorization note.

3. In `sqlite.rs`, implement both traits for `SqliteStore`:
   - `SqliteStore` wraps `rusqlite::Connection`
   - Constructor `SqliteStore::open(path: &Path) -> anyhow::Result<Self>` — calls `CREATE TABLE IF NOT EXISTS` for all tables on open (same schema as `db.rs`)
   - Constructor `SqliteStore::in_memory() -> anyhow::Result<Self>` — for tests
   - All SQL queries must use rusqlite parameterized queries (`?` placeholders, no string interpolation)
   - Move ONLY the non-payment methods from `db.rs`: `save_attestation`, `find_by_tx`, `count`, `search`; lineage methods from `lineage.rs`
   - Do NOT include any payment methods

4. In `mod.rs`, re-export: `pub use traits::{AttestationStore, LineageStore}; pub use sqlite::SqliteStore;` and expose public data types (`AttestationRow`, `SearchResult`).

5. In `core/src/lib.rs`, add `pub mod storage;`

6. In `core/Cargo.toml`, verify `rusqlite = { version = "...", features = ["bundled"] }`, `uuid`, and `chrono` are listed (per tech-spec they are already in the dependency list).

7. In `mcp/src/payment.rs`, keep all payment methods intact: `create_api_key`, `deduct_balance`, `credit_deposit`, `mark_x402_nonce`, `record_attestation_cost`, `get_pnl_stats`, `get_owner_pubkey`. Update internal imports to use `mnemonic_core::storage::SqliteStore` (or still reference the local struct depending on how payment.rs holds a connection — adapt to whatever makes payment.rs compile).

8. In `mcp/src/tools.rs` and `mcp/src/main.rs`, update imports: replace `crate::db::AttestationStore` and similar with `mnemonic_core::storage::{AttestationStore, SqliteStore}`.

9. Add contract tests in `core/src/storage/sqlite.rs` under `#[cfg(test)]`: ~4 tests that verify trait methods work through `SqliteStore` in-memory. Write these tests BEFORE writing the implementation (TDD).

## Details

**Files and what to do:**

`core/src/storage/traits.rs` — Define two public traits. Each trait method signature is derived from `db.rs` public API (see code-research.md section 5, `db` module). Methods for `AttestationStore`: `save_attestation` (takes attestation fields by value or reference — match the existing `db.rs` signature exactly), `find_by_tx(&self, tx_id: &str) -> anyhow::Result<Option<AttestationRow>>`, `count(&self, signer: &str) -> anyhow::Result<i64>`, `search(&self, query_embedding: &[f32], signer: &str, limit: usize) -> anyhow::Result<Vec<SearchResult>>`. For `LineageStore`: methods matching the free functions in `lineage.rs` — `init_lineage_schema`, `record_parents`, `get_parents`, `get_children`, `validate_parents`, `traverse_lineage`. Data types `AttestationRow` and `SearchResult` are defined here or in `mod.rs` (whichever keeps the code cleaner).

`core/src/storage/sqlite.rs` — `SqliteStore` struct wrapping `rusqlite::Connection`. The `open` constructor creates the directory if it does not exist (using `std::fs::create_dir_all`) and applies the schema (all `CREATE TABLE IF NOT EXISTS` statements from `db.rs`). The `in_memory` constructor opens `:memory:` and applies the same schema. All SQL is parameterized — never format strings into SQL queries. The cosine search in `search()` fetches all embeddings then scores them in Rust (matching existing db.rs behavior) — do not try to do cosine math in SQL.

`mcp/src/payment.rs` — Payment methods (`create_api_key`, `deduct_balance`, `credit_deposit`, `mark_x402_nonce`, `record_attestation_cost`, `get_pnl_stats`, `get_owner_pubkey`) currently live on the `AttestationStore` struct. After the split, they need a DB connection. Adapt `payment.rs` to accept `&SqliteStore` or wrap a direct `rusqlite::Connection`. Whatever approach compiles without breaking payment.rs callers is correct.

**Dependencies:**
- Depends on Task 5 (compress extraction) being complete — `core/src/lib.rs` and `core/Cargo.toml` must already exist with codec, identity, embed, compress modules
- `rusqlite = { version = "...", features = ["bundled"] }` must be in `core/Cargo.toml`
- `uuid = { version = "...", features = ["v4"] }` and `chrono = { version = "...", features = ["serde"] }` must be in `core/Cargo.toml`

**Storage lock discipline (from patterns.md):**
`rusqlite::Connection` is `!Send`. In async contexts, callers must wrap `SqliteStore` in `std::sync::Mutex` and never hold the lock across an `.await` point. Document this constraint in the `SqliteStore` rustdoc. The trait methods themselves are synchronous — no `async fn` in the traits.

**Edge cases to handle:**
- Concurrent access (two `SqliteStore::open()` on the same file path): enable WAL mode (`PRAGMA journal_mode=WAL`) on connection open, or document that callers must serialize access — write a test that opens two instances and writes from both without panicking
- `find_by_tx` with no matching row: return `Ok(None)`, not an error
- `search` with empty embedding store: return `Ok(vec![])`, not an error
- Duplicate `attestation_id` in `save_attestation`: return a descriptive `Err`, not a panic — rusqlite will return a constraint violation error which should be propagated via `?`

**Implementation hints:**
- Read `mcp/src/db.rs` in full before writing a single line — map every public method to either the core traits or the payment layer
- The cosine similarity scoring loop in `search()` is pure Rust over fetched embeddings — no SQL math
- `init_lineage_schema` creates the `lineage_edges` table; call it from `SqliteStore::open` and `SqliteStore::in_memory` after the main schema
- For test contract: use `SqliteStore::in_memory()` — no temp files needed for unit tests (except the concurrent access test which needs an actual file)
