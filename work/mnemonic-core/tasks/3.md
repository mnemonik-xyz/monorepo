# Task 3: Extract identity module

## Required Skills

Before starting, load:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Move `mcp/src/identity.rs` to `core/src/identity/mod.rs`, making it a proper module in the `mnemonic-core` library crate. The identity module provides all Ed25519 keypair operations: loading or generating a keypair from a JSON file, base58 public-key formatting, DID derivation (did:sol and did:key), arbitrary-message signing, and signature verification.

This is Wave 3 in the sequential extraction plan (codec → identity → embed → compress → ...). Identity depends only on `solana-sdk` and `bs58` — both already present in the project — so there are no new inter-module dependencies to wire. After the move, `mcp/src/main.rs` and `mcp/src/tools.rs` update their `use crate::identity::` imports to `use mnemonic_core::identity::`. The `identity.rs` file in `mcp/src/` and its `mod identity;` declaration in `main.rs` are removed.

Security note: this module handles keypair loading from the filesystem and Ed25519 signing. The security-auditor must verify the file I/O paths, absence of any key material in test assertions, and correct use of `Keypair::try_from`.

## What to do

1. Create `core/src/identity/mod.rs` by moving the full source of `mcp/src/identity.rs` into it verbatim. No logic changes — the code is correct as-is.

2. Add `pub mod identity;` to `core/src/lib.rs` below the existing `pub mod codec;` line.

3. Verify `core/Cargo.toml` already lists `solana-sdk` and `bs58` as dependencies (they were added in Task 1 scaffold). If either is missing, add it with the version matching `mcp/Cargo.toml` (`solana-sdk = "2.2"`, `bs58 = "0.5"`). Also ensure `tempfile` is in `[dev-dependencies]` (needed by the 4 existing identity tests).

4. In `mcp/src/main.rs`: remove `mod identity;` from the module list at the top and replace all `identity::` usages with `mnemonic_core::identity::`. Add `use mnemonic_core::identity;` (or import the specific functions via `mnemonic_core::identity::{load_or_create_keypair, did_sol}`). There are two call sites: `identity::load_or_create_keypair` and `identity::did_sol`.

5. In `mcp/src/tools.rs`: remove `identity` from the `use crate::{ ... }` import block and add `use mnemonic_core::identity;`. All five tools call identity functions (`pubkey_base58`, `did_sol`, `did_key`, `sign_bytes`).

6. Delete `mcp/src/identity.rs`.

7. Run `cargo test -p mnemonic-core -- identity` — all 4 tests must pass. Run `cargo clippy -p mnemonic-core -- -D warnings` — zero warnings.

## TDD Anchor

The 4 existing tests in `identity.rs` must be preserved in `core/src/identity/mod.rs` and must pass after the move. Write them in the new location before verifying the implementation compiles.

- `core/src/identity/mod.rs::tests::test_did_sol` — `did_sol(&kp)` starts with `"did:sol:"` and contains the base58 pubkey
- `core/src/identity/mod.rs::tests::test_did_key` — `did_key(&kp)` starts with `"did:key:z"` and is deterministic (two calls return equal strings)
- `core/src/identity/mod.rs::tests::test_sign_verify` — `sign_bytes` returns 64-byte signature; `verify_signature` returns true for correct message and false for wrong message
- `core/src/identity/mod.rs::tests::test_keypair_roundtrip` — `load_or_create_keypair` called twice on the same path returns keypairs with identical pubkeys; uses `tempfile::tempdir()`

- `core/Cargo.toml` (verify/modify) — confirm `solana-sdk = "2.2"` and `bs58 = "0.5"` are present under `[dependencies]`. Confirm `tempfile = "3"` is under `[dev-dependencies]`. These should have been added in Task 1 but if absent, add them now.

- `mcp/src/main.rs` (modify) — line 7 is `mod identity;` — remove it. Lines 344 and 346 call `identity::load_or_create_keypair` and `identity::did_sol` — update to use `mnemonic_core::identity::` prefix or add a `use mnemonic_core::identity;` statement at the top so the call sites remain unchanged in form.

- `mcp/src/tools.rs` (modify) — the `use crate::{ ... }` block on lines 10-24 includes `identity,` — move it out. Add `use mnemonic_core::identity;` as a separate use statement. All identity call sites in the file (`identity::pubkey_base58`, `identity::did_sol`, `identity::did_key`, `identity::sign_bytes`) use the short unqualified form and will continue to work after the import change.

- `mcp/src/identity.rs` (delete) — remove file after confirming `core/src/identity/mod.rs` has its content.

**Dependencies:**
- Depends on Task 2 (codec extraction) being complete — `core/src/lib.rs` and `core/Cargo.toml` must already exist with base structure.
- No downstream tasks in the same wave — this is the sole Wave 3 task.

**Edge cases:**
- `load_or_create_keypair` uses `std::fs::read_to_string` and `std::fs::write` — these are not gated with `#[cfg(not(target_arch = "wasm32"))]` since WASM is out of scope for this iteration (Decision 7). Leave as-is.
- `verify_signature` does `<[u8; 64]>::try_from(signature).unwrap()` inside a len-check guard — this `unwrap` is safe and acceptable inside a function body that already checked `signature.len() != 64`. Leave as-is; clippy will not flag it.
- The test `test_keypair_roundtrip` uses `tempfile::tempdir()` with `.unwrap()` — acceptable in tests per project convention.

**Implementation hints:**
- The simplest import approach for `mcp/src/tools.rs` is to replace `identity,` in the `use crate::{ ... }` block with nothing, then add `use mnemonic_core::identity;` at the top of the file. All existing call sites (`identity::pubkey_base58(keypair)`, etc.) continue to compile.
- For `mcp/src/main.rs`, add `use mnemonic_core::identity;` near the other imports and remove `mod identity;`. The two call sites on lines 344/346 will then resolve through the new import.
- Do not add `mnemonic_core::` prefixes inline to the call sites if a `use` statement can keep them readable.
