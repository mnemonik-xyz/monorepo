## Description

Move the integration test files (`tests/integration_cbor.rs`, `tests/proptest_canonical.rs`) and benchmark files (`benches/decompress.rs`, `benches/cbor_codec.rs`) from `mcp/` into the `core/` crate. After the move, eliminate any inline helper code that duplicates functions now available through `mnemonic_core::` — replace all such helpers with direct library imports.

This is the final code-writing wave before the MCP rewiring task. Its purpose is to prove that `mnemonic-core` is independently testable and benchmarkable without `mnemonic-mcp`. The acceptance proof is `cargo test -p mnemonic-core` completing without ever building the MCP crate.

Add `criterion` (with `harness = false`) and `proptest` as dev-dependencies in `core/Cargo.toml`, and declare the two `[[bench]]` targets so Cargo knows where to find them.

## What to do

1. Create `core/tests/` directory and move `mcp/tests/integration_cbor.rs` and `mcp/tests/proptest_canonical.rs` into it. Remove the originals from `mcp/tests/`.

2. Create `core/benches/` directory and move `mcp/benches/decompress.rs` and `mcp/benches/cbor_codec.rs` into it. Remove the originals from `mcp/benches/`.

3. In each moved test file, audit every helper function and constant. If anything duplicates logic already exported from `mnemonic_core`, delete the inline copy and replace usages with the import from `mnemonic_core::`. Integration test files in `tests/` are already treated as separate crates by Cargo — no `#[cfg(test)]` wrapper is needed.

4. In each moved bench file, similarly replace any inline helper code with imports from `mnemonic_core::`. Benchmarks are also separate crates — add `use mnemonic_core::...` at the top.

5. Update `core/Cargo.toml`:
   - Add `criterion = { version = "0.5", features = [] }` under `[dev-dependencies]`.
   - Add `proptest = "1"` under `[dev-dependencies]` (already planned in tech-spec; confirm it is not a duplicate).
   - Add two `[[bench]]` sections:
     ```toml
     [[bench]]
     name = "decompress"
     harness = false

     [[bench]]
     name = "cbor_codec"
     harness = false
     ```

6. Verify `mcp/` no longer references the moved test or bench files (no stale `path` references in `mcp/Cargo.toml`).

7. Run `cargo test -p mnemonic-core --tests` and confirm all integration tests and proptests pass. Run `cargo bench -p mnemonic-core --no-run` to confirm benchmarks compile.

## Details

**Files — what to do with each:**

- `mcp/tests/integration_cbor.rs` — read current content to identify any helpers (e.g., test fixture builders, custom assert macros, or codec wrappers) that replicate what `mnemonic_core::codec` already exports. Move the file to `core/tests/integration_cbor.rs`. Replace inline helpers with `use mnemonic_core::codec::...` imports. The file does not need `#[cfg(test)]` — integration test files in `tests/` are standalone crates.

- `mcp/tests/proptest_canonical.rs` — same approach. Move to `core/tests/proptest_canonical.rs`. Confirm `proptest::proptest!` macro is available via the `proptest` dev-dep in `core/Cargo.toml`. Replace any inline serialization helpers with `mnemonic_core::codec` imports.

- `mcp/benches/decompress.rs` — move to `core/benches/decompress.rs`. Criterion benchmarks declare their own `main` (via `criterion_group!` and `criterion_main!` macros) — this requires `harness = false` in the `[[bench]]` Cargo config. Replace any helpers with `mnemonic_core::compress` or `mnemonic_core::codec` imports.

- `mcp/benches/cbor_codec.rs` — move to `core/benches/cbor_codec.rs`. Same criterion harness pattern. Replace inline codec helpers with `mnemonic_core::codec` imports.

- `core/Cargo.toml` — the `[[bench]]` `name` field must match the filename without `.rs`. So `name = "decompress"` corresponds to `core/benches/decompress.rs`. Both must have `harness = false`.

**Dependencies:**

- Task 9 (lineage extraction) must complete first — `core/src/lib.rs` must export all domain modules before integration tests can compile against them.
- `proptest` may already be present in `core/Cargo.toml` from Task 7 or 8 (httpmock tests). Check before adding a duplicate entry.
- `criterion` version: use `"0.5"` to match current Rust ecosystem. No additional features needed for basic benchmarking.

**Edge cases:**

- If `mcp/tests/` or `mcp/benches/` directories become empty after the move, remove the empty directories to keep the tree clean.
- `mcp/Cargo.toml` may have no explicit `[[bench]]` entries (Cargo auto-discovers from `benches/`). After removing the bench files, no `mcp/Cargo.toml` changes are needed unless it has explicit bench declarations — check and remove those if present.
- The moved integration test files import `mnemonic_core` as an external crate (they are in `tests/`, not `src/`). The `[dev-dependencies]` path to `mnemonic-core` is the workspace dependency — this should already be present from `core/Cargo.toml`'s `[lib]` definition. No special entry is needed.
- Watch for `use super::*` patterns — these are invalid in integration test files (no parent module). Replace with explicit `use mnemonic_core::...` paths.

**Implementation hints:**

- Read each file fully before touching it. Understanding what the inline helpers do tells you exactly which `mnemonic_core` symbol to import instead.
- Use `cargo test -p mnemonic-core --tests 2>&1 | head -50` after each file move to catch import errors immediately rather than fixing all four at once.
- Cargo's test discovery for `tests/` is automatic — no registration needed in `Cargo.toml` for integration test files.
- Cargo's bench discovery requires explicit `[[bench]]` sections when `harness = false` — without them, Cargo would try to use the default libtest harness, which does not understand `criterion_main!`.
