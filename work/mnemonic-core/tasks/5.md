# Task 5: Extract compress module

## Required Skills

Before starting, load: `/skill:code-writing` — [SKILL.md](/home/claude/.openclaw/workspace/mnemonic-refactored/.claude/skills/code-writing/SKILL.md)

## Description

Move `mcp/src/compress.rs` into a new module at `core/src/compress/mod.rs`. This is Wave 5 in the phased extraction — compress depends on the `turboquant-plus-rs` crate migrated in Task 1. Wave ordering places it after Task 4 for architectural consistency; in practice `compress.rs` does not import the `Embedder` trait or any embed types — it only uses `ndarray::Array1` and `turboquant_plus_rs`. After the move, `mcp/` must import `EmbeddingCompressor` and `CompressedEmbedding` from `mnemonic_core::compress::`.

The only namespace change needed in compress logic is `turboquant::` → `turboquant_plus_rs::` (same API surface, different crate name from crates.io migration). All four existing tests travel with the module unchanged. A fifth test — numerical fidelity roundtrip — must be added to verify the namespace change did not silently alter quantization math: compress a vector, decompress it, assert MSE is below a threshold (e.g., 0.01).

Business rule: default is 4 bits. Do not change the bit width — old and new embeddings in an existing database would become incomparable for recall ranking. Compressed bytes live on Arweave for provenance; uncompressed float32 in SQLite is what cosine search actually uses.

## What to do

1. Create `core/src/compress/mod.rs` — move all content from `mcp/src/compress.rs` into it. Update `turboquant::` references to `turboquant_plus_rs::`. Keep all existing pub/priv visibility, struct definitions, and impl blocks unchanged.

2. Move all 4 existing `#[cfg(test)]` tests from `mcp/src/compress.rs` into the `core/src/compress/mod.rs` test module.

3. Add one new test: numerical fidelity roundtrip. Generate a float32 vector of realistic embedding values (e.g., 384 elements, values in [-1.0, 1.0]). Call `EmbeddingCompressor::compress()`, then decompress. Compute MSE between original and reconstructed vectors. Assert MSE < 0.01.

4. Add two edge-case tests: zero-length embedding input and single-element embedding input. Verify they do not panic — either succeed or return a clean `Err`.

5. Update `core/src/lib.rs` — add `pub mod compress;`.

6. Confirm `core/Cargo.toml` already has `turboquant-plus-rs` and `ndarray` (added in Task 1). No new deps needed.

7. Update `mcp/src/main.rs` — replace any `mod compress;` or direct `use compress::` references with `use mnemonic_core::compress::`.

8. Update `mcp/src/tools.rs` — same import replacement pattern.

9. Update `mcp/src/mcp.rs` — it imports `compress::EmbeddingCompressor` directly. Replace with `use mnemonic_core::compress::EmbeddingCompressor;` (and any other compress types it uses). This file will fail to compile after `compress.rs` is deleted if not updated.

10. Delete `mcp/src/compress.rs`.

11. Run `cargo test -p mnemonic-core -- compress` and `cargo clippy -p mnemonic-core -- -D warnings`. Both must pass before submitting for review.

## Details

**Files and what to do:**

- `mcp/src/compress.rs` — source file to read carefully. Contains `EmbeddingCompressor` struct (likely holds a `turboquant::Quantizer` or equivalent), `CompressedEmbedding` struct (compressed bytes + metadata), `compress()` and `decompress()` methods using ndarray, and 4 existing tests. All of this moves verbatim to `core/src/compress/mod.rs` with only the namespace change.

- `core/src/compress/mod.rs` (new) — destination. Paste the source, update `turboquant::` → `turboquant_plus_rs::`. Add the 3 new tests in `#[cfg(test)]`. Keep existing pub/priv visibility intact.

- `core/src/lib.rs` — add one line: `pub mod compress;`. It already has `pub mod codec;`, `pub mod identity;`, `pub mod embed;` from Tasks 2–4. Place `compress` after `embed` to match the wave order.

- `core/Cargo.toml` — `turboquant-plus-rs = "0.1.0"` and `ndarray` were added in Task 1. Verify they are present. If for some reason `ndarray` is missing, add it.

- `mcp/src/main.rs` — remove `mod compress;` declaration (no longer a local module). Replace `use crate::compress::` or `compress::` references with `use mnemonic_core::compress::`.

- `mcp/src/tools.rs` — same pattern: replace local compress imports with `use mnemonic_core::compress::`.

- `mcp/src/mcp.rs` — imports `compress::EmbeddingCompressor` (and possibly other compress types). After `compress.rs` is deleted this file will fail to compile. Replace all compress imports with `use mnemonic_core::compress::EmbeddingCompressor;` (and any additional compress types it references). No other logic changes needed.

**Dependencies:**

- Depends on Task 4 (embed extraction) — wave ordering places compress after embed extraction for architectural consistency (compress is a higher-level concern than the embedding types). In practice `compress.rs` does not import the `Embedder` trait or any embed types — it only uses `ndarray::Array1` and `turboquant_plus_rs`. Task 4 simply must complete before Task 5 starts.
- Depends on Task 1 (turboquant migration) — `turboquant-plus-rs` must already be in `core/Cargo.toml`.

**Edge cases:**

- Zero-length embedding: `ndarray` operations on an empty array may panic or return errors. The test must confirm no panic.
- Single-element embedding: quantization at 4 bits on a single value should succeed; MSE may be higher but the test only checks for no panic.
- Bit width must stay at 4 (default). Do not parameterize or change it — existing database embeddings would become incomparable.

**Implementation hints:**

- The namespace change from `turboquant::` to `turboquant_plus_rs::` is mechanical — do a project-wide search in the compress file only. The API surface is identical.
- For the MSE test: use `ndarray::Array1<f32>` to compute element-wise difference, square, mean. A threshold of 0.01 is appropriate for 4-bit quantization of normalized embedding vectors.
- Do not add `use` for `turboquant` (old name) anywhere in `core/` — it must not appear.
- Compression is lossy by design (4-bit scalar quantization). The roundtrip MSE test confirms the loss is within acceptable bounds, not that it is zero.
- After deleting `mcp/src/compress.rs`, run `cargo build -p mnemonic-mcp` immediately to catch any missed import references.

**Business rules (from patterns.md):**

- Default bit width is 4. Do not change it.
- Compressed bytes on Arweave are for provenance only. Cosine search in `recall` uses the uncompressed float32 embeddings stored in SQLite. The compress module does not interact with SQLite directly.
