# Task 14: Security Audit

## Required Skills

Before starting, load: `/skill:security-auditor` — [SKILL.md](~/.claude/skills/security-auditor/SKILL.md)

## Description

Full-feature security audit of the completed mnemonic-core extraction. This task runs after all implementation waves (Tasks 1–11) and the documentation update (Task 12) are complete. The codebase has been restructured from a monolith into a Cargo workspace with `mnemonic-core` (library) and `mnemonic-mcp` (binary). This audit verifies that the restructuring did not introduce security regressions and that the stated isolation guarantees hold.

The audit covers five security properties:

1. **No secret material in core/** — private keys, funded keypairs, and API keys must not appear in `core/src/` source or tests.
2. **Payment method isolation** — all 8 payment methods (`create_api_key`, `deduct_balance`, `credit_deposit`, `mark_x402_nonce`, `record_attestation_cost`, `get_pnl_stats`, `get_owner_pubkey`, `verify_usdc_transfer`) must reside exclusively in `mcp/src/payment.rs` — none in `core/`.
3. **httpmock test hygiene** — the new arweave (~6 tests) and solana (~7 tests) httpmock tests must not reference real mainnet URLs (`irys.xyz`, `mainnet-beta.solana.com`) or funded keypairs.
4. **SQL injection resistance** — all rusqlite queries in `core/src/storage/sqlite.rs` must use parameterized statements; no string concatenation in SQL construction.
5. **Keypair file handling** — `core/src/identity/` reads Ed25519 keypairs from filesystem safely; key material must not appear in logs, error messages, or `Display` implementations.

OWASP Top 10 mapping: A03 Injection (SQL parameterization), A02 Cryptographic Failures (key material in logs/tests), A05 Security Misconfiguration (real endpoints in tests).

## What to do

1. Audit `core/src/identity/` — verify keypair loading reads from filesystem path only, key bytes are never formatted into strings or passed to `tracing`/`log` macros, error messages on load failure reveal path but not bytes.

2. Audit `core/src/storage/sqlite.rs` — verify every SQL statement uses rusqlite's `?` parameter placeholders or named parameters (`:name`). Flag any use of `format!()`, string concatenation, or `.to_string()` inside SQL string literals.

3. Audit `core/src/arweave/` test module — grep for any occurrence of `irys.xyz`, `uploader.irys.xyz`, `mainnet`, funded keypair bytes. Verify mock server URL (`127.0.0.1` or `localhost` with dynamic port) is used exclusively. Verify test keypairs are generated fresh or are obviously zero/test-only.

4. Audit `core/src/solana/` test module — same check: no `mainnet-beta.solana.com`, no funded keypairs. Confirm mock JSON-RPC server (httpmock) is used for all network calls.

5. Audit `core/src/**/*.rs` for payment method symbols — grep for all 8 payment method names and `verify_usdc_transfer`. None must appear in core/.

6. Audit `core/src/**/*.rs` for secret material patterns — grep for `-----BEGIN`, `PRIVATE`, base58-encoded private key patterns (88-char bs58), hardcoded hex strings that look like 64-byte private keys.

7. Audit `mcp/src/payment.rs` — confirm all 8 payment methods are present and that `verify_usdc_transfer` takes `&SolanaClient` (not owned) and is not re-exported from core.

8. Audit `mcp/src/tools.rs` — verify input handling: user-supplied strings are not interpolated into SQL (storage calls go through trait methods), no command injection vectors (no `std::process::Command` with user input), JSON parsing uses `serde_json` with typed deserialization.

9. Audit `core/Cargo.toml` — check dependency security: confirm `turboquant-plus-rs = "0.1.0"` (not git), no `git = ` dependencies with unverified URLs, no yanked or unmaintained crates with known CVEs (flag for human review if uncertain), confirm `rusqlite` uses `bundled` feature (no system SQLite version dependency).

10. Verify `anyhow::Result` usage throughout — confirm no `unwrap()` in non-test code in `core/src/`. Test code (`#[cfg(test)]` blocks) may use `unwrap()`.

11. Produce a structured findings report in the audit output. For each finding: severity (Critical/High/Medium/Low/Info), file and line, description, recommended fix. If no findings, state "No findings" per category.

## Details

**Task nature:** Analysis only — no files are modified. The auditor reads source files and produces a findings report written to the decisions.md post-completion entry and the structured JSON log.

**Audit scope rationale:**
- `identity.rs` is the most sensitive module: it loads Ed25519 keypairs from disk. The risk is accidental key material appearing in logs or test fixtures. Check `tracing::` and `log::` call sites near keypair operations.
- `storage/sqlite.rs` is the SQL injection surface. rusqlite parameterized queries use `?` placeholders passed as tuples to `.execute()` or `.query_row()`. Any `format!("SELECT ... WHERE field = '{}'", user_input)` pattern is a finding.
- arweave and solana test modules are new (added in Tasks 7 and 8). They are the highest-risk location for accidentally committed test keypairs or real endpoint URLs copied from documentation examples.
- `mcp/src/payment.rs` isolation: the tech-spec Decision 2 explicitly moved `verify_usdc_transfer` here. Verify the function signature takes `&SolanaClient` (not `SolanaClient` owned, which would move ownership out of core).
- `mcp/src/tools.rs` input handling: MCP tools receive JSON-RPC parameters as `serde_json::Value`. Typed deserialization via `serde_json::from_value::<T>()` is safe; extracting `.as_str()` and putting it into SQL is not. The storage trait methods accept typed Rust structs — confirm user input goes through struct deserialization before any storage call.

**OWASP Top 10 mapping:**
- A02 Cryptographic Failures: private keys in test files or logs
- A03 Injection: SQL string concatenation in rusqlite queries
- A05 Security Misconfiguration: real mainnet endpoints in test code (could trigger real transactions if tests run with a funded keypair)
- A06 Vulnerable and Outdated Components: git dependencies with unverified commit hashes vs pinned crates.io versions

**Dependency review guidance:**
- `turboquant-plus-rs = "0.1.0"` — should be crates.io, not git
- `rusqlite` with `features = ["bundled"]` — pins SQLite version, avoids system library vulnerabilities
- `reqwest` — check that `rustls` or `native-tls` is used (not plaintext HTTP forced); TLS default is acceptable
- `httpmock` is a dev-dependency only — confirm it appears under `[dev-dependencies]`, not `[dependencies]`
- Flag any `git = "https://github.com/..."` dependency for manual human review even if it appears benign

**Error handling:** per patterns.md: `anyhow::Result` throughout, `unwrap()` only in tests. An `unwrap()` in production code on a value derived from user input or file I/O is a panic vector.

**What constitutes a funded keypair in tests:** any 64-byte array literal that is not all-zeros, sequential (0,1,2,...), or labeled `test`/`mock`/`dummy`. Base58-encoded strings of length 87–88 that are not obviously placeholder values.

**Dependencies:** Task 11 (MCP server rewiring + full verification) and Task 12 (documentation update) must be complete before this audit runs — the audit targets the final state of all extracted modules.
