# Task 11: MCP server rewiring + full verification

## Required Skills

Before starting, load: `/skill:code-writing` — [SKILL.md](/home/claude/.claude/skills/code-writing/SKILL.md)

## Description

This is the final extraction wave. All domain modules have been moved to `mnemonic-core` in waves 2–9, tests and benchmarks relocated in wave 10. This task performs a final sweep of `mcp/src/` to confirm every import of a domain type now comes from `mnemonic_core::`, removes any leftover module files that were superseded by core extraction, and runs the full workspace verification suite.

After this task the MCP server is a pure thin wrapper: it owns server bootstrap (`main.rs`), JSON-RPC dispatch (`mcp.rs`), tool implementations (`tools.rs`), payment logic (`payment.rs`), dynamic pricing (`pricing.rs`), and configuration (`config.rs`) — nothing else. All domain types (`ArweaveClient`, `EmbeddingCompressor`, `AttestationStore`, `Box<dyn Embedder>`, `SolanaClient`, codec types, lineage types, identity types) flow in from `mnemonic_core::`.

A critical invariant from the user-spec: `pricing.rs` must remain in `mcp/src/` unchanged. It is not a domain module and must not be moved or modified.

The final acceptance signal is a live JSON-RPC round-trip: calling `tools/list` over stdio returns all 5 tools, and calling `mnemonic_whoami` via Cursor or Claude Desktop returns the same pubkey as before the migration (keypair file was never touched).

## What to do

1. **Audit `mcp/src/tools.rs`** — scan every `use` statement and every type usage. Replace any remaining local domain imports (e.g. `crate::codec::`, `crate::identity::`, `crate::embed::`, `crate::compress::`, `crate::storage::`, `crate::arweave::`, `crate::solana::`, `crate::lineage::`) with their `mnemonic_core::` equivalents. Ensure the file compiles after each change.

2. **Audit `mcp/src/mcp.rs`** — same process. `McpState` struct must own: `ArweaveClient`, `EmbeddingCompressor`, `AttestationStore`, `Box<dyn Embedder>`, `SolanaClient` — all imported from `mnemonic_core::`. Remove any `use crate::` for domain types.

3. **Audit `mcp/src/main.rs`** — same process. Bootstrapping code that constructs `McpState` must use `mnemonic_core::` types. Any remaining `mod` declarations for domain modules (codec, identity, embed, compress, db, arweave, solana, lineage) must be removed.

4. **Audit `mcp/src/payment.rs`** — verify this file contains only payment logic: `create_api_key`, `deduct_balance`, `credit_deposit`, `mark_x402_nonce`, `record_attestation_cost`, `get_pnl_stats`, `get_owner_pubkey`, and `verify_usdc_transfer` (standalone async fn taking `&SolanaClient`). Any domain type it uses must be imported from `mnemonic_core::`.

5. **Remove leftover module files** from `mcp/src/` — delete: `codec/` (directory), `identity.rs`, `embed.rs`, `compress.rs`, `db.rs`, `arweave.rs`, `solana.rs`, `lineage.rs`. These were all moved to `core/` in prior tasks. Do NOT delete `pricing.rs` — it stays.

6. **Clean `mcp/Cargo.toml`** — remove `solana-transaction-status` if it is no longer referenced anywhere in `mcp/src/`. Also remove `solana-client` if it lingered. Confirm `mnemonic-core = { path = "../core" }` is present.

7. **Run full workspace verification** — see Verification Steps. All checks must pass before marking done.

8. **Run MCP round-trip test** — pipe the `tools/list` JSON-RPC call via stdio and confirm 5 tools are returned (see smoke command below).

## TDD Anchor

This task does not introduce new logic — it is an import cleanup and file removal pass. The TDD anchor is the compile + test chain itself.

## Details

**Files and what to do:**

`mcp/src/tools.rs` — final import audit. After tasks 2–9, most domain imports should already use `mnemonic_core::`. This task confirms there are no stragglers. Look for any `use crate::` prefixed with a domain module name and replace. Also verify the file has no `mod codec;`, `mod identity;`, etc. declarations.

`mcp/src/mcp.rs` — contains `McpState` struct definition. Verify all field types: `ArweaveClient` → `mnemonic_core::arweave::ArweaveClient`, `EmbeddingCompressor` → `mnemonic_core::compress::EmbeddingCompressor`, `AttestationStore` → `mnemonic_core::storage::AttestationStore` (the trait impl), `Box<dyn Embedder>` → `Box<dyn mnemonic_core::embed::Embedder>`, `SolanaClient` → `mnemonic_core::solana::SolanaClient`. The struct may use type aliases — ensure aliases also resolve to `mnemonic_core::` types.

`mcp/src/main.rs` — bootstraps `McpState`. Constructs each field from config. All construction calls must use types imported from `mnemonic_core::`. Remove any lingering `mod` declarations for moved modules. `use mnemonic_core::{arweave, compress, embed, identity, solana, storage};` style imports are expected here.

`mcp/src/payment.rs` — contains payment-only logic. Must import `SolanaClient` (and any other `mnemonic_core` types it uses) from `mnemonic_core::solana::SolanaClient`. The `verify_usdc_transfer` function takes `&SolanaClient` as first argument and must remain in this file (moved here in Task 8). No domain structs should be defined locally in this file.

`mcp/Cargo.toml` — `solana-transaction-status` evaluation: grep `mcp/src/` for any `solana_transaction_status` usage. If zero results, remove the dep. `solana-client` should already be absent (removed in Task 1), but confirm. `mnemonic-core = { path = "../core" }` must be present.

- `pricing.rs` must not be touched — it is a user-spec acceptance criterion that it is unchanged.
- If `cargo test --workspace` fails with a test that was already passing before this task, that is a regression introduced by this task's file deletions or import changes. Fix it before proceeding.
- The `--transport stdio` flag for the round-trip test may require specific build features or env vars depending on how the MCP binary was configured. Check `config.rs` if the flag is not recognized.

**Implementation hints:**

- Start with `cargo build -p mnemonic-mcp` on the unmodified state to confirm it compiles before making changes. If it already fails, that is a prerequisite issue from a prior task — document it in decisions.md.
- Use `grep -r "use crate::" mcp/src/` to find all remaining local imports that need updating.
