## Description

Move `arweave.rs` from `mcp/src/` into a new `core/src/arweave/` module and add the first test coverage for `ArweaveClient` using `httpmock`. This is wave 7 in the sequential extraction chain — it depends on the storage module (task 6) being in place so all previously-moved modules are already available in `mnemonic_core::`.

`arweave.rs` currently has zero tests because all its methods hit live HTTP endpoints (Irys uploader or a local arlocal instance). The `httpmock` crate lets us spin up a mock HTTP server in-process, point `ArweaveClient` at it, and exercise all six code paths without any external service.

The Arweave client handles permanent storage for attestation payloads using ANS-104 bundle items signed with the agent's Ed25519 keypair. Auth is ANS-104 bundle item signed with the agent Ed25519 keypair (architecture.md). Production endpoint: `https://uploader.irys.xyz`. Local dev: `http://localhost:1984`. Tests must use neither — only the mock server's localhost address.

After this task, `mcp/src/main.rs` and `mcp/src/tools.rs` import `ArweaveClient` from `mnemonic_core::arweave::` instead of the local `arweave` module.

## What to do

1. Create `core/src/arweave/mod.rs` by moving the full content of `mcp/src/arweave.rs` into it. The public API stays identical: `ArweaveClient::new`, `write`, `write_bytes`, `read`, `mine`, `health_check`.

2. Add `pub mod arweave;` to `core/src/lib.rs`.

3. Update `core/Cargo.toml`:
   - Add `httpmock = "0.8"` under `[dev-dependencies]`
   - Ensure `tokio` dev-dependency has `features = ["macros", "rt-multi-thread"]` (needed for `#[tokio::test]`)

4. Add a test-only constructor to `ArweaveClient` that routes `write()` and `write_bytes()` to `write_irys()` against the mock server. Because `httpmock`'s `MockServer::start()` always returns a `127.0.0.1` URL, `ArweaveClient::is_local()` returns `true` for every mock server address. This causes all `write()` and `write_bytes()` calls in tests to take the `write_arlocal()` code path, which generates a PRNG fake tx ID and ignores the HTTP response entirely — making `test_write_success` fail (gets PRNG ID, not the mock response ID) and `test_malformed_json_response` wrongly pass (arlocal skips JSON parsing).

   The fix combines two changes: an `upload_url: String` field so `write_irys()` targets the mock's `/upload` path, and a `bypass_local_routing: bool` field so `write()` never takes the `write_arlocal()` detour during tests.

   Add both fields to `ArweaveClient`:
   - `upload_url: String` — `new()` sets it to `"https://uploader.irys.xyz/upload"`; `write_irys()` uses `self.upload_url` instead of any hardcoded string.
   - `bypass_local_routing: bool` — `new()` sets it to `false`; the test constructor sets it to `true`.

   Update the routing logic in BOTH `write()` AND `write_bytes()`. Each method has its own independent `is_local()` check and must be patched separately — `write_bytes()` does NOT delegate to `write()`:

   In `write()`:
   ```rust
   if !self.bypass_local_routing && self.is_local() {
       self.write_arlocal(payload, keypair).await
   } else {
       self.write_irys(payload, keypair).await
   }
   ```

   In `write_bytes()` (same pattern — replace its existing `is_local()` guard):
   ```rust
   if !self.bypass_local_routing && self.is_local() {
       // arlocal path (write_arlocal or equivalent)
   } else {
       // write_irys path using self.upload_url
   }
   ```

   Add the `#[cfg(test)]`-only constructor:
   ```rust
   #[cfg(test)]
   pub fn new_for_test(base_url: String) -> Self {
       let upload_url = format!("{}/upload", base_url);
       Self { base_url, upload_url, bypass_local_routing: true, client: reqwest::Client::new() }
   }
   ```

   Use `ArweaveClient::new_for_test(server.base_url())` in all tests that call `write()` or `write_bytes()`. The mock must serve `POST /upload` (not `POST /tx`) for write tests — `POST /tx` is only the arlocal path used by `write_arlocal()`. Production behavior (`new()`) is unchanged: `bypass_local_routing: false` means `is_local()` still routes to `write_arlocal()` for localhost URLs.

5. Write ~6 `#[tokio::test]` tests inside a `#[cfg(test)]` block in `core/src/arweave/mod.rs` (see TDD Anchor):
   - `test_write_success` — mock `POST /upload` returning 200 with `{"id":"test-tx-id-123"}`, call `write()` via `new_for_test`, assert returned ID is `"test-tx-id-123"`
   - `test_read_success` — mock `GET /{tx_id}` (no `/tx/` prefix, no `/data` suffix — actual code uses `GET {base_url}/{tx_id}`), call `read()`, assert bytes returned
   - `test_write_bytes_success` — mock `POST /upload` returning 200, call `write_bytes()` via `new_for_test`, assert tx ID returned
   - `test_health_check_success` — mock `GET /info` returning 200 (actual code requests `GET {base_url}/info`), assert `health_check()` returns `true`
   - `test_network_timeout` — use an unreachable port / no mock registered, assert the call returns `Err` (or `false` for health_check)
   - `test_malformed_json_response` — mock `POST /upload` returning 200 with body `not-json`, call `write()` via `new_for_test`, assert `write()` returns `Err`

   SECURITY: all tests must use only `httpmock`'s `MockServer::start()` address (e.g., `http://127.0.0.1:{port}`). No hardcoded mainnet URLs (`uploader.irys.xyz`). No real funded keypairs — use a freshly generated test keypair (`solana_sdk::signature::Keypair::new()`).

6. Delete `mcp/src/arweave.rs`.

7. Update `mcp/src/main.rs`: change `mod arweave;` to `use mnemonic_core::arweave::ArweaveClient;` (or equivalent `use mnemonic_core::arweave;`).

8. Update `mcp/src/tools.rs`: change any `use crate::arweave::` imports to `use mnemonic_core::arweave::`.

**upload_url + bypass_local_routing fields — required for write/write_bytes tests:**

`ArweaveClient::is_local()` returns `true` for `127.0.0.1` URLs. Since `MockServer::start()` always binds to `127.0.0.1`, every `write()` call in tests takes the `write_arlocal()` path: it generates a PRNG fake tx ID and never issues the HTTP request. This breaks `test_write_success` (PRNG ID != `"test-tx-id-123"`) and silently breaks `test_malformed_json_response` (arlocal never parses JSON).

Additionally, `write_irys()` previously posted to a hardcoded `"https://uploader.irys.xyz/upload"` string, ignoring `self.base_url` entirely — meaning even if routing were bypassed, the real production URL would still be hit.

The correct fix requires both fields:
1. `upload_url: String` — `new()` sets it to `"https://uploader.irys.xyz/upload"`; `write_irys()` uses `self.upload_url` so tests can redirect it to the mock.
2. `bypass_local_routing: bool` — `new()` sets it to `false` (production unchanged); `new_for_test()` sets it to `true` so `write()` skips the `is_local()` check and always calls `write_irys()`.

Updated routing in `write()`:
```rust
if !self.bypass_local_routing && self.is_local() {
    self.write_arlocal(payload, keypair).await
} else {
    self.write_irys(payload, keypair).await
}
```

Test-only constructor:
```rust
#[cfg(test)]
pub fn new_for_test(base_url: String) -> Self {
    let upload_url = format!("{}/upload", base_url);
    Self { base_url, upload_url, bypass_local_routing: true, client: reqwest::Client::new() }
}
```

**httpmock test pattern (with upload_url pointing at mock):**

```
let server = MockServer::start();
let mock = server.mock(|when, then| {
    when.method(POST).path("/upload");
    then.status(200).body(r#"{"id":"test-tx-id-123"}"#);
});
// new_for_test sets upload_url = "{server.base_url()}/upload"
// write_irys() uses self.upload_url — hits mock, not production
let client = ArweaveClient::new_for_test(server.base_url());
let keypair = Keypair::new();  // ephemeral — no real funds
let result = client.write("test payload", &keypair).await;
assert!(result.is_ok());
assert_eq!(result.unwrap(), "test-tx-id-123");
mock.assert();
```


**Timeout test pattern:**

Use a port with no listener. `reqwest` will fail to connect and return an error. Alternatively, `httpmock` may provide a way to delay/hang responses — check crate docs. The goal is to confirm `write()` returns `Err(...)` rather than panicking.

**Malformed JSON test:**

Mock returns `200 OK` with body `"not valid json at all"`. The `ArweaveClient::write` method attempts to parse the response as JSON to extract the tx ID. Verify it returns `Err` — not a panic.
