# Task 16: Pre-deploy QA

## Required Skills

Before starting, load: `/skill:pre-deploy-qa` — [SKILL.md](/home/claude/.claude/skills/pre-deploy-qa/SKILL.md)

## Description

Full acceptance testing pass for the mnemonic-core extraction feature. Runs all tests across the workspace, verifies every acceptance criterion from both user-spec and tech-spec, and produces a structured QA report. This is the final gate before the feature is considered shippable.

The task depends on all three audit tasks (code, security, test) being complete. Its job is not to find new bugs — that's what auditors did — but to confirm the entire feature meets the specified acceptance bar end-to-end: builds compile, tests are green, grep checks pass, and the MCP server round-trip works.

If any criterion fails, the QA agent blocks and reports to the user before marking the feature done.

## What to do

1. Read user-spec.md and tech-spec.md acceptance criteria sections. Collect every criterion into a checklist.
2. Run the full test suite: `cargo test --workspace`. Record total/passed/failed/skipped.
3. Run clippy: `cargo clippy --workspace -- -D warnings`. Record any warnings.
4. Execute every grep check from the Agent Verification Plan (HashEmbedder absent, payment methods absent, architecture.md updated).
5. Run the MCP local mode round-trip check (tools/list returns 5 tools via stdio).
6. Run the standalone core test (confirms mnemonic-core is independently usable without building mcp).
7. For each acceptance criterion from user-spec and tech-spec: mark passed / failed / not_verifiable with concrete evidence.
8. Assess coverage: verify each extracted module (codec, identity, embed, compress, storage, arweave, solana, lineage) has corresponding tests.
9. Write `logs/working/qa-report.json` with full structured results.
10. Write a brief entry to decisions.md.
11. If any critical failures found — stop, report to user, do not proceed to the done step.
