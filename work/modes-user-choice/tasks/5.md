# Task 5: Retire "Never mix in one DB" + sync project-knowledge

## Description

Land the documentation changes that make the new per-request mode model the
canonical source of truth. CLAUDE.md's two superseded rules are consciously
retired with rationale (not silently dropped). Project Knowledge files
(`patterns.md`, `architecture.md`) are updated to describe the new mode
dispatch. `decisions.md` gets a final task-completion entry per the repo's
append-only format.

## What to do

1. **Root `CLAUDE.md`** — rewrite the "Storage modes" subsection of the
   "Architecture" section:
   - Remove the literal sentences *"The mode is set at server startup, not
     per-call."* and *"Never mix modes in one database."* (the actual lines
     present in the file today).
   - Replace with a paragraph stating: mode is a per-write user choice
     (`mode: "local" | "participate"`, default `local` with env-var fallback
     for legacy clients); rows tagged via `write_mode` column; `recall`
     spans both modes for one owner.
   - Add a one-line rationale + cross-reference pointing at
     `work/modes-user-choice/user-spec.md` and `decisions.md`.
   - Note the delivery definition: `participate` succeeds only after the
     anchored bytes pass a recall+verify round-trip.

2. **`.claude/skills/project-knowledge/references/patterns.md`** — update
   the "Storage modes" paragraph to mirror the new model. Reword the lock
   discipline section if needed to note the additional `DashMap` shard
   guard rule introduced in T3.

3. **`.claude/skills/project-knowledge/references/architecture.md`** —
   add a short "Mode dispatch" subsection under "Data Flow" describing:
   - The `whoami` envelope contract (`supported_modes`, `default_mode`,
     `participate_cost`).
   - The resolver function (single source of truth for paywall + persisted
     column).
   - The delivery-confirmation step (`recall + verify_cose` over the
     anchored bytes; demote-to-local on failure; refund).
   - The DoS guard keyed on `api_key_hash`.

4. **`.env.example`** (if present at repo root or `mcp/.env.example`):
   document that `STORAGE_MODE` and `PAYMENT_MODE` now set the operator
   *capability/default*; `local` writes are always free regardless of
   `PAYMENT_MODE`. Add the 4 new env vars introduced in T3
   (`MNEMONIC_DELIVERY_REFETCH_TIMEOUT_SECS`,
   `MNEMONIC_DELIVERY_QUOTA_THRESHOLD`,
   `MNEMONIC_DELIVERY_QUOTA_WINDOW_SECS`,
   `MNEMONIC_DELIVERY_QUOTA_EVICT_SECS`) with documented defaults.

5. **`docs/WHITEPAPER.md` §5.7** — add a one-paragraph cross-reference
   linking §5.7.1 (free verification + self-hosting invariants) to the
   `local` path and §5.7.2 (service-layer monetization) to the
   `participate` path. Keep it minimal — the whitepaper rewrite is a
   separate effort.

6. **Append `work/modes-user-choice/decisions.md`** with a final
   "Implementation completed" entry per the repo's strict append-only
   format. Reference the merged tech-spec, the validators that ran, and
   the implementation tasks (T1–T4 + audit + QA).
