# Task 7: Delivery = anchored AND verified by recall

## Description

The delivery guarantee. A `participate` write is only reported `participated`
(and only charged) after a **recall + verify round-trip against the anchored
artifact** succeeds. This is the user's definition — reuse existing verify
machinery, no bespoke read-back primitive.

## What to do

1. **In `sign_memory_inline` (`mcp/src/tools.rs`), after the Arweave+Solana
   anchor** for a `Participate` write:
   - Run the confirmation: fetch the anchored COSE bytes (the `full`-mode path in
     `tools::verify` already does `arweave.read(tx)` → COSE verify → compare hash
     with the Solana anchor) and confirm recall can retrieve the row.
   - On success: set `recall_verified_at = now`, persist the
     `delivery_receipt = {arweave_tx, solana_tx, recall_verified_at}`, report
     `"mode": "participate"`, and proceed to charge (Task 5 gate).
   - On failure (anchor didn't land / bytes don't verify): **do not charge**,
     downgrade the reported result to `local` with synthetic ids, and surface a
     clear `delivery: "failed"` note. The artifact must never be reported
     `participated` while effectively still local.
2. **`verify` output:** surface `recall_verified_at` / `delivery_receipt` so a
   third party sees the artifact was confirmed-delivered, not just written.
3. Forward-shape the receipt struct with an optional `acks: []` field (unused in
   V1; reserved for the deferred recipient-ACK / A2A-bridge path).

## Acceptance Criteria

- [ ] A successful `participate` write returns a `delivery_receipt` with a non-null `recall_verified_at`, and recall+verify against the anchored artifact passes.
- [ ] A forced anchor/verify failure ⇒ result reported `local`, **no charge**, `delivery: "failed"`.
- [ ] `verify` surfaces the receipt; `recall_verified_at` persisted on the row.
- [ ] `MockEmbedder` used in tests (no `HashEmbedder`); `cargo test -p mnemonic-mcp` passes.
