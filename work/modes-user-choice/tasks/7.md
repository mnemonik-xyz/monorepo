# Task 7: Security audit (Audit Wave)

## Description

OWASP Top 10 + tenant-isolation + payment-handling review across the entire
feature surface produced by T1–T5. Read-only — write the report only; no
code changes here. If issues are found, the feature-execution lead spawns a
fixer agent and this auditor becomes the reviewer for the fix.

## What to do

Focus areas (drawn from the three security-audit rounds the tech-spec
already passed; revalidate against actual code):

1. **Input validation.** `resolve_write_mode` rejects every non-canonical
   `mode` value (`null`, non-string, empty, whitespace, case variants,
   unknown) with `-32602 InvalidParams`. The paywall gate and the persisted
   `write_mode` column come from the SAME resolver output (drift impossible
   by construction). Verify in code.

2. **Tenant isolation.** `find_by_tx` (and any sibling lookup used by
   routing) filters by `owner_pubkey`. Cross-tenant `verify` returns
   "not found" with identical response shape to a genuine miss — no
   leaked `content_hash`, `signer_pubkey`, content preview, or response-
   timing skew that distinguishes the two cases (the response-timing
   residual R2-F4 is documented as accepted but verify it has not
   *widened*).

3. **Payment refund correctness.** `payment::refund_balance` is the
   primitive used (idempotent, exempt from the `tx_sig` UNIQUE index per
   `payment.rs` audit-trail logic — verify). Refund reason includes the
   demoted `attestation_id` for 1:1 correlation with the downgrade.
   x402-nonce path: induced delivery failure does NOT consume the nonce;
   caller can retry with the same payment.

4. **DoS amplification guard.** `RefundsBySubject` is keyed on
   `api_key_hash` (not `owner_pubkey`); quota check happens at
   participate-entry BEFORE Arweave/Solana writes; on exceed the request
   returns `-32011 DeliveryQuotaExceeded` with zero chain calls (verify
   via test or static reasoning). Retry budget is wall-clock
   (`MNEMONIC_DELIVERY_REFETCH_TIMEOUT_SECS`), not a fixed attempt count.
   Eviction policy bounded.

5. **PII / data-at-rest in `payment_events`.** Refund-failure audit row
   carries ONLY `{api_key_hash, attestation_id, reason, occurred_at}`.
   No raw `api_key`, no `content_preview`, no `cose_bytes`, no embedding,
   no payload bytes. Verify by reading the migration + `record_refund_failed`
   API.

6. **Lock-across-await.** SqliteStore mutex AND DashMap shard guards
   never held across `.await`. Grep + manual review of T3 participate
   flow.

7. **Information disclosure via errors.** `UnsupportedMode` data
   (`supported: ["local"]`) is symmetric with `whoami.supported_modes` —
   not new disclosure. `DeliveryNotConfirmed` data
   (`arweave_tx, solana_tx, stage, attestation_id`) — verify no PII
   leak; the attestation_id is the user's own, not a cross-tenant probe
   surface. `InvalidParams.data.received` echoes input verbatim — verify
   we don't accidentally echo something like an API key passed in the
   wrong field.

8. **Metric cardinality.** Prometheus counters carry only `stage`
   label, not `owner_pubkey` or `api_key_hash` (verify in metric
   registration).

9. **Storage migration safety.** Backfill heuristic
   `solana_tx LIKE 'local:_%'` is collision-safe (base58 excludes `l`
   and `:` — verify Rust impl matches the spec); migration is
   idempotent.

10. **Compatibility surface.** Legacy `mode`-absent path produces the
    same wire bytes as today (golden fixture in T2). Verify the resolver
    cannot inadvertently change the resolved value for the legacy path
    under any reachable Config combination.
