# Task 9: Pre-deploy QA (Final Wave)

## Description

Acceptance testing before merge. Run the full test suite + lint/format
gates and verify every user-spec invariant and tech-spec acceptance
criterion is exercised by a test (using the traceability matrices from
T8). No live-environment step in this feature — deploy and post-deploy
travel with the next general MCP-server release.

## What to do

1. **Lint + format gates** — must be green:
   ```
   cargo fmt --all -- --check
   cargo clippy --workspace --all-targets -- -D warnings
   ```

2. **Full test suite**:
   ```
   cargo test --workspace --no-fail-fast
   ```
   No flakes — re-run twice if any new test in `mcp/tests/modes_per_request.rs`,
   `delivery_guarantee.rs`, `verify_by_stored_mode.rs` was non-deterministic.

3. **Cross-language interop build gate** (incumbent; must remain green —
   the `cross-lang-build (gate)` CI job is the hard gate; the
   `cross-lang-keychain` job is informational per CLAUDE.md "CI gate
   policy"). This QA task does NOT re-run the cross-lang build locally —
   it READS the latest CI run for the feature branch:
   ```
   RUN_ID=$(gh run list \
     --branch claude/modes-user-choice-Qkk6X \
     --workflow CI --limit 1 --json databaseId --jq '.[0].databaseId')
   gh run view "$RUN_ID" --json jobs \
     --jq '.jobs[] | select(.name=="cross-lang-build (gate)") | .conclusion'
   ```
   Expected: `success`. If CI hasn't run yet, push the latest commit and
   wait; if `cross-lang-build (gate)` is `failure`, this QA fails.

4. **AC traceability** — read T8's `test-audit.md` traceability matrices.
   For each of the 9 tech-spec acceptance criteria and each user-spec
   invariant, confirm:
   - A named test exists,
   - The test ran in step 2 and passed,
   - The matrix lists the test name → AC/invariant mapping.

5. **Audit-wave residuals** — read T6's `code-audit.md` and T7's
   `security-audit.md`. Confirm any `critical` or `major` finding has
   been resolved (either by an interleaved fix commit or by an explicit
   "accepted residual" entry in `decisions.md`). The only pre-known
   accepted residual is R2-F4 (verify response-timing symmetry); any
   other major-or-worse left open BLOCKS this QA.

6. **Smoke probe** against a freshly-built `local`-mode server. The server
   requires an embedder at startup (CLAUDE.md "The server **requires** an
   embedder. By default `EMBED_PROVIDER=fastembed`, which needs
   `--features local-embed`. … Without one, startup aborts.") — use
   fastembed for the smoke:
   ```
   STORAGE_MODE=local PAYMENT_MODE=none EMBED_PROVIDER=fastembed \
     cargo run -p mnemonic-mcp --release --features local-embed -- \
     --transport http --port 3000 &
   PID=$!
   # First boot downloads ~22MB ONNX model — allow generous warm-up.
   for i in {1..30}; do
     sleep 1
     curl -s localhost:3000/health >/dev/null 2>&1 && break
   done
   curl -s -X POST localhost:3000/mcp -H 'content-type: application/json' \
     -d '{"jsonrpc":"2.0","method":"tools/call","id":1,
          "params":{"name":"mnemonic_whoami","arguments":{}}}' \
     | jq '.result.content[0].text | fromjson | .supported_modes'
   # Expected: ["local"]
   kill $PID
   ```

7. **Write final QA report** to
   `work/modes-user-choice/logs/qa/pre-deploy-qa.md` with:
   - Lint/format/test result transcripts (or links/heads).
   - AC traceability table (read-through of T8 matrix).
   - Audit residual disposition.
   - Smoke probe transcript.
   - Verdict: `pass` / `fail`.

8. **If verdict is `pass`** — propose merge of `claude/modes-user-choice-Qkk6X`
   → `main` (do NOT push; surface the proposal). If `fail` — list the
   blocking items.

      (except the documented accepted residual R2-F4).

      server.

      `work/modes-user-choice/logs/qa/pre-deploy-qa.md` with verdict
      = `pass`.
