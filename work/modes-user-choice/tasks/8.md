# Task 8: Test audit (Audit Wave)

## Description

Test quality + coverage audit across all suites added in T1–T4 and the
compat-regression block. Read-only — write the report only. If issues are
found, the feature-execution lead spawns a fixer agent and this auditor
becomes the reviewer.

## What to do

Audit dimensions (project's standard `test-master` skill):

1. **Coverage against user-spec invariants.** Each invariant in
   `user-spec.md` (free-local-always, paid-participate-always, per-request
   granularity, "delivered = anchored AND verified by recall",
   discoverability via `whoami`, typed `UnsupportedMode` error,
   compatibility with shipped extension, mixed-mode coexistence, tenant
   isolation) maps to at least one test. Build the traceability matrix.

2. **Coverage against tech-spec acceptance criteria** (the 9 AC in
   §"Acceptance Criteria"). Same matrix: AC → test(s).

3. **Test-pyramid balance.** Pure-function units
   (`resolve_write_mode`, `paywall_gate`, `WriteMode::from_str_strict`,
   `migrate_write_mode_column`) tested at the unit level. Integration
   tests in `mcp/tests/` exercise the dispatcher end-to-end where the
   contract is HTTP-shaped. No accidental over-mocking that would mask
   integration drift.

4. **Compat regression strength.** The golden fixture for the
   `mode`-absent response shape exists, is checked into the repo
   (`mcp/tests/fixtures/modes/legacy_sign_response.json`), and
   normalisation is correct (volatile fields stripped, structural fields
   preserved).

5. **Refund-release assertion.** Delivery-failure tests assert the
   caller's balance returns to pre-call value (not merely the absence of
   an `attestation_costs` row).

6. **x402 nonce path.** Has a sibling case asserting the x402 nonce is
   NOT consumed on delivery failure.

7. **Quota guard test.** Asserts zero Arweave/Solana calls occur in the
   short-circuited request (via absence of httpmock invocations), not
   merely the response code.

8. **Tenant-isolation test.** Asserts the "wrong tenant" response is
   byte-identical to the "row not found" response — no leaked fields, no
   response-timing-distinguishable behaviour.

9. **Migration tests.** Fresh-schema, legacy-rows mixed fixture
   (`local:abc`, `local:` exact, real signature), idempotency. Strict
   heuristic `LIKE 'local:_%'` is exercised by the mixed fixture.

10. **Flakiness / determinism.** All new tests are deterministic? No
    `tokio::time::sleep` with real wall-clock without `tokio::time::pause`
    in tests? `arlocal` + `solana-test-validator` startup well-encapsulated?

11. **Test naming.** Each test name reads as a one-line spec of the
    behaviour under test (no `test_foo_1`, `test_bar_works`).
