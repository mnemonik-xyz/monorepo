# Task 4: `verify` routes by stored `write_mode` + tenant isolation on `find_by_tx`

## Description

Replace the env-var-based branch in `mcp/src/tools.rs::verify` with a SQLite
lookup of the row's stored `write_mode`. Surface `write_mode` in `recall`
results. Close a pre-existing tenant-isolation gap: `find_by_tx` (and any
related lookup used by routing) must filter by the caller's `owner_pubkey`,
since the new feature deliberately cohabits `local` and `participate` rows
from many tenants in one DB.

## What to do

1. **`core/src/storage/sqlite.rs::find_by_tx` (and any sibling lookup used by
   `verify` routing):**
   - Add an `owner_pubkey: &str` parameter; extend the SELECT predicate with
     `AND owner_pubkey = ?`.
   - Treat a row that exists but belongs to a different tenant as "not found"
     — return `Ok(None)` from the storage layer; do NOT leak the row's
     existence via timing, error shape, or returned fields.
   - Update the `AttestationStore` trait signature accordingly. Bump internal
     test fixtures.

2. **`SqliteStore` — also add `find_write_mode_by_tx(&self, tx: &str,
   owner_pubkey: &str) -> Result<Option<WriteMode>>`** (or extend the
   existing find to also return `write_mode`). Used by `verify` routing
   without re-loading the full row.

3. **`mcp/src/tools.rs::verify`:**
   - Remove the env-var routing branch. Look up `write_mode` (and any other
     row state needed) scoped to `owner_pubkey` (resolved from the JWT `sub`
     claim like in `sign_memory`).
   - If no row found → return the existing "not found" error shape — no
     leakage of whether the row exists for a different tenant.
   - `WriteMode::Local` → call `verify_local(...)`.
   - `WriteMode::Participate` → call `verify_cose(...)` (or
     `verify_legacy_json` fallback as today).
   - Keep the `storage_mode: &str` parameter in the function signature for
     compatibility with existing callers; it is no longer consulted for
     routing. Add a `#[deprecated]` doc comment noting it is ignored.

4. **`mcp/src/tools.rs::recall`:**
   - Extend the per-row result envelope with `"write_mode": "local" |
     "participate"` so clients can render mixed-mode lists with provenance
     visible.
   - No other behaviour change — `recall` already spans both modes by virtue
     of cohabiting rows in one DB.

5. **Integration tests** in `mcp/tests/verify_by_stored_mode.rs` (new file):
   - `verify_routes_local_for_local_row`: seed a row with
     `write_mode='local'`; `verify` returns the local-shape envelope
     regardless of `STORAGE_MODE` env (try both `local` and `full` env
     values).
   - `verify_routes_participate_for_participate_row`: seed a row with
     `write_mode='participate'` and real anchor (using the harness from T3);
     `verify` returns the participate envelope regardless of env.
   - **`tenant_isolation`** (critical): caller A authenticates and writes a
     `participate` row; caller B authenticates and calls
     `verify(solana_tx_from_A)` — must return "not found", **no
     `content_hash`, `signer_pubkey`, or content preview leaked**. Repeat
     for a `local`-tagged row.
   - `recall_surfaces_write_mode`: seed mixed-mode rows for one owner; assert
     each row in the result carries its stored `write_mode` tag.

## Acceptance Criteria

- [ ] `find_by_tx` scoped by `owner_pubkey` — wrong-tenant lookup returns
      `Ok(None)`; right-tenant lookup unchanged.
- [ ] `verify` routes by stored `write_mode`, not by env var; both `local`
      and `participate` rows behave correctly under either `STORAGE_MODE` env
      value.
- [ ] `recall` result includes per-row `write_mode`.
- [ ] Tenant isolation: caller B never observes caller A's row existence,
      hash, signer, or content via `verify` (asserted by full response
      equality with the "not found" shape and absence of identifying fields
      in error data).
- [ ] Existing `cargo test -p mnemonic-mcp verify_` and `recall_` suites
      remain green.
- [ ] `cargo clippy --workspace --all-targets -- -D warnings` clean.

## TDD Anchor

First test (in `mcp/tests/verify_by_stored_mode.rs`):

```rust
#[tokio::test]
async fn verify_does_not_leak_other_tenants_row() {
    let server = TestServer::builder().storage_mode("local").build().await;
    let token_a = server.mint_test_jwt(USER_A_PUBKEY);
    let token_b = server.mint_test_jwt(USER_B_PUBKEY);

    // Caller A writes a row.
    let resp = server.with_token(&token_a)
        .call_tool("mnemonic_sign_memory",
            json!({ "content": "secret", "mode": "local" })).await;
    let a_sol_tx = extract_solana_tx(&resp);

    // Caller B asks to verify A's tx.
    let resp_b = server.with_token(&token_b)
        .call_tool("mnemonic_verify",
            json!({ "solana_tx": a_sol_tx })).await;

    // Must look identical to a genuine miss: no content_hash, no signer,
    // no preview.
    let result = resp_b.result.as_object().unwrap();
    assert_eq!(result["status"], "not_found");
    for leaky in ["content_hash", "signer_pubkey", "content", "preview"] {
        assert!(result.get(leaky).is_none(),
            "leaked field: {leaky}");
    }
}
```
