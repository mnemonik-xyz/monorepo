# Task 4: `sign_memory` accepts a per-call `mode`

## Description

The core inversion: the caller chooses `local` vs `participate` per write. Resolve
the requested mode against the operator envelope; reject unsupported requests
loudly (no silent downgrade).

## What to do

1. **Tool input:** `mnemonic_sign_memory` gains optional `"mode": "local" |
   "participate"`. Parse via `WriteMode::from_str`; absent ⇒ `Config.default_write_mode`.
2. **Resolution rule** (in `mcp/src/mcp.rs` dispatch or a small helper):
   - `Local` → always allowed.
   - `Participate` on a server with `allow_participate == false` → return a typed
     JSON-RPC error: *"this server only supports local mode; participate requires
     an anchoring operator"*. **Do not** silently store locally — the user asked
     for a delivery guarantee.
3. **Thread `WriteMode`** (not `&str`) into `tools::sign_memory` / `sign_memory_inline`,
   replacing the `storage_mode == "local"` string check at `tools.rs:332` with
   `matches!(mode, WriteMode::Local)`. The Arweave+Solana branch runs for `Participate`.
4. Update the tool's input schema/description in the tool registration.

## Acceptance Criteria

- [ ] `sign_memory` honors an explicit `mode`; absent ⇒ operator default.
- [ ] `participate` on a local-only server ⇒ typed error, nothing written, no charge.
- [ ] `local` write path is byte-identical to today's `storage_mode == "local"` behavior.
- [ ] `WriteMode` is threaded as a typed value, not a string, through `tools.rs`.
- [ ] `cargo test -p mnemonic-mcp` passes; new test for the unsupported-mode error.
