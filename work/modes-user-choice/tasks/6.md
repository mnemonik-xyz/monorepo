# Task 6: S1 storage migration — tag rows with `write_mode` + receipt columns

## Description

Implements decision S1: one DB, rows tagged by mode, plus the delivery-receipt
fields. Idempotent migration; legacy rows = `local`.

## What to do

1. **Edit `core/src/storage/sqlite.rs`:**
   - Add columns to the attestations table (idempotent — guard with
     `PRAGMA table_info` or `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` pattern
     already used in the codebase):
     - `write_mode TEXT NOT NULL DEFAULT 'local'`
     - `recall_verified_at TEXT` (nullable — set only when delivery confirmed)
     (the `arweave_tx` / `solana_tx` columns already exist and carry the anchor.)
   - Legacy rows (pre-migration) inherit `write_mode = 'local'` via the DEFAULT.
2. **Extend `save_attestation`** to accept + persist `write_mode` (and leave
   `recall_verified_at` NULL at insert time — Task 7 sets it on confirmation).
3. Keep recall mode-agnostic: cosine search spans all rows regardless of
   `write_mode` (this is the S1 "local + shared coexist, recall sees both" goal).

## Acceptance Criteria

- [ ] Migration is idempotent — running twice on an existing DB is a no-op, no error.
- [ ] A legacy DB (no `write_mode` column) migrates cleanly; existing rows read back as `local`.
- [ ] `save_attestation` persists `write_mode`; `recall` returns both `local` and `participate` rows.
- [ ] `cargo test -p mnemonic-core` passes; add a migration-idempotency test + a mixed-mode recall test.
