# Task 6: Code audit (Audit Wave)

## Description

Holistic code-quality audit across the entire feature surface produced by
T1–T5. Read-only — write the report only; no code changes here. If issues are
found, the feature-execution lead spawns a fixer agent and this auditor
becomes the reviewer for the fix.

## What to do

Audit dimensions (project's standard `code-reviewing` skill):

1. **Structure & naming.** `WriteMode` enum, `resolve_write_mode` resolver,
   error helpers, `RefundsBySubject` — names match the project's idiom?
   Module placement consistent with `architecture.md`?

2. **Patterns & conventions.** `Embedder`-trait-style indirection respected?
   `AttestationStore` trait extensions clean? No concrete provider direct
   calls from business logic? `#[cfg(not(target_arch = "wasm32"))]`
   gating intact for any native-only paths touched?

3. **Error handling.** `anyhow::Result` used consistently in `core/`?
   JSON-RPC error helpers (`unsupported_mode`, `invalid_params`,
   `delivery_not_confirmed`, `delivery_quota_exceeded`) factored into a
   single place, not duplicated across handlers? No `unwrap()` outside
   tests?

4. **Lock discipline.** `SqliteStore` mutex never held across `.await`
   (Decision 8). DashMap shard guards (`RefundsBySubject`) never held
   across `.await` (Decision 8 extended). Grep for `lock()` followed by
   `.await` in the same scope.

5. **Concurrency / shared state.** Single owner of `RefundsBySubject`
   counter? Background eviction task started once in `McpState::new` and
   not duplicated? `Arc`/`DashMap` cardinality bounded?

6. **Compatibility surface.** `mode`-absent path remains byte-identical
   to legacy (regression risk vis-à-vis shipped chrome-extension).
   Golden fixture present? Deferred-signing path
   (`mcp/tests/deferred_sign_flow.rs`) assertions unchanged?

7. **Migration safety.** `migrate_write_mode_column` idempotent? Backfill
   heuristic `LIKE 'local:_%'` collision-safe and tested?
   `migrate_payment_events_*` (if added in T3) idempotent?

8. **PII / data-at-rest.** `payment_events { event_kind='refund_failed' }`
   row carries ONLY the pinned allow-list
   (`{api_key_hash, attestation_id, reason, occurred_at}`) — no raw
   `api_key`, no `content_preview`, no `cose_bytes`. Prometheus labels do
   not carry `owner_pubkey` or `api_key_hash` (cardinality / log-scrub).

9. **Resource cleanup.** Background eviction task stops on graceful
   shutdown? `tokio::select!` patterns correct?

10. **Public API surface.** Any newly `pub`-exposed symbols intentional and
    documented? `WriteMode` is `pub` (intentional); helper internals
    `pub(crate)` only?
