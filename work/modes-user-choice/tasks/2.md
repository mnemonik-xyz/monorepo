# Task 2: Config policy envelope (operator advertises modes, not picks one)

## Description

Reframe `Config` so the operator declares *which modes it can serve*, not a
single fixed mode. No per-call logic yet — just the envelope fields + derivation.
Existing `STORAGE_MODE`/`PAYMENT_MODE` env vars stay readable for back-compat.

## What to do

1. **Edit `mcp/src/config.rs`:**
   - Keep `storage_mode` / `payment_mode` fields (still read from env) — they
     become the *operator default*, not a global lock.
   - Add `pub allow_participate: bool`. Derive in `from_env`: `true` iff the
     server is capable of anchoring — i.e. `storage_mode == "full"` (the existing
     signal that Arweave+Solana are wired and a funded keypair is expected).
     A pure-local operator (`STORAGE_MODE=local`) ⇒ `false`.
   - Add `pub default_write_mode: String` = `storage_mode` mapped to a `WriteMode`
     string (`"full"` → `"participate"`, else `"local"`), so `whoami` (Task 3)
     can advertise a default consistent with the operator's capability.
2. **Do not** change any downstream consumer yet (mcp.rs/tools.rs still read the
   old fields). This task is additive only.

## Acceptance Criteria

- [ ] `Config` has `allow_participate: bool` + `default_write_mode: String`, populated in `from_env`.
- [ ] `STORAGE_MODE=full` ⇒ `allow_participate == true`, `default_write_mode == "participate"`.
- [ ] `STORAGE_MODE=local` (default) ⇒ `allow_participate == false`, `default_write_mode == "local"`.
- [ ] `mcp/src/test_support.rs` + `chat.rs` Config literals updated to include the new fields (local-only defaults).
- [ ] `cargo build -p mnemonic-mcp` + `cargo test -p mnemonic-mcp` pass.
