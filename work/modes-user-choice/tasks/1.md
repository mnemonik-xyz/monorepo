# Task 1: `WriteMode` enum + `write_mode` column migration + `save_attestation` signature

## Description

Introduce the typed per-write mode (`WriteMode { Local, Participate }`) as a pure
`core/` type, persist it on every attestation row via a new `write_mode TEXT NOT
NULL` column with an idempotent migration helper, and propagate the
`WriteMode` parameter through the `AttestationStore` trait and the `SqliteStore`
impl. Foundation for everything that follows; no behavior change to MCP tools
in this task — the parameter is plumbed but every existing call site passes the
value implied by today's `STORAGE_MODE` so production behavior is identical.

## What to do

1. **`core/src/storage/mode.rs` (new):**
   - `pub enum WriteMode { Local, Participate }` with derives
     `#[derive(Clone, Copy, Debug, PartialEq, Eq, Serialize, Deserialize)]`.
   - `#[serde(rename_all = "lowercase")]` so JSON round-trips
     `"local"` / `"participate"`.
   - `impl WriteMode`: `as_str() -> &'static str`; `from_str_strict(s: &str) ->
     Option<Self>` returning `Some` ONLY for exact lowercase `"local"` /
     `"participate"` (case-insensitive variants, `null`, empty, whitespace
     return `None` — the API resolver in T2 maps `None` to its typed error).
   - Implement `rusqlite::ToSql` / `FromSql` via the `&str` adapter.
   - `Default` = `Local`.

2. **`core/src/storage/mod.rs`:** `pub mod mode;` and `pub use mode::WriteMode;`
   so `mnemonic_core::storage::WriteMode` resolves.

3. **`core/src/storage/traits.rs`:** add a `write_mode: WriteMode` parameter to
   `AttestationStore::save_attestation` (last parameter, before
   `embedding`).

4. **`core/src/storage/sqlite.rs`:**
   - **Schema:** the inline `CREATE TABLE IF NOT EXISTS attestations` keeps its
     current shape (the column is added by the migration helper below for both
     fresh and legacy DBs — same pattern as `migrate_owner_pubkey_columns`).
   - **`migrate_write_mode_column` (new)** — idempotent helper sibling of
     `migrate_owner_pubkey_columns` and `migrate_correlation_id_column`:
     - check `pragma_table_info('attestations')`; if `write_mode` absent,
       `ALTER TABLE attestations ADD COLUMN write_mode TEXT NOT NULL DEFAULT
       'participate'`.
     - Backfill: `UPDATE attestations SET write_mode = 'local' WHERE solana_tx
       LIKE 'local:_%'` (strict — at least one char after the colon; base58
       excludes lowercase `l` and `:`, so this is collision-safe with real
       signatures).
     - `CREATE INDEX IF NOT EXISTS idx_attestations_write_mode ON
       attestations(owner_pubkey, write_mode)`.
   - **Wire migration:** call `migrate_write_mode_column(&conn)?` from
     **both** `SqliteStore::open` AND `SqliteStore::in_memory` alongside the
     existing `migrate_owner_pubkey_columns` / `migrate_correlation_id_column`
     calls. (There is no `SqliteStore::new` — those two are the constructors.)
   - **`save_attestation` impl:** accept the new `write_mode` parameter; extend
     the INSERT column list to `(... , write_mode)` and the VALUES tuple
     accordingly. Bind with `write_mode.as_str()`.
   - **All internal call sites** in `core/src/storage/sqlite.rs` test helpers and
     fixtures get a default of `WriteMode::Participate` (matching their previous
     "real anchor" semantics) so test behavior is preserved.

5. **`core/src/lib.rs`:** no change needed — `storage` is already `pub mod`.

6. **Unit tests** (inside `core/src/storage/mode.rs` + `sqlite.rs`):
   - `from_str_strict` accepts `"local"`/`"participate"`, rejects `"Local"`,
     `"PARTICIPATE"`, `""`, `" "`, `"unknown"`.
   - serde JSON round-trip of both variants.
   - rusqlite ToSql/FromSql round-trip.
   - `migrate_write_mode_column` test cases:
     - **fresh DB:** column added, default `'participate'`, index present.
     - **legacy DB seeded** with a mix of `solana_tx` values: `local:abc`,
       `local:` (exact, no suffix), and a real base58 signature — assert
       `local:abc` row gets `'local'`, `local:` exact stays `'participate'`,
       real signature stays `'participate'`.
     - **idempotency:** run migration twice on the same DB — no error, no
       duplicate rows, identical final state.

## TDD Anchor

First test to write (table-driven, in `core/src/storage/mode.rs`):

```rust
#[test]
fn write_mode_from_str_strict_accepts_only_canonical_lowercase() {
    assert_eq!(WriteMode::from_str_strict("local"),       Some(WriteMode::Local));
    assert_eq!(WriteMode::from_str_strict("participate"), Some(WriteMode::Participate));
    for bad in ["Local", "PARTICIPATE", "", " ", "unknown", "local "] {
        assert_eq!(WriteMode::from_str_strict(bad), None, "{bad} should not parse");
    }
}
```
