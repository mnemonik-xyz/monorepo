# Task 15: Post-deploy verification

## Required Skills

Before starting, load: `/skill:post-deploy-qa`

## Description

Live-environment verification after Task 14's deploy. On a fresh machine (or container) install the published package and run the full demo flow including bootstrap-ticket. Verify cross-tool semantics: same identity logged into Claude.ai sees the CLI-signed attestation. Verify negative paths: arbitrary `redirect_uri` → 400 (regression of the allowlist), double-redeem of bootstrap ticket → 410, `mnemonic verify <stranger-id>` → not_found.

If any check fails → escalate; do NOT mark feature complete.

## What to do

1. **Fresh-machine install.** Use a container or fresh user to avoid stale state:
   - `docker run --rm -it node:20 bash`.
   - Inside: `npm install -g @mnemonik-xyz/cli`. Verify `mnemonic --version` prints `0.1.0`.

2. **Bootstrap-ticket flow:**
   - On a desktop browser: open `https://mnemonik.xyz/install`. Generate webapp identity if absent. Click "Send to CLI". Copy the ticket command.
   - Inside container: paste the ticket command (`mnemonic identity import --ticket <uuid>`). Verify `~/.mnemonic/identity.json` appears with mode 0600 and same pubkey as webapp localStorage.

3. **Login + sign + recall + verify:**
   - `mnemonic login` (interactive — opens browser; for headless container, use `--token <jwt>` after issuing one via webapp).
   - `mnemonic sign "Hello from CLI test on $(date)"` → returns attestation_id, exit 0.
   - `mnemonic recall "Hello from CLI"` → finds the just-signed entry; signature verifies.
   - `mnemonic verify <attestation_id>` → exit 0.

4. **Cross-tool verification:**
   - In Claude.ai (or another configured client) with the same identity: ask "recall what I signed via terminal today". Claude should return the CLI-signed attestation.
   - In Cursor: same.

5. **Negative paths (security regression):**
   - `curl -s -X GET 'https://mc.mnemonik.xyz/oauth/authorize?client_id=mnemonic-cli&redirect_uri=https://evil.com&response_type=code&...' -i` returns HTTP 400 (allowlist violation).
   - Re-redeem the same ticket from step 2: `curl -s 'https://mc.mnemonik.xyz/api/cli-bootstrap/redeem/<same-uuid>'` returns HTTP 410 Gone.
   - `mnemonic verify <random-uuid-not-yours>` → exit 1 (not_found, not exit 3 — would-be tampered means the row exists; not_found means it doesn't).

6. **Tenant isolation regression:**
   - Issue a bootstrap ticket with one webapp identity. Log into a separate webapp identity. Try to redeem the first identity's ticket from the second account's session — should NOT work (the redeem endpoint has no auth, so the UUID is the cap; this is by design — verify the cap is unguessable enough that random UUIDs don't collide).

7. **Bundle install on Bun and Deno:**
   - `bun install -g @mnemonik-xyz/cli` and run smoke commands.
   - Deno: `deno install -A npm:@mnemonik-xyz/cli` (per Deno's npm interop) — confirm CLI runs.

8. **Write report** at `work/mnemonic-cli/logs/working/post-deploy.json`:
   ```json
   {
     "status": "pass" | "fail",
     "fresh_install": "pass",
     "bootstrap_ticket_flow": "pass",
     "demo_flow": "pass",
     "cross_tool_recall_claude": "pass",
     "cross_tool_recall_cursor": "pass",
     "allowlist_regression": "pass",
     "ticket_replay_410": "pass",
     "verify_not_found": "pass",
     "bundle_install_bun": "pass",
     "bundle_install_deno": "pass"
   }
   ```

9. **If status=pass** → finalize: append decisions.md entry + suggest user runs `/done mnemonic-cli`. **If status=fail** → escalate to feature-execution lead.
