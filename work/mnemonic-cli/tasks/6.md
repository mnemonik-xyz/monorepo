# Task 6: Server-side — OAuth redirect-URI allowlist + bootstrap-ticket endpoints + PKCE state binding

## Required Skills

Before starting, load: `/skill:code-writing`

## Description

Two server changes in one task because they cluster: (1) `mcp/src/oauth.rs` — add a redirect-URI allowlist (does not exist today; current code accepts any URI — security latent finding). PKCE state is also bound to verifier + redirect_uri at authorize-time, validated at token-exchange-time per RFC 7636 §4.4. (2) `mcp/src/api.rs` — add `POST /api/cli-bootstrap/issue` (Bearer JWT auth; payload: keypair_json; returns: ticket_id) and `GET /api/cli-bootstrap/redeem/:ticket` (no auth — the UUID is the capability, identical pattern to existing `correlation_id`-authed endpoints). New `BootstrapTickets` LRU+TTL store modeled on existing `mcp/src/pending.rs::PendingBundles`.

After this task: the OAuth flow is hardened (no more arbitrary `redirect_uri`), CLI's loopback callback redirect is allowlisted, and webapp can issue one-time bootstrap tickets that the CLI can redeem to align identities.

## What to do

1. **`mcp/src/oauth.rs` — redirect-URI allowlist.**
   - Add a `fn allowed_redirect(uri: &str, client_id: &str) -> bool`. Allowed entries:
     - Exact match: `https://mnemonik.xyz/oauth/consent`.
     - Exact-prefix match: `cursor://anysphere.cursor-deeplink/`, `vscode:mcp/`, `https://claude.ai/api/`.
     - Regex (gated to `client_id == "mnemonic-cli"`): `^http://127\.0\.0\.1:\d+/callback$`, `^http://\[::1\]:\d+/callback$`.
   - Call `allowed_redirect` in `authorize_handler` before storing PKCE state. Reject with 400 if not allowed.
   - Bind `redirect_uri` into the PKCE-state map alongside `verifier` and `state`. Validate on token-exchange.
   - Unit tests: positive (each allowlisted scheme), negative (`https://evil.com`, `http://0.0.0.0:1234`, loopback URI without `/callback` suffix).

2. **`mcp/src/api.rs` — bootstrap-ticket endpoints.**
   - New struct `BootstrapTicket { ticket_id: Uuid, keypair_json: String, jwt_sub: String, expires_at: i64 }`.
   - New struct `BootstrapTickets { entries: Mutex<LruCache<Uuid, BootstrapTicket>>, per_user_count: Mutex<HashMap<String, usize>>, ttl_seconds: u64 }` with methods `insert(jwt_sub, keypair_json) -> Uuid`, `consume(ticket_id) -> Option<BootstrapTicket>` (atomic remove-and-return). Limits: max 100 total entries, max 3 active per `jwt_sub`, TTL 600 seconds.
   - Add to `McpState` as `bootstrap_tickets: Arc<BootstrapTickets>`.
   - Handler `POST /api/cli-bootstrap/issue`: extract Bearer JWT via existing middleware, decode `sub`, parse JSON body for `keypair_json`, call `tickets.insert(sub, keypair_json)`, return `{ticket_id: <uuid>}`. 401 if no JWT, 429 if per-user limit hit, 503 if total limit hit.
   - Handler `GET /api/cli-bootstrap/redeem/:ticket`: parse `:ticket` UUID, call `tickets.consume(ticket_id)`. 404 if not found / already consumed / expired. 200 with `{secret: number[64], pubkey_base58: string}` on success.
   - Add routes to `mcp/src/main.rs` next to existing `/api/sign-callback` route.
   - Add the bootstrap allowlist entries (`POST /api/cli-bootstrap/issue` requires JWT; `GET /api/cli-bootstrap/redeem/*` does NOT — capability auth) to the `bearer_auth_layer` allowlist in `oauth.rs`.

3. **Unit tests** in `mcp/src/oauth.rs::tests` and `mcp/src/api.rs::tests`:
   - `oauth_allowed_redirect_positive_negative` (both arms).
   - `oauth_state_binding_validates_redirect_uri_too` — token-exchange with mismatched redirect_uri rejected.
   - `bootstrap_tickets_atomic_consume` — concurrent two-thread consume; only one returns Some.
   - `bootstrap_tickets_per_user_cap` — issue 4 tickets for one user, 4th returns 429.
   - `bootstrap_tickets_ttl_expiry` — issue, advance time past TTL, consume returns None.
   - `bootstrap_redeem_no_auth_required` — call `/api/cli-bootstrap/redeem/:ticket` with no `Authorization` header; succeeds if ticket is fresh.

4. **Smoke verification.** `cargo test -p mnemonic-mcp -- oauth_ bootstrap_` green. Then run server locally, `curl https://localhost/oauth/authorize?client_id=mnemonic-cli&redirect_uri=https://evil.com&...` returns 400.
