# Task 3: SDK OAuth — `buildAuthorizeUrl`, `exchangeCodeForToken`, headless mode

## Required Skills

Before starting, load: `/skill:code-writing`

## Description

Implement OAuth 2.1 + PKCE primitives in `packages/sdk/src/oauth.ts`. The SDK exposes them as runtime-agnostic functions (Web APIs only — no `node:http`, no `child_process`); the CLI's `commands/login.ts` (Task 5) wraps them with the loopback HTTP server. A future Chrome extension will wrap them with `chrome.identity.launchWebAuthFlow`.

Key correctness requirement (Decision 5): the PKCE state value MUST be stored together with the verifier and the redirect_uri. At code-exchange time, the SDK validates that the state returned by the callback matches the originally-issued tuple; mismatch terminates the flow before any HTTP exchange (RFC 7636 §4.4 + RFC 8252 §7).

After this task: SDK exports `buildAuthorizeUrl({baseUrl, clientId, redirectUri, scope})` returning `{url, state, verifier, sessionId}` and `exchangeCodeForToken({baseUrl, code, verifier, redirectUri, sessionId})` returning `{jwt, expiresAt}`. Headless mode is implicit — `MnemonicClient({jwt})` constructor accepts a pre-issued JWT; OAuth code is simply not invoked.

## What to do

1. **`packages/sdk/src/oauth.ts`** — pure functions:
   - `generatePkceVerifier()`: 32 bytes from `crypto.getRandomValues`, base64url-encoded.
   - `pkceChallenge(verifier)`: `crypto.subtle.digest('SHA-256', utf8(verifier))`, base64url-encoded.
   - `randomState()`: 32 bytes from `crypto.getRandomValues`, base64url-encoded.
   - `buildAuthorizeUrl({baseUrl, clientId, redirectUri, scope='mcp'})`: returns `{url: URL string, state, verifier, sessionId}` where `sessionId` is a UUID for caller-side bookkeeping. Stores `{verifier, state, redirectUri, sessionId}` in an in-memory `Map<sessionId, ...>` named `pendingAuthSessions` exported as a module-level value (caller manages lifecycle by passing `sessionId` back to `exchangeCodeForToken`).
   - `exchangeCodeForToken({baseUrl, code, state, redirectUri, sessionId})`: looks up the session, validates `state` matches stored, validates `redirectUri` matches stored, POSTs `/oauth/token` with `{grant_type: 'authorization_code', code, code_verifier: stored_verifier, redirect_uri: stored_redirect_uri, client_id: 'mnemonic-cli'}` as JSON. Returns `{jwt, expiresAt: ISO-8601}`. Clears the session on success or on any validation failure. Throws `AuthError` (from `errors.ts`) on mismatch.
   - `parseJwtPayload(jwt)`: parses header + payload (no signature verification — that's server's job). Returns `{sub, exp, iat}`. Used by CLI's `--token <jwt>` headless validation in Task 5.

2. **No `node:http` server here.** SDK is runtime-agnostic. The loopback callback handling is CLI's responsibility (Task 5).

3. **Unit tests** in `packages/sdk/test/oauth.test.ts`. Use `vitest` + mocked `fetch`. Cover:
   - `buildAuthorizeUrl` produces a valid URL with `code_challenge`, `code_challenge_method=S256`, `state`, `client_id=mnemonic-cli`, `response_type=code`.
   - `pkceChallenge(verifier)` matches a known-good fixture (compute one in Python or Rust and embed for cross-impl validation).
   - `exchangeCodeForToken` with mismatched state throws `AuthError` and does NOT issue HTTP request.
   - `exchangeCodeForToken` happy path POSTs JSON body with all required fields.
   - `parseJwtPayload` correctly extracts `sub` and `exp`; returns null/throws for expired or malformed tokens.

4. **Update `packages/sdk/src/index.ts`** to re-export OAuth surface: `buildAuthorizeUrl`, `exchangeCodeForToken`, `parseJwtPayload`.
