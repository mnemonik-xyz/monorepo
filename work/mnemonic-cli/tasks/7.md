# Task 7: Webapp `IdentityPanel` "Send to CLI" button

## Required Skills

Before starting, load: `/skill:code-writing`

## Description

Add a "Send to CLI" button to `webapp/src/components/IdentityPanel.tsx`. On click: webapp POSTs the localStorage keypair JSON to the new `/api/cli-bootstrap/issue` endpoint (Task 6) with the existing webapp JWT in `Authorization`. Server returns `{ticket_id}`. UI displays a copyable code block: `mnemonic identity import --ticket <uuid>`. Per Decision 7 of tech-spec, this is the primary bootstrap path; the file-based fallback is via the existing `IdentityPanel` keypair download/upload UI which already exists.

After this task: a webapp-using user can click "Send to CLI" and receive a one-line command to paste in their terminal that imports the same keypair. Closes the CLI ↔ webapp identity loop without exposing a phishing surface.

## What to do

1. **Add a "Send to CLI" button** to `webapp/src/components/IdentityPanel.tsx`. Place it under the existing "Download keypair" / "Import keypair" buttons. `data-testid="identity-send-to-cli"`.

2. **Click handler:**
   - Read `localStorage["mnemonic.identity"]` (existing convention).
   - Read JWT from existing webapp's auth state (already managed for the OAuth consent flow — likely in a context or hook).
   - `fetch('/api/cli-bootstrap/issue', { method: 'POST', headers: { 'Authorization': 'Bearer ${jwt}', 'Content-Type': 'application/json' }, body: JSON.stringify({ keypair_json: <localStorage value> }) })`.
   - On 200: parse `{ticket_id}`, transition UI to display state.
   - On 429 (per-user cap): show "You have 3 active CLI tickets. Wait or revoke one in `mnemonic identity list`."
   - On 401 (bad/expired JWT): redirect user to `/oauth/consent` to re-auth.
   - On other errors: show "Could not issue ticket: ${error.message}".

3. **Display state:** show a code block with:
   ```
   mnemonic identity import --ticket <uuid>
   ```
   plus a "Copy" button that uses `navigator.clipboard.writeText`. Show a hint: "Run this in your terminal within 10 minutes". Show countdown timer (uses the `expires_at` field if returned, else assumes 10min from issue).

4. **Unit tests** in `webapp/src/components/IdentityPanel.test.tsx`:
   - Mock `fetch` returning `{ticket_id: 'abc-123'}`. Render component, click button, assert ticket displayed in code block; copy button calls `navigator.clipboard.writeText('mnemonic identity import --ticket abc-123')`.
   - Mock `fetch` returning 429; assert error message visible.

5. **E2E test** in `webapp/e2e/cli-bootstrap.spec.ts` (Playwright, against local dev or staging):
   - Navigate to `/install`.
   - Generate a webapp identity (existing flow).
   - Click "Send to CLI" button.
   - Assert a code block with `mnemonic identity import --ticket <uuid>` appears.
   - Optionally: programmatically `fetch('/api/cli-bootstrap/redeem/:ticket')` against the server and assert response shape; this validates the server side too. Skip if running fully offline.

6. **Smoke.** `cd webapp && npx vitest run src/components/IdentityPanel.test.tsx` passes. `cd webapp && npx playwright test e2e/cli-bootstrap.spec.ts` passes against staging.
