# Task 1: npm workspace skeleton + wasm-pack target investigation

## Required Skills

Before starting, load: `/skill:code-writing`

## Description

Set up the npm-workspace foundation that hosts `@mnemonik-xyz/sdk` and `@mnemonik-xyz/cli`, and **empirically determine** which `wasm-pack` target produces an artifact that loads under all four target runtimes (Node 20, Node 22, Bun, Deno). The wrong choice here cascades into Wave 2 work — Decision 3 of `tech-spec.md` calls this out as the gating decision for SDK consumability.

After this task: repo root `package.json` is an npm workspace; `packages/sdk/` and `packages/cli/` are skeleton packages with empty `src/index.ts`, `tsconfig.json`, `vitest.config.ts`; `webapp/scripts/build-wasm.sh` produces both the existing `core/pkg/` (web target for webapp) and a new artifact at `core/pkg-<chosen-target>/` for SDK consumption; the chosen target is documented in `packages/sdk/README.md` and works on all four runtimes via the smoke test below.

## What to do

1. **Convert repo root to npm workspace.** Edit `/Users/syi/src/sessions/2/package.json` (create if absent — repo is currently Cargo-only at the root). Set `"workspaces": ["packages/*", "webapp"]`. Add a `private: true` flag (root is not published).

2. **Create skeleton packages.** Under `/Users/syi/src/sessions/2/packages/`:
   - `packages/sdk/{package.json, tsconfig.json, vitest.config.ts, README.md, src/index.ts}` — name `@mnemonik-xyz/sdk`, version `0.0.0`, `type: module`, `main: dist/index.js`, `types: dist/index.d.ts`, scripts: `build`, `test`. Empty `src/index.ts`.
   - `packages/cli/{package.json, tsconfig.json, vitest.config.ts, README.md, bin/mnemonic.ts, src/index.ts}` — name `@mnemonik-xyz/cli`, depends on `@mnemonik-xyz/sdk` workspace-internal, `bin: { "mnemonic": "./dist/bin/mnemonic.js" }`. Empty.

3. **wasm-pack target investigation.** Run `wasm-pack build core --target <T> --features wasm --out-dir core/pkg-<T>` for `T ∈ {web, nodejs, bundler}`. For each output, write a one-liner smoke script (`packages/sdk/scripts/smoke-<T>.mjs`) that calls `import { sign_cose_payload } from '../../core/pkg-<T>/mnemonic_core.js'` and prints `typeof sign_cose_payload`. Run each smoke under `node`, `bun`, `deno`. Record the matrix in `packages/sdk/README.md`. Pick the target (or pair with `package.json` conditional exports) that loads on all four. **Likely outcome:** `--target web` works for Node 20+ ESM and Bun (both implement `import.meta.url` + native fetch); a parallel `--target nodejs` may be needed if Deno's WASM loader is stricter.

4. **Update `webapp/scripts/build-wasm.sh`** additively to produce both the existing `core/pkg/` (web target — keep as-is for webapp) AND the chosen SDK target output. Add a script `packages/sdk/scripts/build-wasm.sh` that builds the SDK target and is called from SDK's `package.json` `prepublish`.

5. **Document the choice** in `packages/sdk/README.md` "Runtime targets" section: which wasm-pack target was chosen, why (link to smoke matrix), what conditional exports (if any) are configured in `packages/sdk/package.json`.

6. **Smoke-verify locally.** From repo root: `bun install`, then `for r in node bun deno; do $r packages/sdk/scripts/smoke-<chosen-target>.mjs; done` — all three print `function`. (Skip the fourth runtime if not installed; document fallback.)

## TDD Anchor

This task is investigative — no unit tests in this round. The smoke matrix in `packages/sdk/README.md` IS the verification artifact.
