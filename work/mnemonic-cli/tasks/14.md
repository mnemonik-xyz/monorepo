# Task 14: Deploy — npm publish + GitHub release + server config + webapp deploy

## Required Skills

Before starting, load: `/skill:deploy-pipeline`

## Description

Multi-target deployment after pre-deploy QA passes. Three artifacts ship in this task:

1. **npm packages:** `@mnemonik-xyz/sdk@0.1.0` and `@mnemonik-xyz/cli@0.1.0` published with sigstore provenance attestation (`npm publish --provenance`).
2. **Server changes** from Task 6 (`mcp/src/oauth.rs` allowlist + `mcp/src/api.rs` bootstrap endpoints) deployed to the VPS at `mc.mnemonik.xyz`.
3. **Webapp changes** from Task 7 (`IdentityPanel` "Send to CLI" button) deployed via the existing webapp deploy path (npm run build → nginx serves dist/).

Plus update `mnemonik.xyz/install` page (webapp) with a fourth "Install in terminal" card pointing at `npm install -g @mnemonik-xyz/cli`.

After this task: `npm install -g @mnemonik-xyz/cli` works for any user globally; `https://mc.mnemonik.xyz/api/cli-bootstrap/issue` accepts requests; webapp shows the new button. **CLI does not yet have post-deploy verification — that's Task 15.**

## What to do

1. **Tag the release.** From repo root: `git tag v0.1.0-cli && git push origin v0.1.0-cli`. (Distinct from previous tags so pipelines can filter.)

2. **Publish to npm:**
   - `cd packages/sdk && npm publish --access public --provenance` (org `mnemonik-xyz` must have provenance enabled on npmjs.com).
   - `cd packages/cli && npm publish --access public --provenance`.
   - Smoke: `npm view @mnemonik-xyz/cli version` returns `0.1.0`.
   - Smoke: `npm install -g @mnemonik-xyz/cli` on a clean container; `mnemonic --version` prints `0.1.0`.

3. **Deploy server changes** to VPS at `claude@150.251.147.215`:
   - SSH in: `ssh claude@150.251.147.215`.
   - `cd /home/claude/monorepo && git pull origin main` (assumes the merge is on main).
   - `source ~/.cargo/env && cargo build --release -p mnemonic-mcp --features local-embed` (~1 min on the VPS).
   - `sudo systemctl restart mnemonic-mcp` — **explicit user authorization required for restart per harness rules.** Lead requests + waits.
   - Smoke: `curl -s -X POST https://mc.mnemonik.xyz/oauth/authorize -d 'client_id=mnemonic-cli&redirect_uri=https://evil.com&...' -i` returns HTTP 400 with allowlist-violation body.
   - Smoke: `curl -s -X POST https://mc.mnemonik.xyz/api/cli-bootstrap/issue -H 'Authorization: Bearer <test-jwt>' -d '{"keypair_json":"..."}'` returns 200 + ticket_id.

4. **Deploy webapp changes** to VPS:
   - Same SSH session: `cd /home/claude/monorepo/webapp && npm install && npm run build`.
   - Smoke: `curl -s https://mnemonik.xyz/install | grep -q 'install-windsurf'` (regression — windsurf landed earlier; cli would be in the JS bundle, not the HTML).
   - Smoke: `curl -s https://mnemonik.xyz/assets/index-*.js | grep -q 'identity-send-to-cli'` — new button in bundle.

5. **Update `mnemonik.xyz/install` page** with a new "Install in terminal" card. Edit `webapp/src/components/InstallButtons.tsx` adding a fourth button (or a separate "Terminal" section) with copy-to-clipboard for `npm install -g @mnemonik-xyz/cli`. Rebuild + redeploy webapp.

6. **GitHub Release** for `v0.1.0-cli`. `gh release create v0.1.0-cli --title "mnemonic-cli v0.1.0" --notes-from-tag` or paste a curated changelog from this tech-spec's deviations + acceptance criteria.

7. **Smoke aggregate.** All four health checks green:
   - `npm view @mnemonik-xyz/{sdk,cli} version` reports 0.1.0 for both.
   - `curl https://mc.mnemonik.xyz/health` returns `{"status":"ok"}`.
   - `curl https://mnemonik.xyz/health` returns `{"status":"ok"}`.
   - Webapp `/install` page renders the new "Install in terminal" card visibly in browser.
