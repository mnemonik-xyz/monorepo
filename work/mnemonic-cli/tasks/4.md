# Task 4: COSE wrapper + golden-fixture cargo feature + CI lockstep gate

## Required Skills

Before starting, load: `/skill:code-writing`

## Description

Build the byte-for-byte parity test infrastructure between Rust core's canonical CBOR + COSE_Sign1 encoder and the SDK's WASM-based wrapper. Decision 12 of tech-spec specifies a `golden-fixtures` cargo feature that emits JSON triples (`{input_bytes_hex, expected_canonical_cbor_hex, expected_cose_envelope_hex}`); the SDK loads the JSON and asserts WASM produces byte-identical output; CI enforces lockstep via SHA-256 checksum diff.

Currently `golden-fixtures` does NOT exist — this task creates it. The fixture is committed to `packages/sdk/test/fixtures/golden-cose.json` along with `golden-cose.sha256`. The CI workflow regenerates from Rust on every PR and diffs against the checksum; drift fails the workflow.

After this task: any divergence between Rust's `to_canonical_cbor` + `sign_cose` and the SDK's WASM-driven equivalent is detected at PR time. The SDK's `cose.ts` wrapper passes the golden test for ~50 input cases including known CBOR-canonical edge cases (negative integers, indefinite-length arrays would-be encoded as definite, NaN handling, max-int boundaries, embedded UTF-8 vs raw bytes).

## What to do

1. **Add `golden-fixtures` cargo feature to `core/Cargo.toml`:**
   ```toml
   [features]
   golden-fixtures = []
   ```

2. **Create `core/tests/golden_fixtures.rs`** (a Rust integration test gated `#[cfg(feature = "golden-fixtures")]`). Iterate ~50 input cases (define a `Vec<(name, content_bytes, tags, signer_pubkey_bytes, secret_bytes)>` covering: empty content, ASCII content, UTF-8 multi-byte, large content, content with control chars, embedded null bytes, content matching CBOR breaks, multi-tag arrays, tag with empty string, tag with very long string, etc.). For each, call `core::codec::canonical::to_canonical_cbor(...)` to get the canonical bytes, then `core::codec::sign::sign_cose(canonical_bytes, &keypair)` to get the COSE envelope. Emit a JSON file via `serde_json::to_string_pretty`:
   ```json
   [{"name":"empty","input_hex":"...","canonical_cbor_hex":"...","cose_envelope_hex":"..."}, ...]
   ```
   Write to stdout when run as `cargo test --features golden-fixtures -p mnemonic-core --test golden_fixtures -- --ignored emit_fixtures`. Use `--ignored` so the emitter doesn't run on default `cargo test`.

3. **Add a regenerator script `packages/sdk/scripts/regen-golden-fixtures.sh`** that runs the cargo test, captures stdout, writes to `packages/sdk/test/fixtures/golden-cose.json`, computes SHA-256, writes to `packages/sdk/test/fixtures/golden-cose.sha256`. Document usage in `packages/sdk/README.md`.

4. **Run the script once locally**, commit the resulting `golden-cose.json` (~50 entries) and `golden-cose.sha256`.

5. **Build `packages/sdk/test/cose.golden.test.ts`:** load the fixture JSON, for each entry decode `input_hex` to bytes, run SDK's `coseSignPayload(canonical_bytes_decoded, keypair_json)` (where `keypair_json` is reconstructed from the fixture's `signer_pubkey_bytes` + `secret_bytes`). Assert byte-equality with `cose_envelope_hex` decoded.

6. **Add CI lockstep gate** to `.github/workflows/node-test.yml` (created in Task 8):
   ```yaml
   - name: Lockstep golden fixture
     run: |
       cargo test --features golden-fixtures -p mnemonic-core --test golden_fixtures -- --ignored emit_fixtures > /tmp/regen.json
       sha256sum /tmp/regen.json | awk '{print $1}' > /tmp/regen.sha
       diff /tmp/regen.sha packages/sdk/test/fixtures/golden-cose.sha256
   ```
   If the diff is non-empty, the workflow fails. (Task 8 will integrate this into the broader CI matrix.)

7. **Smoke verification.** Run `cargo test --features golden-fixtures -p mnemonic-core --test golden_fixtures -- --ignored emit_fixtures > /tmp/test.json && wc -l /tmp/test.json` — expect ~50 lines plus JSON metadata. Then `cd packages/sdk && bun test test/cose.golden.test.ts` — all golden cases pass.

## TDD Anchor

- `packages/sdk/test/cose.golden.test.ts::all_golden_cases_match` — for each of the ~50 fixture entries, `coseSignPayload` produces byte-identical output. **Drives** Decision 12 byte-for-byte parity.
- `core/tests/golden_fixtures.rs::test_emitter_deterministic` — running the emitter twice on the same input produces identical JSON (no field reordering, no random seeds). **Drives** the lockstep mechanism.
