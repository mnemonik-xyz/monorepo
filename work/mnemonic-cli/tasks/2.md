# Task 2: SDK core — `MnemonicClient`, `Signer` interface, `LocalSigner`, `Keypair`, contract suite

## Required Skills

Before starting, load: `/skill:code-writing`

## Description

Build the SDK's stateless client surface: a `MnemonicClient` class that wraps the 5 MCP HTTP tool methods, a pluggable `Signer` interface with the `LocalSigner` Phase 1 implementation, `Keypair` helpers, and an abstract `Signer` contract test suite (`runSignerContract(signer)`) that any future signer impl must pass.

The `signMemory` method **always** handles the server's pending-bundle response shape — Decision 7 / completeness validator finding: the hosted MCP server has no inline-signed code path for HTTP+JWT clients. SDK decodes `payload_cbor_base64`, runs WASM `sign_cose_payload(cbor_bytes, keypair_json)`, then POSTs the COSE_Sign1 envelope to `/api/sign-callback` with `{correlation_id, signer_pubkey, cose_signed}` (no Bearer JWT — capability auth via correlation_id).

`LocalSigner` uses the existing WASM export `sign_challenge(keypair_json, challenge_bytes)` for raw Ed25519 signatures over arbitrary byte payloads. **Do not** use `sign_cose_payload` for the `Signer.sign` path — that wraps in COSE, which is wrong for a generic byte-signer interface.

After this task: SDK exposes the public types from § Data Models in tech-spec; round-trip unit tests for client and signer pass; `signer-contract.ts` is consumable by other test files.

## What to do

1. **`packages/sdk/src/types.ts`** — public TS types: `SignerInterface`, `MnemonicClientConfig`, `SignMemoryOptions`, `SignMemoryResult`, `VerifyResult`, `RecallResult`, `WhoamiResult`, `ProveResult`. Match the shapes in tech-spec § Data Models.

2. **`packages/sdk/src/keypair.ts`** — wraps WASM `generate_keypair`, `export_keypair_json`, `import_keypair_json`. Exposes class `Keypair` with static `generate()`, `fromJSON(json)`, instance `toJSON()`, `pubkey` getter.

3. **`packages/sdk/src/signer.ts`** — defines `interface Signer { pubkey: string; sign(bytes: Uint8Array): Promise<Uint8Array> }` and concrete `LocalSigner` class. `LocalSigner` constructor takes a `Keypair`; `.sign(bytes)` calls WASM `sign_challenge(this.keypair.toJSON(), bytes)` and returns the resulting `Uint8Array` (must be 64 bytes).

4. **`packages/sdk/src/cose.ts`** — thin wrapper `coseSignPayload(canonicalCbor: Uint8Array, keypairJson: object): Promise<Uint8Array>` calls WASM `sign_cose_payload`. Used only by `client.ts::signMemory`.

5. **`packages/sdk/src/errors.ts`** — typed error classes (`AuthError`, `ServerError`, `IntegrityError`, `UserError`) with a `redactJWT(str)` helper that replaces JWT-shape strings (`/eyJ[A-Za-z0-9_-]{20,}/`) with `[REDACTED-JWT]`. All thrown errors run their messages through this redactor before construction.

6. **`packages/sdk/src/client.ts`** — `MnemonicClient` class:
   - Constructor: `{baseUrl, signer, jwt?}`. Stores all three. No I/O at construction.
   - `whoami()`: GET-equivalent via `tools/call name=mnemonic_whoami` — but per Decision 14 this method is intended for SDK consumers who want a generic check; CLI's `whoami` command does NOT use this (it's client-side). Return shape: `{server_pubkey, server_did}` (whatever server returns).
   - `signMemory(content, opts)`: POST `tools/call name=mnemonic_sign_memory` to `/mcp` with Bearer JWT. Decode pending-bundle response, call `coseSignPayload(...)`, POST envelope to `/api/sign-callback` (no JWT). Return `SignMemoryResult`.
   - `recall(query, opts)`: POST `tools/call name=mnemonic_recall`. Return array of results.
   - `verify(attestationId)`: POST `tools/call name=mnemonic_verify`. Return `VerifyResult`.
   - `proveIdentity(challenge)`: POST `tools/call name=mnemonic_prove_identity` — server-side prove (not used by CLI per Decision 14, but available for SDK consumers).

7. **`packages/sdk/test/signer-contract.ts`** — exports `runSignerContract(makeSigner: () => Signer | Promise<Signer>): void` that asserts: `pubkey` non-empty base58, `sign(32-byte-input)` returns 64 bytes, signature verifies via WASM `verify_signature(pubkey, bytes, sig)`, signing same input twice gives identical bytes (Ed25519 deterministic), signing rejects on null/zero-length input.

8. **Unit tests** in `packages/sdk/test/{client,signer,signer-contract}.test.ts`. Use `vitest` + mocked `fetch` (via `vi.fn()`). Cover: client correctly POSTs `/mcp` with Bearer JWT; `signMemory` correctly handles pending-bundle response (decode base64 → coseSign → POST `/api/sign-callback`); `LocalSigner` runs through `runSignerContract` cleanly.

9. **`packages/sdk/src/index.ts`** — re-export public surface only.
