# Task 21: Onboarding orchestrator + SetPassphrase mount integration tests

## Description

Round-2 test audit (`work/chrome-extension/logs/working/audit/test-auditor-round2.json`) flagged coverage gaps TA-MIN1 (no Onboarding orchestrator test) and the implicit gap that `SetPassphrase.tsx` is library-only — its mounted-in-Onboarding integration path has no test. T17 round-1 (T17-T-02) addressed component-level coverage but not the orchestrator wiring.

Add tests that drive the Onboarding state machine end-to-end at the React-component level (mocked fetches, mocked chrome.*). Cover the three Decision-5 branches:
1. `existingPubkey === null` → mounts SetPassphrase → wrap-and-upload → success.
2. `existingPubkey + escrow_present` → mounts Restore → unwrap → identity persisted.
3. `existingPubkey + no escrow` → "manual import" edge-case panel.

## What to do

1. **`packages/extension/tests/component/popup/Onboarding.test.tsx`** (new):
   - Render `<Onboarding>` with an injected runtime stub.
   - **Branch 1 — fresh user**:
     - `lookupExisting` mock returns `{ existingPubkey: null }`.
     - Assert SetPassphrase mounts (find the zxcvbn meter region by role/label).
     - Type a strong passphrase (use a fixed long alphanumeric string that yields zxcvbn score ≥ 3, e.g. `"correct horse battery staple 0xFA1"`).
     - Submit → assert `keyEscrow.wrapSecret` called once with the stub keypair + passphrase; `keyEscrow.uploadEscrow` called with the resulting blob and the `aud=extension` JWT; `auth.link` called with the link-challenge signature.
   - **Branch 2 — welcome back**:
     - `lookupExisting` mock returns `{ existingPubkey: "<base58>", escrowPresent: true, linkChallenge: null }`.
     - Assert Restore mounts (find the headline by text match on "Welcome back").
     - Submit correct passphrase → assert `keyEscrow.fetchEscrow` called once, `unwrapSecret` called, `chrome.storage.local.set` invoked with `identity` + `identity_secret`, `onComplete` fired.
   - **Branch 3 — existing identity, no escrow**:
     - `lookupExisting` mock returns `{ existingPubkey: "<base58>", escrowPresent: false }`.
     - Assert the "manual import / start fresh" panel renders with both options.
     - Both options are buttons; "Continue in local mode" calls `onComplete({ mode: "local" })`.
   - **Branch reset**: after error in branch 1, user can go back and retry without state leak (assert mount/unmount clears passphrase state).
2. Use the existing test-seam pattern from `Restore.test.tsx` and `SetPassphrase.test.tsx` — inject runtime stub via prop or `setOnboardingRuntime` helper. If the helper doesn't exist, add it in `src/popup/Onboarding.tsx` matching the `setPopupRuntime` pattern.
3. Mock `chrome.storage.local`, `chrome.runtime.sendMessage`, and `fetch` consistently — reuse existing helpers from `tests/component/popup/Restore.test.tsx`. Reset between tests with `beforeEach`.
4. Address audit nit AUD-T-R2-01: in `tests/unit/auth/extension-bootstrap.test.ts`, refactor the refresh-buffer test to use the existing `installFetch()` helper instead of inline `globalThis.fetch = …`.
