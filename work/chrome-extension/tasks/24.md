# Task 24: Options-page coverage gaps (About / Identity-import) + property/fuzz tests

## Description

Round-2 test audit flagged remaining gaps TA-MIN2 (no About section test) and TA-MIN4 (no Identity-import test) on the Options page. Plus, the user requested maximum testing coverage — add property-based fuzz tests for the two highest-leverage parsers/crypto paths so we catch the long-tail of malformed inputs the unit tests don't enumerate.

## What to do

1. **`packages/extension/tests/component/options/About.test.tsx`** (new — TA-MIN2):
   - Render `<About>` from `src/options/sections/About.tsx`.
   - Assert it renders the extension version (from manifest), build SHA placeholder (or 'dev'), the four canonical links (whitepaper, source, MCP endpoint, Discord), and a "Reset all data" button.
   - "Reset all data" → confirm dialog → on confirm, calls `runtime.reset()` (mockable) → success toast.
   - Cancel in dialog → no `reset()` call.

2. **`packages/extension/tests/component/options/Identity.import.test.tsx`** (new — TA-MIN4):
   - Render `<Identity>` from `src/options/sections/Identity.tsx`.
   - Test the import flow:
     - Click "Import" → file picker (mock the `<input type="file">` change event with a Blob containing a valid keypair JSON — base58 `pubkey` + base58 `secret` or whatever the canonical layout is, derive from `popup/runtime-impl.ts::loadIdentity`).
     - On valid file: assert `chrome.storage.local.set` called with `identity` + `identity_secret` keys; success toast; the displayed identity badge updates.
     - On malformed file (missing field, wrong base58, wrong byte length 32 vs 64): assert no storage write, error toast with specific message, identity badge unchanged.
     - Export → click "Export" → assert a downloadable Blob URL is created with the canonical JSON shape.
   - Use the existing `tests/component/options/Identity.test.tsx` patterns; reuse mocks.

3. **`packages/extension/tests/unit/messages.fuzz.test.ts`** (new — property-based):
   - Use `fast-check` if already in devDependencies; otherwise use a small hand-rolled generator (≤ 50 lines) that produces random objects, primitives, arrays, missing fields, extra fields, and `null` slots.
   - Property: `parseMsg(x)` always returns either `null` or a typed `Msg`. The function must never throw, never return `undefined`, never return a partially-typed result.
   - 1000 iterations. If the runner is slow, drop to 200 — but document.
   - Specifically include adversarial samples:
     - Object with valid `type` but completely wrong payload shape.
     - Object with valid `type` + valid payload AND extra fields → should parse, extra fields ignored.
     - Deeply-nested junk: `{type: "ui:recall", payload: {query: {nested: {a: [1, "b"]}}}}` → returns null (query must be string).
   - This is the test that locks the parser invariant for the lifetime of `Msg`.

4. **`packages/extension/tests/unit/auth/key-escrow.fuzz.test.ts`** (new — property-based round-trip):
   - Property: for any random secret bytes (length ∈ [1, 256]) and any random passphrase string (UTF-8, length ∈ [8, 200]), `wrapSecret + unwrapSecret` is the identity (byte-equal Uint8Array).
   - Property: tampering with any single byte of `blob.ciphertext_b64` causes `unwrapSecret` to throw (`WrongPassphraseError`).
   - Property: tampering with `blob.nonce_b64` causes throw.
   - Property: `blob.kdf_params` are stable across two wraps of the same input + passphrase WHEN the salt is fixed (i.e. KDF determinism). Use a deterministic-salt variant of `wrapSecret` (or inject one via test seam) for this property if necessary.
   - 50 iterations (Argon2id is expensive — cap to keep CI < 60s).

5. **TA-MIN1 doc patch**: if any of the above leaves a known coverage gap (e.g. fast-check not available so fuzz is hand-rolled), document it in `decisions.md` under a new "T24 — coverage gaps closed" subsection.
