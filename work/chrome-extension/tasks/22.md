# Task 22: Cloud-tier popup component tests (Capture / Verify / Recall merge)

## Description

Round-2 test audit (TA-MIN3) flagged that Local-tier popup paths are tested but the Cloud-tier code paths in `Capture.tsx`, `Verify.tsx`, and the Cloud-mode `Recall.tsx` merge are not exercised at the component layer. The cloud-client unit tests verify `signRemote` / `recallRemote` / `verifyRemote` in isolation, and `cloud-sync.test.ts` verifies the SW drain — but the popup's interaction with `runtime.cloudSync.*` is not.

Add component tests that mount each popup tab in Cloud-tier mode with an injected runtime whose `cloudSync` facade is mocked to assert the contract.

## What to do

1. **`packages/extension/tests/component/popup/Capture.cloud.test.tsx`** (new):
   - Render `<Capture>` with runtime stub where `storageTier === "cloud"` and `auth.getSession()` returns a valid session.
   - Submit a memory → assert `cloudSync.signRemote` called once with `{content, tags, embedding, cose_bytes, signer_pubkey, content_hash}` (any-of for fields the popup actually computes). Server tx ids returned by the mock surface in the success toast.
   - Network failure path: `cloudSync.signRemote` rejects with `TransientSyncError` → assert local IDB row still created AND row marked `pending_upload` (or whatever the runtime returns) AND the popup shows "queued for retry" copy, not a hard error.
   - 401 path: rejects with `AuthError` → assert `mnemonik:re-auth-required` event observed OR runtime re-auth callback fired; popup shows re-login prompt.
2. **`packages/extension/tests/component/popup/Verify.cloud.test.tsx`** (new):
   - Render `<Verify>` with runtime stub for cloud verification.
   - Paste an attestation ID → assert `cloudSync.verifyRemote` called with the id; success path renders the verified panel; tampered path renders the tampered panel; not-found path renders the not-found panel.
3. **`packages/extension/tests/component/popup/Recall.merge.test.tsx`** (new):
   - Render `<Recall>` in cloud-tier mode.
   - Stub both `IndexedDbStore.search` (3 local results) and `cloudSync.recallRemote` (3 cloud results, some overlapping by `attestation_id`).
   - Assert merge behaviour: duplicates removed (by `attestation_id`), best score wins on conflict, final sort by score descending. Cloud-only results have non-`local:` tx ids; local-only have `local:` placeholder.
   - Cloud failure: `recallRemote` rejects → assert local results still render and a non-blocking warning surfaces ("cloud unreachable — showing local cache").
4. Reuse existing chrome.* + fetch mock helpers from sibling component tests. Reset state in `beforeEach`. No new helpers unless deduplicating ≥3 spots.

## TDD Anchor

- `tests/component/popup/Capture.cloud.test.tsx::cloud_push_succeeds` — drives the deferred-signing happy path from the popup; asserts `signRemote` called once, success toast renders with returned `attestation_id`.
- `tests/component/popup/Recall.merge.test.tsx::merge_dedupes_and_resorts` — drives the Cloud-tier merge contract; provides overlapping inputs and asserts final order + dedupe key.
