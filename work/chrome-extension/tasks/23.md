# Task 23: SW ↔ popup bridge contract tests + test-hygiene nits

## Description

The audit wave found cross-component drift (FAB message variants missing from `Msg` union; popup-vs-options session-shape mismatch; `tab:fab-*` messages silently dropped) that unit tests didn't catch — because each side mocked the boundary. Add bridge-level tests that exercise the real `parseMsg` + `handleMsg` paths against real-shape messages, locking the contract between sender (popup / content-script / FAB) and receiver (SW).

Plus fix the two test-hygiene nits flagged in round-2 audits.

## What to do

1. **`packages/extension/tests/unit/messages.contract.test.ts`** (new):
   - For every `Msg` variant in `src/messages.ts`, produce a well-formed payload and assert:
     - `parseMsg(serialized)` returns a non-null typed result.
     - The result's `type` discriminant equals the input variant.
     - At least one payload field is present and correctly typed.
   - For each variant, also build at least one malformed payload (wrong field type, missing required field) and assert `parseMsg` returns `null`.
   - Unknown discriminant → `parseMsg` returns `null`.
   - Object with no `type` → `null`. `null` / `undefined` / primitives → `null`.
2. **`packages/extension/tests/unit/background/service-worker.contract.test.ts`** (new):
   - For each Msg variant that the SW handles (`ui:*`, `tab:*`, etc.), call `handleMsg(parsed, sender, deps)` directly with:
     - The correct sender shape (popup-realm vs content-script-realm vs unknown).
     - Mocked `deps` (storeFactory, fetchImpl, now, signer).
   - Assert:
     - The handler returns the expected response shape.
     - Side effects fire (store calls, fetch calls, alarm registrations).
     - Sender-authorization rejection: a `ui:*` message from a tab-bearing sender is rejected; a `tab:*` message from a non-allowed origin is rejected.
   - This is the test that would have caught audit B5 (FAB types absent from `Msg`) AND B4 (SW recall stub).
3. **AUD-T-R2-02 nit (vacuous header assertion)**: in `tests/unit/auth/extension-bootstrap.test.ts`, the test that asserts no `Authorization` header on the GET /redeem call currently passes vacuously when the headers object is omitted. Fix by either:
   - Explicitly asserting `init.headers === undefined` (case where the test expects no headers object at all), OR
   - Building a fresh `Headers` instance and asserting `headers.get("authorization") === null` against an actually-set headers object.
   The assertion must distinguish "no headers" from "headers but no Authorization key".
4. **TA-MIN5 (size-limit gate doc)**: if `.size-limit.json` has a known mitigation gap (no `--fail-if-not-found`), add a CI step that runs `bun x size-limit --json` and `jq`-checks at least one matched path was non-zero. If the size-limit version in use does support a strict mode, switch to it. Otherwise add a CI grep that fails when the popup bundle is missing from the dist.
