# Task 6: Code Audit

## Description

Full-feature code-quality audit across all files touched by Tasks 1–5 of the refresh-token-rotation feature. This is a read-only audit wave task — the auditor reviews the implementation against the tech-spec's Architecture, Decisions, and Shared resources sections, identifies deviations, smells, and risks, and produces a written report. No production code is modified.

The audit specifically verifies:
- **Mutex discipline** — `rusqlite::Connection` is `!Send`; the project-wide invariant (CLAUDE.md "Storage lock discipline") is that the `Mutex<Connection>` lock is never held across an `.await`. Refresh rotation runs `BEGIN IMMEDIATE` inside a synchronous block; the audit confirms no `.await` lives between `lock()` and `drop(guard)` anywhere in `refresh.rs`, the refresh branch of `token_handler`, the evictor task, or in `escrow.rs`/`mcp.rs` paths touched by the feature.
- **Shared-resources compliance (per tech-spec D6)** — `OAuthState.refresh_store` is a SECOND `Arc<Mutex<rusqlite::Connection>>` opened on the same SQLite file as `McpState.store` (`Mutex<SqliteStore>`); the two are **independent Mutex instances** by design — SQLite WAL mode serializes writers at the file level. Audit MUST confirm: (a) exactly ONE Connection per side (refresh.rs doesn't accidentally open a third Connection), (b) `OnceLock<u64>` for JWT TTL seeded exactly once in `run_http`, (c) exactly one `ReuseCache` instance per `OAuthState`, (d) no per-request cache construction.
- **Per-decision rationale alignment** — every Decision (D1–D16) in tech-spec maps to concrete code that matches the stated rationale. Spot-checks include: D5 cache `put` happens before `COMMIT` in Branch A (the CWE-362 race fix); D8 family-revoke executes inside the same `BEGIN IMMEDIATE` transaction as detection; D2 salt validation aborts boot when `MCP_REFRESH_SALT` is absent or under 32 bytes after base64url decode; D12 JWT TTL parse failure and out-of-range values log WARN and fall back / clamp; D14 logging policy emits forensic fields per branch and NEVER logs `token_hash`, plaintext, salt, or the access JWT; D15 `Cache-Control: no-store` + `Pragma: no-cache` headers appear on success AND error responses; D16 the 4 KiB length cap fires before hashing or DB work.
- **Error-handling patterns** — `anyhow::Result` for fallible functions, `?` propagation, no `unwrap()` outside tests, parameterized SQL only, `oauth_error` builder used for every error response on `/oauth/token`, RFC 6749 §5.2 codes (`invalid_request`, `invalid_grant`, `unsupported_grant_type`) used per Decision 11.
- **Naming consistency** — module/function/field names line up with the tech-spec and existing project conventions (`refresh::rotate`, `refresh::mint_for_authorization_code`, `refresh::migrate_refresh_tokens`, `refresh::start_evictor`, `ReuseCache`, `OAuthState.refresh_store`, `OAuthState.refresh_salt`, `OAuthState.reuse_interval`, `OAuthState.evictor_tick`, `OAuthState.reuse_cache`).

## Details

- `mcp/src/oauth/refresh.rs` — Task 1 output. Audit: BEGIN IMMEDIATE wraps detect + family-revoke (D8); Branch A `reuse_cache.put` precedes `COMMIT` (D5); blake3(salt + plaintext) at rest with no log/print of plaintext or hash (D2, D14); LRU cap honored from `OAuthState` field, not hardcoded (round-2 m6); evictor uses `tokio::time::sleep(tick).await` loop (D9); no `.await` while holding the `Connection` Mutex.
- `mcp/src/oauth/mod.rs` — Tasks 2 & 3 output. Audit: `pub fn jwt_ttl_secs()` reads `OnceLock<u64>` with clamp + WARN on parse failure / out-of-range (D12); all 4 read sites at lines 391, 1075, 1113, 1124 use the function; `TokenRequest` has all fields `Option<String>`; `token_handler` post-parse dispatch covers `authorization_code` / `refresh_token` / unknown (D11); discovery metadata appends `"refresh_token"` to `grant_types_supported`; every response from `token_handler` carries `Cache-Control: no-store` + `Pragma: no-cache` (D15); 4 KiB length cap fires before hashing / DB (D16); `oauth_error` builder used for every error.
- `mcp/src/escrow.rs` — Task 2 output. Audit: 2 read sites at lines 511 and 797 switched from const to `jwt_ttl_secs()`; import line 59 updated accordingly.
- `mcp/src/main.rs` — Tasks 2 & 3 output. Audit: `OnceLock<u64>` seeded exactly once in `run_http` from `MCP_JWT_TTL_SECS`; `MCP_REFRESH_SALT` validated for presence and ≥32 bytes after base64url decode with clear boot error (D2); shared `Arc<Mutex<Connection>>` opened once and threaded into both `McpState.store` and `OAuthState::new`; `refresh::migrate_refresh_tokens` called before serving; `refresh::start_evictor` spawned once next to the existing confirmation evictor.
- `mcp/src/mcp.rs` — Task 3 output. Audit: all `OAuthState::new` call sites pass the shared `Connection`, salt, durations, and reuse cache without constructing duplicates.
- `mcp/tests/_helpers/mod.rs` — Tasks 3 & 4 output. Audit: `with_oauth_token(true)` mounts `/oauth/token` in the same tower stack as `/mcp`; helper signatures stable for Task 5.
- `mcp/src/test_support.rs` — Task 4 output. Audit: no production-only types accidentally exposed; helpers gated appropriately.
- `mcp/tests/oauth_refresh_e2e.rs` — Task 5 output. Audit (code quality only — deep test audit is Task 8): naming, structure, no `sleep(5s)` in hot paths, use of `with_reuse_interval(Duration::from_millis(100))`.

**Dependencies:** depends on Task 5 completion — the full feature implementation must be merged into the working tree before the audit begins.

**Edge cases the audit explicitly checks:**
- A second `Connection::open` accidentally introduced anywhere in the feature path.
- A second `OnceLock` for JWT TTL (e.g., a duplicate definition in `escrow.rs`).
- `reuse_cache.put` happening AFTER `COMMIT` instead of before — re-introduces the CWE-362 race (D5).
- Family-revoke executed in a second transaction (D8 violation).
- A `tracing::*!` macro accidentally formatting `plaintext`, `token_hash`, `refresh_salt`, or the access JWT.
- `Cache-Control` header emitted on success but missing on error responses.
- Length cap evaluated AFTER the body is hashed or AFTER a DB lookup (D16 violation).
- `MCP_JWT_TTL_SECS=notanumber` / empty / whitespace silently falling back without WARN (Task 10 R1 gate footgun — D12).
- `.await` between `lock()` and the matching `drop` in any feature-touched code path.

**Implementation hints:**
- Use the tech-spec § Shared resources table as the singleton-count checklist.
- Use the tech-spec § Decisions section as the rationale-alignment checklist; the report should walk D1 → D16 explicitly.
- Use CLAUDE.md "Hard architectural rules" as a fast pre-flight check.
- The report format is auditor's choice within the structure: verdict line, per-decision walkthrough, findings list grouped by severity, plus a summary of singleton/shared-resource counts.
