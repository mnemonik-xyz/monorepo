# Task 2: JWT_TTL_SECS env-plumbing via OnceLock

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Decision 12 prerequisite for the R1 pre-ship empirical gate (Task 10): JWT
access-token TTL must be overridable from the deploy env so
`mcp.dev.mnemonik.xyz` can run with `MCP_JWT_TTL_SECS=60` for the 2-minute
parallel Cursor + Claude.ai observation window. Today the TTL is a hard-coded
`pub const JWT_TTL_SECS: u64 = 3600` at `mcp/src/oauth/mod.rs:58`, read from
six production sites (4 in `oauth/mod.rs`, 2 in `escrow.rs`).

Replace the constant with a `pub fn jwt_ttl_secs() -> u64` reading a
process-global `std::sync::OnceLock<u64>` seeded once in `run_http` from the
`MCP_JWT_TTL_SECS` env var. The seed step clamps the parsed value to the
`[60, 604800]` range (1 minute to 7 days) — out-of-range values clamp and log
WARN. Parse failures (`notanumber`, empty, whitespace) log WARN and fall back
to `3600` — explicit non-silent behaviour so a deploy-typo on Task 10 doesn't
produce a 1h gate mistaken for a 60s one. All 6 read sites switch to the new
function (no `OAuthState` field-threading needed at any reader site, matching
the `confirmation_token::DEFAULT_TTL` single-source style).

`.env.example` and `references/deployment.md` document the new optional env
var alongside `MCP_JWT_SECRET`.

Note: the `pub mod refresh;` declaration is owned by Task 1 — this task does
NOT touch the module-declaration block of `mcp/src/oauth/mod.rs`.

## What to do

- In `mcp/src/oauth/mod.rs`:
  - Delete `pub const JWT_TTL_SECS: u64 = 3600;` at line 58.
  - Add a private `static JWT_TTL: std::sync::OnceLock<u64> = OnceLock::new();`
    — use `std::sync::OnceLock` (stable since Rust 1.70, mandated by
    Decision 12). Do NOT follow code-research §I.1 sample which still
    references the legacy `once_cell::sync::OnceCell` crate — that crate is
    not part of the project's dependency surface and using it here would
    introduce a needless dep.
  - Add `pub fn jwt_ttl_secs() -> u64` returning `*JWT_TTL.get().unwrap_or(&3600)`
    so any reader called before `run_http` seeded the lock still gets a safe
    default (binary path or stdio transport never reaches `run_http`).
  - Add a `pub fn seed_jwt_ttl_from_env()` (or equivalent — internal name at
    the implementer's discretion) that reads `MCP_JWT_TTL_SECS`, applies the
    clamp `[60, 604800]`, logs WARN on out-of-range clamp / parse failure /
    empty / whitespace, and sets the `OnceLock` exactly once. Default on any
    failure or absent env is `3600`.
- Switch every read site to `jwt_ttl_secs()`:
  - `mcp/src/oauth/mod.rs:391` (`exp: now + JWT_TTL_SECS`)
  - `mcp/src/oauth/mod.rs:1075` (`expires_in: JWT_TTL_SECS`)
  - `mcp/src/oauth/mod.rs:1113` and `:1124` (rfc3339 expires-at formatting,
    chrono arithmetic) — these two sites currently use `JWT_TTL_SECS as i64`.
    The replacement must keep the cast: write
    `jwt_ttl_secs() as i64` so the chrono `Duration::seconds(...)` /
    timestamp math compiles identically.
  - `mcp/src/escrow.rs:511` (`expires_in: JWT_TTL_SECS`)
  - `mcp/src/escrow.rs:797` (`exp: now + JWT_TTL_SECS`)
- Update the import line at `mcp/src/escrow.rs:59` to drop `JWT_TTL_SECS` and
  add `jwt_ttl_secs` (the function).
- In `mcp/src/main.rs::run_http`, call the seed function exactly once near the
  top of `run_http` (alongside `load_jwt_secret()?`, before `OAuthState::new`).
- Add `tracing-test = "0.2"` to `[dev-dependencies]` in `mcp/Cargo.toml` —
  required by the two WARN-log assertion tests below. Tech-spec Dependencies
  section lists this crate; it lands here because the first WARN-log tests
  in the codebase are owned by Task 2 (Task 3 / `logging_policy` reuses the
  same dev-dep).
- Add `MCP_JWT_TTL_SECS` documentation:
  - `.env.example`: commented example line with description + the clamp range
    + the parse-failure / clamp-WARN semantics + that omitting it gives the
    `3600` default.
  - `.claude/skills/project-knowledge/references/deployment.md`: a row in the
    env-var table near the existing `MCP_JWT_SECRET` row (line 58) and a
    short note in the hosted-mode env block (around line 269-274) covering
    the R1 use-case (`MCP_JWT_TTL_SECS=60` on dev for the empirical gate;
    unset / `3600` in prod).
- Write the two unit tests called out under TDD Anchor before flipping the
  implementation.

## TDD Anchor

Тесты пишем ДО реализации, запускаем, убеждаемся что падают, имплементим,
убеждаемся что проходят.

- `mcp/src/oauth/mod.rs::tests::jwt_ttl_seeded_from_env_and_clamped` —
  seeds the OnceLock with raw env values (`"10"`, `"9999999"`, `"3600"`) and
  asserts the clamp `[60, 604800]` applies (10→60, 9999999→604800,
  3600→3600). Captures `tracing` output via `#[traced_test]` from the
  `tracing-test = "0.2"` dev-dep added to `mcp/Cargo.toml` in this task,
  and asserts a WARN line was emitted for each clamped value.
- `mcp/src/oauth/mod.rs::tests::jwt_ttl_parse_failure_logs_warn_and_uses_default` —
  parses `"notanumber"`, `""`, `"   "` (whitespace-only). Each must fall
  back to `3600` AND emit a WARN log (asserted via `tracing-test`'s
  `logs_contain`). Closes the silent-default vector for the R1 gate
  (Task 10) — a deploy typo must be loud.

Both tests have to run on a OnceLock that has not yet been seeded by another
test; either gate them behind an `OnceLock`-resetting test seam (e.g. a
`#[cfg(test)] fn reset_jwt_ttl_for_test()`) or factor the clamp + WARN logic
into a pure helper (`compute_jwt_ttl_from_env_str(&str) -> u64` returning
the clamped value and emitting the WARN as a side effect) and test the
helper directly. Implementer's call; both are acceptable.

  jwt_ttl_secs() -> u64` + a seed function. Update 4 internal read sites
  (`391`, `1075`, `1113`, `1124`); `:1113` and `:1124` keep the `as i64`
  cast for chrono arithmetic.
- `mcp/src/escrow.rs` — update line 59 import; update 2 read sites

- `mcp/src/main.rs` — inside `run_http` (around line 789-791, right after
  `load_jwt_secret()?`), call the seed function. Stdio transport
  intentionally skipped — stdio sessions never check JWTs.
- `mcp/Cargo.toml` — add `tracing-test = "0.2"` under `[dev-dependencies]`
  (used by the two WARN-log assertion tests).
- `.env.example` — add a documented `MCP_JWT_TTL_SECS` line.
- `.claude/skills/project-knowledge/references/deployment.md` — document
  the new env var in the hosted-mode env table near
  `MCP_JWT_SECRET` (line 58) and in the deploy block around line 269-274.

**Dependencies:**
- `std::sync::OnceLock` (stable since Rust 1.70) — no new runtime crate
  required. Decision 12 specifically mandates `std::sync::OnceLock`; do
  NOT use `once_cell::sync::OnceCell` even though code-research §I.1
  sample code shows it.
- `tracing` is already pulled in for WARN logging.
- `tracing-test = "0.2"` is added in this task as a dev-dep so the WARN
  assertions can call `logs_contain` from `#[traced_test]`-decorated
  tests.

**Edge cases:**
- Seed runs on stdio transport too? No — `run_http` is HTTP-only;
  stdio transport's `JWT_TTL_SECS` reads never fire (no Bearer path) but the
  `OnceLock` default of `3600` keeps `jwt_ttl_secs()` correct even if some
  unforeseen call site reads it pre-seed.
- Race between seed and reader during startup? Impossible — `run_http`
  seeds before any axum router is built, and the only readers are inside
  request handlers that the router has not yet mounted.
- `OnceLock::set` returning `Err` (already initialised) — the seed function
  must tolerate this for test re-runs; either use `get_or_init` with an
  inner closure that captures the parsed value or `set` ignoring
  already-init errors with a debug-only assert.
- WARN log volume — only fires once per process at startup; no rate-limit
  concern.

**Implementation hints:**
- Mirror the `confirmation_token::DEFAULT_TTL` single-source pattern called
  out in Decision 12.
- For testability, factor the env-string-to-clamped-u64 + WARN logic into a
  pure helper that the OnceLock seed function calls; the two unit tests
  then exercise the helper directly without OnceLock pollution between
  tests (test-isolation hint, not a hard requirement — implementer may
  pick a `#[cfg(test)] fn reset_jwt_ttl_for_test()` instead).
- The `Risks` row in tech-spec ("MCP_JWT_TTL_SECS operator footgun (e.g.,
  setting 1s)") is satisfied by the clamp + WARN combo. Document the
  observed clamp in the WARN message so a grep on prod logs after Task 10
  /Task 11 can confirm operator intent.
