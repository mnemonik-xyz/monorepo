# Task 10: Dev deploy + R1 empirical gate

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:deploy-pipeline` — [skills/deploy-pipeline/SKILL.md](~/.claude/skills/deploy-pipeline/SKILL.md)

## Description

Это **load-bearing pre-ship empirical gate** из user-spec R1: до промоушна refresh-token-rotation на прод мы должны убедиться, что Claude.ai (the device under test) действительно использует выданный `refresh_token` и тихо ротирует доступ через `POST /oauth/token` с `grant_type=refresh_token`, а не выкидывает пользователя на OAuth-страницу при истечении JWT.

Cursor (control) уже известно ведёт себя корректно по Stripe-precedent наблюдениям. Мы развёртываем feature-branch на `mcp.dev.mnemonik.xyz` с искусственно сжатым `MCP_JWT_TTL_SECS=60` (минимально допустимое значение после clamp `[60, 604800]` из Decision 12), запускаем оба клиента параллельно на 2+ минуты — этого достаточно, чтобы JWT истёк несколько раз — и фиксируем GO/NO-GO.

- **GO** — оба клиента продолжают работать без OAuth-prompt → разблокировка Task 11 (prod deploy).
- **NO-GO** — Claude.ai требует re-auth → **STOP, не промоутить на прод**. Параллельно: (1) завести Anthropic ticket с детализацией поведения, (2) развернуть планирование в `work/stateless-auth-rearch/` (per-request signing — long-term fallback из Decision 1).

Свежий `MCP_REFRESH_SALT` генерится для этого деплоя отдельно: salt — deploy secret per Decision 2, и мы не переиспользуем продовый секрет в dev окружении.

## What to do

1. Сгенерировать новый `MCP_REFRESH_SALT` через `openssl rand -base64 32`. Сохранить локально вне репозитория (deploy secret). Убедиться, что base64url-decoded длина ≥32 байт — иначе server откажется бутаться (D2 + `oauth::tests::salt_under_32_bytes_aborts_boot`).
2. Задеплоить текущий feature branch на `mcp.dev.mnemonik.xyz` со следующим окружением:
   - `MCP_JWT_TTL_SECS=60` (минимально-допустимое значение после clamp, Decision 12).
   - `MCP_REFRESH_SALT=<свежесгенерированный>`.
   - Остальные dev env vars — как обычно для `mcp.dev.mnemonik.xyz`.
   Использовать процесс из `deployment.md` (VPS Deploy Process). Дождаться чистого старта (smoke `curl /.well-known/oauth-authorization-server | jq '.grant_types_supported'` содержит `"refresh_token"`).
3. Параллельно подключить **две** реальные клиентские сессии к dev MCP:
   - **Cursor** — control, известно ротирующий клиент.
   - **Claude.ai** — device under test, основной субъект R1.
   В каждом сделать осмысленный вызов `mnemonic_sign_memory` сразу после коннекта (baseline — оба клиента работают, JWT валиден).
4. Наблюдать оба клиента **минимум 2 минуты** (>= 2 истечения JWT при TTL=60s). Раз в ~30 секунд в обоих клиентах делать вызов `mnemonic_sign_memory` или `mnemonic_recall`, чтобы spurious-success не давал ложного GO.
5. Зафиксировать поведение:
   - **GO**: оба клиента продолжают работать **тихо** (без OAuth-page, без видимой re-auth) после первого и последующих JWT-expiry. Зафиксировать в отчёте, проследовать к Task 11.
   - **NO-GO**: Claude.ai в какой-то момент выдаёт OAuth-page / требует re-auth / падает с auth ошибкой. **STOP. НЕ ПРОМОУТИТЬ на прод.** В отчёте: (a) подробный таймлайн с моментом фейла, (b) скриншот/логи поведения, (c) подтверждение, что Cursor в той же сессии продолжал работать, (d) ссылка на свежезаведённый Anthropic ticket, (e) ссылка на обновлённый `work/stateless-auth-rearch/` (минимум — заметка с датой и контекстом).
6. Если есть возможность mitmproxy'ить трафик от Claude.ai (или анализировать через `journalctl` на VPS) — приложить наблюдение по `POST /oauth/token` с `grant_type=refresh_token`: вызывался ли вообще, какой ответ получил. Это критично для NO-GO диагностики (Anthropic ticket будет требовать этих деталей).
7. Записать отчёт в `work/refresh-token-rotation/logs/working/r1-empirical-gate-report.md` со следующей структурой:
   - GO/NO-GO решение в первой строке.
   - Окружение деплоя (dev URL, версия/commit, env vars без значений секретов).
   - Таймлайн наблюдения по минутам.
   - Поведение Cursor (control).
   - Поведение Claude.ai (device under test).
   - Наблюдаемый `/oauth/token` трафик (если доступен).
   - Решение и следующий шаг (Task 11 OR Anthropic ticket + stateless-auth-rearch).

## Details

**Files:**
- `work/refresh-token-rotation/logs/working/r1-empirical-gate-report.md` (NEW) — финальный отчёт по структуре из шага 7. Это load-bearing артефакт: Task 11 запускается только при наличии GO-отчёта здесь.

**Dependencies:**
- Task 9 (pre-deploy QA) должен быть пройден — все тесты/clippy/fmt/gitleaks зелёные. Без этого деплой на dev запрещён по `patterns.md` (Git workflow).
- Feature branch актуально замержен с `main` или поверх `main` — иначе dev может не отражать тот же код, что готовится к prod (Task 11).
- Доступ к VPS, на котором крутится `mcp.dev.mnemonik.xyz` (deploy через `deployment.md::VPS Deploy Process`).
- Реальные сессии Claude.ai и Cursor (нельзя имитировать через curl — R1 проверяет именно поведение клиента после JWT expiry, не сервера).

**Edge cases:**
- **Cursor падает, Claude.ai работает** — недостоверный GO. Cursor — control: если control сломан, эксперимент невалидный. Перезапустить с диагностикой VPS.
- **Оба клиента переподключились в первые 30 секунд** — JWT ещё не истёк, наблюдение невалидное. Нужно дождаться ≥2 expiry.
- **`MCP_JWT_TTL_SECS=60` принят, но логи показывают clamp / parse-failure WARN** — операторская ошибка (опечатка значения / неверный env). Проверить логи на старте, исправить, перезапустить.
- **dev URL отдаёт старую версию кода** (rolling deploy не завершился) — discovery curl покажет grant_types без `refresh_token`. Дождаться завершения rollout.
- **Claude.ai упал на самом первом вызове** (до первого JWT expiry) — это **не** NO-GO по R1, это деплой-баг. Сначала разобраться с базовой работой, потом запускать наблюдение.
- **NO-GO без видимого `/oauth/token` трафика** — возможно Claude.ai вообще не пытается рефрешить (просто очищает сессию и редиректит). Это критично для Anthropic ticket — указать явно.

**Implementation hints:**
- Деплой по `deployment.md::VPS Deploy Process` — никакого нового пути.
- Salt — strictly out-of-repo. Не коммитить в `.env`, не вписывать в task report. В отчёте указать только факт генерации (`openssl rand -base64 32` использован) без значения.
- Минимально допустимый TTL после clamp — 60 секунд (Decision 12, `[60, 604800]`). Меньше не выставлять — clamp сработает + WARN.
- Cursor — control: если он сломан, не делать выводов о Claude.ai. Это базовый принцип эксперимента.
- При NO-GO Anthropic ticket должен содержать: точный таймлайн, версию dev MCP (commit hash), сэмпл реквеста (если виден), что Cursor работал в той же конфигурации.
- При GO путь к Task 11 явный: отчёт → Task 11 запускается → продовый деплой с **дефолтным** (3600s или unset) TTL и **отдельным** продовым `MCP_REFRESH_SALT`.
