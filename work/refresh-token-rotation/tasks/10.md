# Task 10: Dev tunnel + R1 empirical gate

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:deploy-pipeline` — [skills/deploy-pipeline/SKILL.md](~/.claude/skills/deploy-pipeline/SKILL.md)

## Description

Это **load-bearing pre-ship empirical gate** из user-spec R1: до промоушна refresh-token-rotation на прод нужно убедиться, что Claude.ai (the device under test) реально использует выданный `refresh_token` и тихо ротирует доступ через `POST /oauth/token` с `grant_type=refresh_token`, а не выкидывает пользователя на OAuth-страницу при истечении JWT.

**Топология dev vs prod (важно)** — этот gate выполняется **локально**, без доступа к VPS. У проекта нет отдельной `mcp.dev.mnemonik.xyz` инсталляции: `deployment.md` покрывает только продовый `mcp.mnemonik.xyz` (см. `deployment.md::VPS Deploy Process`). Реальные клиенты (Cursor, Claude.ai) требуют HTTPS-origin с валидным TLS для OAuth/CORS — localhost напрямую не работает. Поэтому dev-проверка реализуется через **Cloudflare Tunnel (`cloudflared`)** или **ngrok**, которые подняли локально работающий `mnemonic-mcp` на публичный HTTPS-URL (например, `https://<random>.trycloudflare.com`). Продовый деплой выполняется отдельно в Task 11 на `mcp.mnemonik.xyz` по `deployment.md::VPS Deploy Process` и **никак не связан** с этим dev-окружением.

Cursor (control) по Stripe-precedent наблюдениям корректно ротирует. Запускаем оба клиента параллельно на 2+ минуты при `MCP_JWT_TTL_SECS=60` (минимально допустимое значение после clamp `[60, 604800]` из Decision 12) — этого достаточно, чтобы JWT истёк несколько раз — и фиксируем GO/NO-GO.

- **GO** — оба клиента продолжают работать без OAuth-prompt → разблокировка Task 11 (prod deploy).
- **NO-GO** — Claude.ai требует re-auth → **STOP, не промоутить на прод**. Параллельно: (1) завести Anthropic ticket с детализацией поведения, (2) развернуть планирование в `work/stateless-auth-rearch/` (per-request signing — long-term fallback из Decision 1).

Свежий `MCP_REFRESH_SALT` генерится для этого прогона отдельно: salt — deploy secret per Decision 2, и мы не переиспользуем продовый секрет в dev-туннеле.

## What to do

1. Сгенерировать новый `MCP_REFRESH_SALT` через `openssl rand -base64 32`. Сохранить локально вне репозитория (deploy secret). Убедиться, что base64url-decoded длина ≥32 байт — иначе server откажется бутаться (D2 + `oauth::tests::salt_under_32_bytes_aborts_boot`).
2. Запустить локально `mnemonic-mcp` на порту 3000 в HTTP-режиме поверх feature branch:
   - `cargo build -p mnemonic-mcp --release` (если ещё не собран).
   - Запустить с env:
     - `MCP_JWT_TTL_SECS=60` (минимально-допустимое после clamp, Decision 12).
     - `MCP_REFRESH_SALT=<свежесгенерированный>`.
     - `STORAGE_MODE=local`, `PAYMENT_MODE=none` (упрощаем — это про OAuth, не про платёжный пайплайн).
     - `EMBED_PROVIDER` + соответствующий ключ/feature как обычно для локального запуска (см. CLAUDE.md).
   - Команда: `STORAGE_MODE=local PAYMENT_MODE=none MCP_JWT_TTL_SECS=60 MCP_REFRESH_SALT=<...> cargo run -p mnemonic-mcp --release -- --transport http --port 3000`.
3. Поднять публичный HTTPS-туннель на локальный порт 3000:
   - Вариант A (рекомендуемый, бесплатный, без аккаунта): `cloudflared tunnel --url http://localhost:3000` → выдаст `https://<random>.trycloudflare.com`.
   - Вариант B: `ngrok http 3000` → выдаст `https://<random>.ngrok-free.app` (или платный stable subdomain).
   - Зафиксировать публичный URL — назовём его `TUNNEL_URL`. Через 2+ часа Cloudflare quick-tunnel может закрыться — учесть, при долгом наблюдении переподнять.
4. Smoke-проверить discovery через туннель **до** подключения клиентов:
   - `curl https://<TUNNEL_URL>/.well-known/oauth-authorization-server | jq '.grant_types_supported'` должен вернуть массив, содержащий и `"authorization_code"`, и `"refresh_token"`. Если `refresh_token` отсутствует — деплой не из feature branch / `mcp.rs::discovery` не задеплоен / процесс не перезапустился. STOP, разобраться, прежде чем подключать клиентов.
5. Добавить `TUNNEL_URL` как MCP-сервер в **обоих** клиентах (ручной UI-шаг — задокументировать в отчёте):
   - **Cursor** (control): Settings → MCP → Add server → HTTP transport, URL = `<TUNNEL_URL>`.
   - **Claude.ai** (device under test): Settings → Connectors → Add custom connector → URL = `<TUNNEL_URL>`.
   В каждом пройти OAuth flow до конца — получить initial JWT (валиден 60 секунд из-за `MCP_JWT_TTL_SECS=60`).
   Сразу после коннекта сделать осмысленный вызов `mnemonic_sign_memory` — baseline, оба клиента работают.
6. Наблюдать оба клиента **минимум 2 минуты** (>= 2 истечения JWT при TTL=60s). Раз в ~30 секунд в обоих клиентах делать вызов `mnemonic_sign_memory` или `mnemonic_recall`, чтобы spurious-success не давал ложного GO.
7. Зафиксировать поведение:
   - **GO**: оба клиента продолжают работать **тихо** (без OAuth-page, без видимой re-auth) после первого и последующих JWT-expiry. Зафиксировать в отчёте, проследовать к Task 11.
   - **NO-GO**: Claude.ai в какой-то момент выдаёт OAuth-page / требует re-auth / падает с auth ошибкой. **STOP. НЕ ПРОМОУТИТЬ на прод.** В отчёте: (a) подробный таймлайн с моментом фейла, (b) скриншот/логи поведения, (c) подтверждение, что Cursor в той же сессии продолжал работать, (d) ссылка на свежезаведённый Anthropic ticket, (e) ссылка на обновлённый `work/stateless-auth-rearch/` (минимум — заметка с датой и контекстом).
8. Если есть возможность mitmproxy'ить трафик от Claude.ai (или анализировать stdout локального `mnemonic-mcp` процесса) — приложить наблюдение по `POST /oauth/token` с `grant_type=refresh_token`: вызывался ли вообще, какой ответ получил. Это критично для NO-GO диагностики (Anthropic ticket будет требовать этих деталей).
9. Записать отчёт в `work/refresh-token-rotation/logs/working/r1-empirical-gate-report.md` со следующей структурой:
   - GO/NO-GO решение в первой строке.
   - Окружение прогона (TUNNEL_URL provider — cloudflared/ngrok, версия/commit feature branch, env vars без значений секретов).
   - Discovery smoke output (`grant_types_supported`).
   - Таймлайн наблюдения по минутам.
   - Поведение Cursor (control).
   - Поведение Claude.ai (device under test).
   - Наблюдаемый `/oauth/token` трафик (если доступен).
   - Решение и следующий шаг (Task 11 OR Anthropic ticket + stateless-auth-rearch).
10. После gate'а — погасить туннель (`Ctrl+C` cloudflared/ngrok) и локальный процесс. Туннельный `MCP_REFRESH_SALT` **не переиспользовать** в прод-деплое (Task 11) — там генерится отдельный prod-only.

## Verification Steps

### User

Реальный пользователь подтверждает после поднятия туннеля:
- Discovery smoke (`curl <TUNNEL_URL>/.well-known/oauth-authorization-server | jq '.grant_types_supported'`) возвращает оба grant'а — `"authorization_code"` и `"refresh_token"`.
- Cursor сессия и Claude.ai сессия параллельно подключены к `TUNNEL_URL`.
- Оба клиента остаются функциональными (вызовы `mnemonic_sign_memory` проходят) на протяжении **2+ JWT expiry** при `MCP_JWT_TTL_SECS=60`.
- В Claude.ai не появляется OAuth-page и не требуется re-auth в течение окна наблюдения.

## Details

**Топология dev vs prod (явно):**
- Этот gate бежит **ЛОКАЛЬНО** — нет доступа к VPS, нет инсталляции `mcp.dev.mnemonik.xyz`. `deployment.md` покрывает только прод (`mcp.mnemonik.xyz`).
- Прод-деплой запускается отдельно в Task 11 на `mcp.mnemonik.xyz` по `deployment.md::VPS Deploy Process` после GO в этом gate'е.
- Туннель — временный (одна сессия наблюдения), не часть постоянной инфраструктуры.

**Files:**
- `work/refresh-token-rotation/logs/working/r1-empirical-gate-report.md` (NEW) — финальный отчёт по структуре из шага 9. Это load-bearing артефакт: Task 11 запускается только при наличии GO-отчёта здесь.

**Dependencies:**
- Task 9 (pre-deploy QA) должен быть пройден — все тесты/clippy/fmt/gitleaks зелёные. Без этого dev tunnel запуск запрещён по `patterns.md` (Git workflow).
- Feature branch актуально замержен с `main` или поверх `main` — иначе локальный билд может не отражать тот же код, что готовится к prod (Task 11).
- Установлен `cloudflared` (`brew install cloudflared`) **или** `ngrok` (`brew install ngrok`); локальная сборка `mnemonic-mcp` (`cargo build -p mnemonic-mcp --release`).
- Реальные сессии Claude.ai и Cursor (нельзя имитировать через curl — R1 проверяет именно поведение клиента после JWT expiry, не сервера).

**Edge cases:**
- **Cursor падает, Claude.ai работает** — недостоверный GO. Cursor — control: если control сломан, эксперимент невалидный. Перезапустить локальный процесс с диагностикой.
- **Оба клиента переподключились в первые 30 секунд** — JWT ещё не истёк, наблюдение невалидное. Нужно дождаться ≥2 expiry.
- **`MCP_JWT_TTL_SECS=60` принят, но логи показывают clamp / parse-failure WARN** — операторская ошибка (опечатка значения / неверный env). Проверить логи на старте, исправить, перезапустить.
- **Discovery curl отдаёт ответ без `refresh_token`** — туннель не на тот порт / процесс крутит старую ветку / не перестартовался. Дождаться чистого старта.
- **Quick Cloudflare Tunnel умер через ~2 часа** — нормальное поведение бесплатного quick-режима. Если наблюдение растянулось, переподнять туннель (URL поменяется, клиентов придётся переподключать; учесть в таймлайне отчёта).
- **CORS / TLS errors в клиенте при подключении** — Claude.ai и Cursor требуют валидный HTTPS-origin. localhost напрямую не подойдёт — поэтому туннель. Проверить, что URL в клиенте — `https://...`, а не `http://localhost:...`.
- **Claude.ai упал на самом первом вызове** (до первого JWT expiry) — это **не** NO-GO по R1, это connector-setup баг. Сначала разобраться с базовой работой, потом запускать наблюдение.
- **NO-GO без видимого `/oauth/token` трафика** — возможно Claude.ai вообще не пытается рефрешить (просто очищает сессию и редиректит). Это критично для Anthropic ticket — указать явно. Локальный stdout `mnemonic-mcp` процесса покажет, был ли вообще запрос.

**Implementation hints:**
- Salt — strictly out-of-repo. Не коммитить в `.env`, не вписывать в task report. В отчёте указать только факт генерации (`openssl rand -base64 32` использован) без значения.
- Минимально допустимый TTL после clamp — 60 секунд (Decision 12, `[60, 604800]`). Меньше не выставлять — clamp сработает + WARN.
- Cursor — control: если он сломан, не делать выводов о Claude.ai. Это базовый принцип эксперимента.
- При NO-GO Anthropic ticket должен содержать: точный таймлайн, версию (commit hash feature branch), сэмпл реквеста (из локального stdout, если виден), что Cursor работал в той же конфигурации через тот же `TUNNEL_URL`.
- При GO путь к Task 11 явный: отчёт → Task 11 запускается → продовый деплой с **дефолтным** (3600s или unset) TTL и **отдельным** продовым `MCP_REFRESH_SALT` на `mcp.mnemonik.xyz`.
- Туннельный (Cloudflare quick / ngrok free) URL — эфемерный; не публиковать наружу, использовать только для gate'а; погасить после наблюдения.
