# User Spec: Режим — это выбор пользователя, а не параметр сервера

## Суть

**Пользователь не должен думать о механике.** Те же 5 MCP-инструментов
(`sign_memory`, `recall`, `verify`, `whoami`, …), тот же keypair — везде.
Каждый раз когда пользователь что-то «запоминает», он выбирает **только
намерение**:

- **`local`** — держать у себя, бесплатно, оффлайн (default);
- **`participate`** — вынести в сеть, заякорить, сделать verifiable. Платно.

Всё. Где крутится инфраструктура и сколько стоит — следствие *куда пользователь
подключён*, не отдельное решение на каждый вызов.

Сегодня всё наоборот: `STORAGE_MODE` и `PAYMENT_MODE` **жёстко зашиты
оператором при старте процесса**, одно значение на всех пользователей и на
каждый вызов сразу (CLAUDE.md: «Mode is set at startup, not per-call»). Мы это
переворачиваем: **режим = намерение конкретной записи**, оператор лишь
декларирует, *что в принципе умеет* (envelope).

## Прозрачный спектр развёртываний (позиционирование, не код)

Один артефакт, один keypair, один API. Различается только **где живёт сервер и
куда идёт `participate`** — и за счёт этого цена. Пользователь свободно
двигается между точками:

### 1. Локально — бесплатно, по умолчанию
Артефакты лежат у пользователя (локальная ФС / self-hosted бэкенд). **Платить
не нужно никогда** (whitepaper §5.7.1: подпись, хеш, проверка lineage не могут
быть предметом ренты). Это поведение **по умолчанию**: кто ничего не
настраивал — получает бесплатную личную память, а не «настройте оплату».

### 2. Свой MCP-сервер — дешевле, без посредника
Опытный пользователь поднимает `mnemonic-mcp` сам (`STORAGE_MODE=full,
PAYMENT_MODE=none`) и пишет в Arweave/Solana напрямую со своего funded keypair.
Платит **только raw-стоимость** якорения, без маржи оператора. Это **не
отдельный режим в коде** — буквально «ты сам себе оператор», уже работает.
Путь для разработчиков; **не впариваем рядовому пользователю**, не дефолт.

### 3. Чужая инфраструктура (Mnemonik или другой оператор) — без своей инфры
Пользователь подключается к удалённому MCP, артефакт сохраняется/якорится,
оплата — **per-call через x402** (микроплатёж за каждую вынесенную в сеть
запись). Дороже за удобство и zero-ops, но не нужно держать ничего своего.

> Все три точки — это **варианты деплоя**, не три значения в API. В коде
> существует только `mode: local | participate` (binary, per-request). Tier-2
> vs Tier-3 — это «к какому MCP клиент подключён» и оператор-side env-vars;
> новый код для tier-2 не нужен — он *уже* работает (`STORAGE_MODE=full +
> PAYMENT_MODE=none`), эта фича лишь делает явным, что это легитимный путь.

## Инварианты

- **Личная память бесплатна всегда** (tier-1). Это структурное свойство
  кодового пути, не настройка оператора. Сегодня если оператор поднял сервер в
  `full`, любой `sign` стоит денег — даже сугубо личная заметка (`mcp.rs:424`).
  Это прямое нарушение §5.7.1; фича чинит структурно: free/paid fork теперь
  определяется **резолвнутым `mode` на запросе**, не env-var оператора.
- **`participate` платен всегда** (tier-2/3). Durable-якорь стоит денег у кого
  угодно. **Сколько и кому** платит пользователь — это спектр (свой raw-cost
  vs x402 оператору), а не одна навязанная точка.
- **Результат не зависит от тира.** Тот же keypair, тот же подписанный,
  заякоренный и проверяемый артефакт. Меняются только цена и владелец
  инфраструктуры.
- **Гранулярность — per-request.** Намерение задаётся optional полем `mode`
  в `sign_memory` (default `local`). Local- и participate-записи **сосуществуют
  у одного пользователя в одной БД**, тегируясь `write_mode`; `recall` видит и
  то, и другое. Старый инвариант CLAUDE.md «Never mix in one DB» сознательно
  ретайрится (правка CLAUDE.md в том же PR).
- **«Доставлено» = заякорено И подтверждено через recall.** Пока артефакт не
  перечитан через собственный read-path протокола (recall находит + verify
  проверяет blake3-хеш и Ed25519-подпись заякоренных байт), запись остаётся
  `local` и плата не берётся. Это ловит единственный тихий сбой: отрапортовали
  «participated», а якорь на деле не лёг.
- **Discoverability через `whoami` (контракт).** Сервер декларирует envelope —
  что он *в принципе* умеет, — до того как клиент попробует писать. Тот же
  envelope — единственный источник правды о цене и дефолте для UX.

  `mnemonic_whoami` возвращает (в дополнение к существующим полям):

  ```jsonc
  {
    "pubkey": "ed25519:...",
    "supported_modes": ["local", "participate"], // что сервер реально умеет
    "default_mode": "local",                      // что применится без mode-поля
    "participate_cost": {                         // null если participate не умеет
      "currency": "USD",
      "amount_cents": 1,
      "payment_methods": ["x402", "balance"]      // подмножество того, как платят
    }
  }
  ```

  Три точки спектра дают три envelope'а:

  | Сервер | `supported_modes` | `participate_cost` |
  |---|---|---|
  | Tier-1: чисто локальный (`STORAGE_MODE=local`) | `["local"]` | `null` |
  | Tier-2: «сам себе оператор» (`full + PAYMENT_MODE=none`) | `["local","participate"]` | `{amount_cents: 0, payment_methods: []}` |
  | Tier-3: чужой оператор (`full + x402` / `balance`) | `["local","participate"]` | `{amount_cents: N, payment_methods: ["x402",…]}` |

  **Запрос `participate` на сервере, который его не умеет — типизированная
  ошибка, не тихий downgrade в `local`.** Форма:

  ```jsonc
  // sign_memory { mode: "participate" } против tier-1 сервера →
  // JSON-RPC error
  {
    "code": -32010,
    "message": "Unsupported mode",
    "data": {
      "kind": "UnsupportedMode",
      "requested": "participate",
      "supported": ["local"]
    }
  }
  ```

  Пользователь явно попросил вынести в сеть — молча оставить локально нельзя:
  это сломало бы инвариант «delivered = anchored AND verified by recall» (ничего
  не доставлено, а ошибки нет). Клиент должен либо повторить запрос с
  `mode: "local"` осознанно, либо переключиться на другой сервер.
- **Совместимость с shipped `work/chrome-extension/`.** Поле `mode` —
  **optional, default `local`**. Существующий extension его не шлёт и
  продолжает работать как сейчас: Local-тир = пишет в IndexedDB локально,
  Cloud-тир = deferred signing к hosted `STORAGE_MODE=full` (тот же HTTP-
  контракт, что и сегодня). Сервер для запросов без `mode` ведёт себя по
  env-var — никакой принудительной смены семантики для не-обновлённых
  клиентов. Браузерная витрина и эта фича развиваются параллельно, не
  блокируют друг друга.

## Зачем

1. **Соответствие whitepaper, которого сейчас нет.** Whitepaper обещает
   operator pluralism и «migrate across operators or drop back to raw self-
   hosting». Сегодня режим — глобальный рубильник оператора: пользователь не
   может на одном сервере держать часть памяти приватной и бесплатной, а часть
   — вынесенной и заякоренной. Спектр выше — это и есть обещанный pluralism.
2. **Бесплатность личной памяти перестаёт зависеть от чужих настроек**
   (инвариант №1). Сегодня твоя личная заметка стоит денег, если ты случайно
   попал на оператора в `full`-режиме; после — нет.
3. **Открывает дорогу к настоящему обмену (issue #28, #29).** «Вынос в сеть» —
   входная точка marketplace/обмена. Чтобы обмен был честным, нужна не просто
   запись в Arweave, а **гарантия доставки** (инвариант про recall). Фича
   вводит само понятие «участие = durability + delivery» и точку, куда встанет
   биллинг.

## Не делаем (out of scope этой итерации)

- **Изменения в `packages/extension/`.** Браузерное расширение держим
  **совместимым** (см. инвариант), но **не трогаем** код в этой таске. Любые
  «как сделать в браузере лучше» (direct-to-chain из браузера, no-embedder,
  native-messaging bridge, OPFS-SQLite, и т.п.) — не наш предмет здесь. Это
  будущая отдельная работа на стороне `work/chrome-extension/`.
- **Приватный durable cloud-mirror как третий mode.** Когда такой mirror
  появится — он будет **поверх якоря**, а не вместо: artefact всё равно
  anchored on Arweave/Solana (там и живёт verifiability), а private cloud
  лишь добавляет удобный re-fetch с других устройств владельца. До тех пор
  V1-API остаётся бинарным `local | participate`; никаких `target` /
  `visibility` полей в этой итерации не вводим, чтобы не приколачивать гвоздями
  ещё не существующий tier.
- **Pluggable signer alg / chain-pluggable anchor** (issue #29) — отдельный
  арк. Здесь signer = Ed25519, anchor = Arweave + Solana.
- **Полная биллинг-поверхность** (top-up UX, refund-флоу) — issue #28. Здесь
  вводим *развилку* «бесплатно local / платно participate» + точку подключения
  биллинга, но не реализуем кошелёк целиком.
- **Шифрование / directed exchange конкретному получателю** — будущий арк
  (A2A-мост). Публичный вынос в V1 — открытые подписанные байты (ERC-8004-
  shape).
