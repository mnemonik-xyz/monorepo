# Task 13: SEO — webapp-side prerender of /blog/:slug + dynamic sitemap

## Required Skills

- `/skill:code-writing` — [SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Real crawl coverage for dynamic blog content (decisions.md Q3/Decision 4, REVISED
2026-06-27). The webapp and mcp server are SEPARATE deployments (Decision 9): the mcp
server stays a headless JSON API and does NOT render HTML. Crawlable `/blog/:slug`
pages are produced on the **webapp side at build time** by fetching `GET /blog` from
the API and emitting one static HTML file per post. A publish webhook triggers a
rebuild so newly agent-published posts get crawlable HTML within minutes.

## What to do

- Extend the build-time prerender from task 12: after fetching `GET ${VITE_MCP_BASE}/blog`,
  generate a static HTML file for each post slug (`/blog/<slug>.html` or framework
  equivalent) containing `<title>`, meta description, canonical, OG tags, Article
  JSON-LD, and the rendered post body — so crawlers see content without executing JS.
  The SPA still hydrates for humans.
- Generate `sitemap.xml` at build time (webapp `public/` or build output) listing the
  static routes plus every published post slug fetched from `GET /blog`. This replaces
  the static placeholder `public/sitemap.xml` from task 5.
- Publish-freshness: read a deploy-hook URL from an env var (e.g. `BLOG_REBUILD_HOOK`);
  on a successful `POST /blog` / `mnemonic_publish_post` (task 9), the server pings it to
  trigger a webapp rebuild. If unset, posts appear on the next scheduled build (document
  this). Keep the trigger out of `core/` (CLAUDE.md rule 1) — it lives in `mcp/`.
- Render markdown to HTML safely at build time (reuse the webapp's existing
  `react-markdown`/`remark-gfm` or a sanitizing renderer); HTML-escape to avoid stored-XSS
  from agent-published markdown. Keep CSP intact (no new origins).

## TDD Anchor

- prerendered `/blog/<slug>.html` contains the post title, meta description, and body text in raw HTML.
- generated `sitemap.xml` includes published slugs; valid XML.
- build-time markdown render sanitizes/escapes raw HTML (no script injection from post body).

## Acceptance Criteria

- [ ] Each published post yields a static HTML file with correct head + content (no JS needed)
- [ ] `sitemap.xml` includes post slugs; valid XML
- [ ] Build-time markdown sanitized/escaped; no stored XSS
- [ ] `POST /blog` success pings the rebuild hook when `BLOG_REBUILD_HOOK` is set (no-op when unset)
- [ ] `cd webapp && npm run build` green; `cargo test -p mnemonic-mcp` green

## Details

**Files:** webapp build/prerender script (extends task 12), webapp/public/sitemap.xml (or build output),
mcp/src/api.rs (rebuild-hook ping on publish only — NO HTML rendering in mcp)
**Dependencies:** task 8 (post JSON data), task 10 (RSS/discovery), task 12 (static prerender baseline)
**Edge cases:** unknown slug → SPA 404; very long posts; markdown with raw HTML (must be sanitized);
empty post list → sitemap with static routes only; hook URL unset → skip ping
**Implementation hints:** keep the mcp server headless — it only emits JSON + (optionally) pings the
deploy hook. All HTML generation is webapp-side. Do not duplicate the SPA shell; reuse the prerender
pipeline from task 12.
