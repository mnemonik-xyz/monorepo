# Task 8: MCP read routes — artifacts, analytics, blog

## Required Skills

- `/skill:code-writing` — [SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Public, unauthenticated read endpoints in `mcp/` that back the Ledger, Analytics, and
Blog pages. All domain types come from `mnemonic_core::`; payment methods stay in
`payment.rs`. Response shapes match the frontend clients exactly.

## What to do

- Add handlers (pattern: `public_stats_handler` in `mcp/src/api.rs`) and register in `main.rs`:
  - `GET /artifacts?q=&limit=` → `{ artifacts:[...], total }`, `visibility=public` ONLY; shape = `lib/ledger.ts` `Artifact`.
  - `GET /analytics/attestations?range=30d|90d|12m` → `{ buckets:[{date,on_node,on_chain}], total_on_node, total_on_chain, unique_users }`.
  - `GET /blog` → `{ posts:[...] }` and `GET /blog/:slug` → `{ post }`; shape = `lib/blog.ts` `BlogPost`; unknown slug → 404.
- Storage via Mutex; never hold the lock across `.await`. No payment gating on these reads.

## TDD Anchor

- `/artifacts` returns only public rows and matches shape.
- `/analytics` buckets/totals correct per range.
- `/blog` + `/blog/:slug` return expected JSON; unknown slug → 404.

## Acceptance Criteria

- [ ] Three read routes registered + working, shapes match frontend clients
- [ ] `/artifacts` is public-only
- [ ] Unknown blog slug → 404
