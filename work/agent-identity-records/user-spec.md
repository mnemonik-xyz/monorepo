# User Spec: Agent identity records — Mnemonik как источник идентичности агентов

## Что делаем

Владелец агента публикует через Mnemonik самоподписанную запись идентичности
агента. Любой может по идентификатору получить и проверить текущий ключ подписи,
ключ шифрования, адреса сервисов, AgentCard и привязанные адреса в блокчейнах.

## Зачем

- Сегодня для запечатанного A2A нужно обменяться AgentCard и доверенным ключом
  вне протокола. Теперь достаточно знать идентификатор агента.
- Ротация ключей появляется впервые; старые подписи остаются проверяемыми.
- Ни оператор Mnemonik, ни площадка не могут подменить ключ агента.

## Как работает (коротко)

- Идентификатор — хеш первой записи (он фиксирует первый ключ и хеш следующего
  ключа). Записи образуют цепочку (`seq`, `prev`) и якорятся в Arweave.
- Каждая запись заранее фиксирует хеш следующего ключа. Укравший текущий ключ
  не может перехватить идентичность: владелец ротирует ключ заранее
  зафиксированным следующим ключом, и ротация побеждает.
- Mnemonik хранит индекс, но не является авторитетом: он может скрыть запись, но
  не подделать её. Цепочку проверяет клиент.
- Ротация требует следующего ключа, который владелец хранит вне хоста агента.
  Обновления подписывает текущий ключ; отзыв текущим ключом — предварительный,
  ротация его отменяет. Через MCP агент может только читать
  (`mnemonic_resolve_agent`).
- Записи подписываются с отдельным типом содержимого, поэтому подпись из другого
  потока Mnemonik не может стать записью идентичности.

## Критерии готовности

- `mnemonic agent init/publish/rotate/revoke/show` работают на тестовой сети.
- Отправитель запечатанного A2A указывает только `id` получателя.
- Каждое правило цепочки покрыто тестом, включая кражу текущего ключа.

## Чего не делаем в версии 1

- Поручительства (endorsements), зеркало в ERC-8004, свидетели — запланировано.
- Поиск агентов по возможностям — только разрешение по `id`.
