# Task 6: Hosted sealed write path and "private" label fix

## Description

Make `visibility: private` (the default) mean encrypted on the hosted
server, for `local` and `participate` writes (tech-spec §4, §8.1, §8.3).
Fix finding F1.

## What to do

1. `resolve_visibility` (`mcp/src/tools.rs:214-237`): allow `private` on
   `local` writes; keep rejecting `public` on `local`.
2. `sign_memory_deferred` (`mcp/src/tools.rs:877-919`): for `private`, build
   inner MEMORY_V1, call `sealed::seal_memory` with the owner public key, park
   only the outer CBOR. Zeroize plaintext, inner CBOR and `K`. Do not keep
   the embedding.
3. `PendingBundles` (`mcp/src/pending.rs`): a sealed entry carries no
   `content` and no `embedding`.
4. Sign-callback (`mcp/src/api.rs:560-790`): upload sealed COSE with tag
   `Mnemonic-Type: sealed`; memo `v: 3`; save with `save_sealed_attestation`.
   Delivery check uses the outer hash. Remove the hard-coded
   `Visibility::Private` (`api.rs:782`); use the value from the pending entry.
5. Hosted `local` + `private`: seal inline with the owner public key, save a
   sealed row. No signature, no keychain, no round-trip.
6. F1 (D-8): run `relabel_plaintext_anchors()` at startup once; API and
   recall responses for those rows show `visibility: public`,
   `plaintext_on_arweave: true`.
7. D-7: migration command `mnemonic-mcp seal-local-rows` (seal in place, then
   `VACUUM`). Document backup rotation in `docs/deployment` notes.
8. Never log plaintext, `K` or inner CBOR. Add a test that scans captured logs.
9. Docs: `docs/tools.md`, `docs/how-it-works.md`, `docs/WHITEPAPER.md` §5 and §8.2,
   `AGENTS.md`, CLAUDE.md "Data flow" and "Write modes".
