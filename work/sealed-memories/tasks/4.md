# Task 4: SQLite migration for sealed rows and grants

## Description

Store sealed rows and grants (tech-spec §10). All SQL stays parameterized in
`core/src/storage/sqlite.rs`.

## What to do

1. Migration: `attestations.privacy TEXT NOT NULL DEFAULT 'plaintext'`
   (`plaintext` | `sealed`), `attestations.sealed_blob BLOB`.
2. New table `grants(id, memory_hash, reader_kid NULL, grant_cose BLOB, author_pubkey, created_at, withdrawn_at NULL)` with indexes on `memory_hash` and `reader_kid`.
3. Tables for tech-spec §7.4 (used only by task 13; create now to avoid a
   second migration): `owner_recall_keys(owner_pubkey, rk_wrap BLOB)`,
   `sealed_index(attestation_id, k_wrap_rk BLOB, emb_nonce BLOB, emb_ct BLOB)`.
4. `save_sealed_attestation(...)`: `content = ''`, no `attestation_embeddings` row.
5. `list_sealed(owner, since, limit)`, `save_grant`, `grants_for_reader`,
   `grants_for_memory`, `withdraw_grant`.
6. Vector search skips `privacy = 'sealed'` rows. Add `count_sealed(owner)`.
7. Data fix for F1 behind a function `relabel_plaintext_anchors()`: anchored
   rows with `visibility = 'private'` get `privacy = 'plaintext'` (task 6 runs it).

## TDD anchors

- Migration is idempotent on an existing database.
- A sealed row never appears in vector search results.
- `grants_for_reader` returns only non-withdrawn grants.

## Acceptance

- `cargo test -p mnemonic-core storage` passes. Clippy clean.
