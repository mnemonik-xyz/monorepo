# Task 10: MCP routes and tools for sharing and E2E writes

## Description

Server surfaces for E2E clients and sharing (tech-spec §7.3, §8.2, §8.4).
The server never receives `K` or plaintext on these paths (except `/api/embed`).

## What to do

1. `POST /api/anchor-sealed`: body = signed sealed COSE. Check signature,
   `producer == did:sol:<jwt.sub>`, payment or free quota (logic stays in
   `mcp/src/payment.rs`), then upload, memo, delivery check, save.
2. `POST /api/store-sealed`: unsigned outer CBOR for `local`; owner = `jwt.sub`.
3. `GET /api/sealed?since=&limit=`: the caller's own sealed blobs.
4. `POST /api/grants` (signed GRANT_V1, author = `jwt.sub`),
   `GET /api/grants?reader=<kid>`, `DELETE /api/grants/{id}` (withdraw).
5. `POST /api/embed` (D-4): returns a vector; never stores or logs the text.
6. Tool `mnemonic_share {memory_hash, reader}`: returns `awaiting_signature`
   with `approve_url` (webapp makes the grant in the browser).
7. `mnemonic_recall`: add `sealed_hidden` count and a hint.
   `mnemonic_verify`: sealed-aware (`sealed: true, readable: false`).
8. Register the tool in `mcp/src/mcp.rs`; update `docs/tools.md` and the
   tool count in CLAUDE.md.

## TDD anchors
