# Task 8: Webapp — approve decrypt, sealed view, links, grants

## Description

Browser surfaces for sealed memories. The browser holds the key; the server
never gets `K` or plaintext (tech-spec §8.1, §8.4, §8.5).

## What to do

1. Approve page: for a SEALED_V1 bundle, decrypt in the browser and show the
   text before the user signs. Show "encrypted, only you can read it".
2. `/m/<hash>` sealed view: author, date, "Signature valid", "Sealed". If the
   URL has `#k=`, verify `kc` and decrypt locally. Load no third-party
   scripts on this route. Never send the fragment in any request or log.
3. Share dialog: grant to a DID / AgentCard / X25519 key, or make a link.
   Show the no-revocation warning (tech-spec §5.5) before confirming.
4. Grant approve flow for `mnemonic_share` (`approve_url`).
5. Label F1 rows "Published before encryption existed. Readable on Arweave."
6. Playwright: the network log contains no request with `K`.
