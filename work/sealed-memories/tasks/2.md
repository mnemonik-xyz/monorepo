# Task 2: SEALED_V1 and GRANT_V1 schemas

## Description

Register two new artifact schemas in `core/src/codec/schema.rs` (tech-spec
§6.1, §6.5). Do not change `MEMORY_V1`. Add a verification helper that checks
a sealed or grant COSE_Sign1 without any key (§6.4).

## What to do

1. `SEALED_V1`: type `sealed`, version 1, required fields and canonical order
   `artifact_id, type, schema_version, alg, nonce, ct, kc, wraps, created_at, producer`.
2. `GRANT_V1`: type `grant`, version 1, fields `type, schema_version,
   memory_hash, reader (optional), enc, wk, perms (optional), created_at, producer`.
3. Add `("sealed", 1)` and `("grant", 1)` to the schema lookup (`schema.rs:414`).
4. Byte-string fields (`nonce`, `ct`, `kc`, `enc`, `wk`) encode as CBOR bstr,
   not base64 text. Check that `to_canonical_cbor` supports bstr; extend it if not.
5. `codec::sign::verify_sealed(cose_bytes) -> SealedVerification {producer, content_hash, created_at, wrap_count}`.
   It checks the signature and the `kid` = `producer` match. It never decrypts.
6. Update `docs/YELLOWPAPER.md` schema section (mark "planned" until task 6 ships).

## TDD anchors

- Field order is stable; missing required field is rejected.
- `verify_sealed` fails for a changed `ct` byte and for a `kid` that does not match `producer`.
- Existing MEMORY_V1 golden fixtures are unchanged.

## Acceptance

- `cargo test -p mnemonic-core codec` passes. Clippy clean.
