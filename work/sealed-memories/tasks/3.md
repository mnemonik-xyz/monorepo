# Task 3: Seal, open, grant and link API with golden vectors

## Description

Compose tasks 1 and 2 into the high-level API used by the server, WASM and
clients (tech-spec §6, §8.4, §8.5).

## What to do

1. `sealed::seal_memory(inner_memory_json, author_ed25519_pub, rng) -> SealedArtifact`
   (outer canonical CBOR, `content_hash`, and `K` in `Zeroizing`). Inner
   `producer` and `artifact_id` are copied to the outer artifact.
2. `sealed::open_memory(outer_cbor, x25519_secret) -> inner_memory_json`.
   Checks: `kc`, AEAD, inner `producer` and `artifact_id` equal outer.
3. `sealed::open_with_key(outer_cbor, K)` for bearer links and grants.
4. `sealed::make_grant(memory_hash, outer_cbor, K, reader_pk, author_did, perms?)`
   returns unsigned GRANT_V1 CBOR. `sealed::open_grant(grant, x25519_secret) -> K`.
   Anonymous grant: `reader` omitted.
5. `sealed::link_fragment(K) -> "k=<base64url>"` and parser.
6. `core/src/rebuild.rs`: `rebuild_sealed_row(cose_bytes, x25519_secret)`.
7. Golden vectors in `core/tests/golden_fixtures.rs` (`golden-fixtures` feature):
   fixed identity, `K`, nonce, HPKE ephemeral seed → outer CBOR, content hash,
   grant CBOR. Emit JSON for the SDK and extension.
8. Streams helper for #242: `seal_chunk(K, stream_prefix, index, last, ad)`
   and `open_chunk` (tech-spec §9.4).

## TDD anchors

- Seal then open equals input for random inputs (proptest).
- Non-recipient gets `NotARecipient`. A grant signed by another key is rejected by the caller helper.
- Reordered, dropped or truncated chunks fail.
- Golden bytes stable across two runs.

## Acceptance

- Tests pass, including `--features golden-fixtures`. Clippy clean.
