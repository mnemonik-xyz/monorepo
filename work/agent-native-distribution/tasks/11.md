# Task 11: Test Audit

## Required Skills

- `/skill:test-master` — [skills/test-master/SKILL.md](~/.claude/skills/test-master/SKILL.md)

## Description

Full-feature test quality audit across all test files created by Tasks 1-8. Analysis-only; findings trigger a fixer + reviewer cycle if needed.

## What to do

Verify the test suite actually exercises the production code paths it claims to cover, that assertions are behavioral (not structural-only), and that pyramid balance is appropriate for an L-sized feature.

- **Per-AC coverage**: enumerate AC1-AC17 from user-spec + technical ACs from tech-spec; verify each has at least one test that triggers the condition and asserts the documented behavior. Specifically:
  - AC1 anonymous discovery — Task 2's `discovery_anonymous` integration tests, byte-for-byte manifest snapshot check (NOT substring "Purpose" check).
  - AC3 offline local sign — Task 5's `unshare -rn` netns isolation test, with `ss -tn` + `strace` proving zero outbound connections.
  - AC4 local recall finds local-written — Task 3 or 4's round-trip test (embed → store → search → top-1).
  - AC5/AC6 soft-fall semantics — Task 5's four sub-cases including the Decision 4+5b interaction (visibility re-resolution after escalation).
  - AC11 OAuth-loopback + cached-token reuse — Task 6's three sub-cases: fresh-install, expired, corrupted.
  - AC13 visibility-respecting anonymous recall — Task 4's seeded-DB test.
  - AC14 visibility-on-local rejection — Task 4.
  - AC15 embedder version surface — Task 2 + Task 5's mismatch warning E2E.
  - AC16 error catalogue — Task 4's parametrized test over all 12 rows; verify each row's trigger fixture is actually a production code path, NOT a hand-crafted response stub.
  - AC17 doctor — Task 7's parametrized failure cases for all 6 doctor checks.
- **Test pyramid balance**: ~7-12 unit tests, ~12-15 integration tests, 2-3 E2E. Verify not over-mocked at integration level (e.g., integration test that wiremocks 90% of dependencies isn't really integration).
- **Behavioral vs structural assertions**: each test asserts on a concrete result (return value, error code, file contents, DB row, mock call count) — not just "function was called" or "no exception thrown".
- **Litmus test for empty-test anti-pattern**: imagine the implementation is replaced with `unimplemented!()` or `throw new Error("not implemented")`. Does each test fail? If a test still passes against `unimplemented!()`, it's an empty test.
- **HMAC confirmation token tests** (Task 4): cross-owner replay (sub-case f) is present and verifies that `claims.sub` is what gets checked at consume — not just HMAC reconstruction. Concurrent consume race (sub-case g) uses `tokio::Barrier` or similar to force simultaneous execution.
- **Parametrized error catalogue** (Task 4): each row's trigger is the production code path (held SQLite lock, broken embedder, etc.), not "send malformed JSON and assert -32602". A row passes the litmus test only if removing the production code that surfaces that error causes the row's assertion to fail.
- **Doctor tests** (Task 7): the 6 parametrized failure cases each induce the failure via the production code path (corrupt the cached binary file, mock the /health response to return 503, deny keychain access, hold a SQLite write lock). NOT by mocking the doctor's check functions to return failure.
- **netns isolation** (Task 5, AC3): `unshare -rn` is used (NOT `--offline` flag or absence of network interface alone). `ss -tn state established` inside the netns shows zero. `strace -e trace=connect` records zero non-loopback `connect()` calls.
- **Snapshot tests** (Task 2 AC1): manifest content is checked byte-for-byte against the source `.md` files (NOT just "contains 'Purpose'" substring). Placeholder token check (TBD/TODO/XXX/FIXME) is present.
- **Install tests** (Task 7): mtime-unchanged assertion for `--check` mode is genuine mtime check (not just absence of write spy). Symlink-out-of-home refusal is tested with an actual symlink fixture, not just argument validation.
- **Smoke tests**: each task's Verify-smoke is deterministic (no "if available" qualifiers), reproducible on a clean machine.

Write the audit report to `work/agent-native-distribution/logs/working/task-11/audit-report.md` with severity, file:line citations of test files, and concrete fix recommendations for each finding.
