# Task 6: Token-file access for Rust binary + TokenExpired typed error

## Required Skills

- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Add a new `core/src/identity/token_store.rs` module that exposes file-based read/write/delete helpers for `~/.mnemonic/token.json` — the same file written by the existing Node CLI at `packages/cli/src/config.ts:39-65`. Honor `expires_at` from the JWT claim — return typed `-32099 TokenExpired` when current time exceeds it. Update Rust callsites in `mcp/src/oauth/mod.rs` to delegate to the new helpers. **No keychain wrapper** for tokens in v1 per Decision 7. **Node CLI is unchanged** in v1 — both runtimes continue to share the existing file path; the Rust binary just gains a typed reader/writer instead of inline file I/O.

## What to do

- Create `core/src/identity/token_store.rs` with:
  - `pub fn token_path() -> PathBuf` — returns `dirs::home_dir().unwrap().join(".mnemonic/token.json")`.
  - `pub struct TokenJson { pub jwt: String, pub expires_at: String, pub sub: String }` — mirrors the Node CLI's shape at `config.ts:39-65` exactly (`expires_at` is **ISO-8601 string**, NOT unix-seconds int — see `config.ts:42` and the validator at `config.ts:354` that asserts `typeof o.expires_at === "string"`). Parse via `DateTime::parse_from_rfc3339(&token.expires_at)` for comparisons.
  - `pub fn read_token() -> Result<Option<TokenJson>, TokenStoreError>` — returns `Ok(None)` on file-not-found or malformed JSON (NOT a panic per Round 3 test review); returns `Ok(Some(token))` on success; returns `Err(TokenStoreError::Expired)` when `expires_at < now()`.
  - `pub fn save_token(token: &TokenJson) -> Result<(), TokenStoreError>` — atomic write via tempfile + rename in the same directory; mode 0o600 on Unix.
  - `pub fn delete_token() -> Result<(), TokenStoreError>` — `std::fs::remove_file()` ignoring NotFound (idempotent for Task 5's logout subcommand).
- Add `enum TokenStoreError { Expired, Io(io::Error), Parse(serde_json::Error) }`. Implement `Display` and `From<io::Error>`/`From<serde_json::Error>`.
- Add public type re-export in `core/src/identity/mod.rs`.
- Update callsites in `mcp/src/oauth/mod.rs` that currently do inline token I/O (search for `token.json` references — code-research §5 says Rust binary doesn't read/write the file today, so this should be additive: add new callsites where the binary needs to *cache* tokens after OAuth-loopback). Look for the OAuth callback / token-exchange completion path and persist via `token_store::save_token`. Look for the JWT validation path that today reads from `Authorization` header — add a fallback to `token_store::read_token` when no header is present and we need to authenticate the binary's own subsequent calls.
- The Node CLI (`packages/cli/`) is **NOT modified** in v1 — both runtimes share `~/.mnemonic/token.json` via their respective I/O paths.
- Map `TokenStoreError::Expired` → `-32099 TokenExpired { expires_at, pubkey }` at the JSON-RPC boundary (use Task 4's new error helper).

**Edge cases:**
- HOME env var unset — `dirs::home_dir()` returns None → `Err(TokenStoreError::Io(...))` with clear message.
- File written by Node CLI v0.2.x — same path, same shape, no migration. Rust binary reads it. Future versions may diverge; out of scope for v1.
- Concurrent writes from Rust binary and Node CLI — atomic tempfile+rename means whichever finishes second wins; neither sees a corrupt file. Acceptable for v1 because tokens are short-lived and re-OAuth is cheap.
- `expires_at` 0 or negative — treat as already expired (returns Expired).
- Tokens written by tests must NOT pollute the real `~/.mnemonic/token.json` — use `XDG_CONFIG_HOME` override or temp-HOME pattern in test setup.

**Implementation hints:**
- Reuse `NamedTempFile` + `persist()` from `tempfile` crate (already in workspace) for atomic write. Set mode AFTER persist via `std::os::unix::fs::PermissionsExt::set_mode(0o600)`.
- For JSON: `serde_json::from_str` + `serde_json::to_string_pretty` (pretty matches Node CLI's existing output format).
- For the OAuth callback hookup in `mcp/src/oauth/mod.rs`: find the function that completes the OAuth code-exchange and constructs the user-facing JWT response. Add a `token_store::save_token(&TokenJson { jwt: response.access_token, expires_at: response.expires_at, sub: claims.sub })` call right after the JWT is minted (server-side persists for its own future authenticated calls).
- Time source: use `chrono::Utc::now()` to compare against the parsed `DateTime::parse_from_rfc3339(&expires_at)`. Provide a test seam via a `now_fn` parameter if needed; the expired-token unit test uses ISO-8601 timestamps in the past, no time-source override required.
