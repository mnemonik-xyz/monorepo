# Task 3: visibility column migration + Visibility enum + storage signatures

## Required Skills

- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Add a new `Visibility` enum (Private | Public) to `core/src/storage/mode.rs` (the same module that hosts `WriteMode`), with idempotent `migrate_visibility_column()` mirroring the existing `migrate_write_mode_column` precedent at `sqlite.rs:282-350`. Extend the `AttestationStore::save_attestation` trait signature (and the SQLite impl) with `visibility: Visibility`. Extend `search` with optional `visibility_filter`. Wire migration into both `SqliteStore::open` and `SqliteStore::in_memory`. **Do not** touch the existing WAL + `busy_timeout=5000` configuration at `sqlite.rs:371` — Decision 13 explicitly reuses what is already there.

## What to do

- Add `pub enum Visibility { #[default] Private, Public }` to `core/src/storage/mode.rs` (alongside `WriteMode`). Implement `Display`/`FromStr` mirroring `WriteMode` exactly. Add serde impls. Add a `serialize_to_sqlite` / `from_sqlite_str` pair if needed for rusqlite codec compatibility.
- Add `migrate_visibility_column()` to `core/src/storage/sqlite.rs` immediately below `migrate_write_mode_column` (around line 350). Copy structure verbatim: `attestations_has_column` probe via `PRAGMA table_info(attestations)`, `BEGIN IMMEDIATE`, conditional `ALTER TABLE attestations ADD COLUMN visibility TEXT NOT NULL DEFAULT 'private'`, backfill UPDATE (no-op on already-populated rows), `CREATE INDEX IF NOT EXISTS idx_attestations_visibility ON attestations(visibility)`, COMMIT/ROLLBACK.
- Wire `migrate_visibility_column(&conn)?;` into both `SqliteStore::open` (around line 378, right after the existing `migrate_write_mode_column` call) and `SqliteStore::in_memory` (around line 394).
- Extend `AttestationStore::save_attestation` trait signature in `core/src/storage/traits.rs:57` to accept `visibility: Visibility` as a new positional argument before `embedding`. Update the SQLite impl at `sqlite.rs:488-532` — extend the INSERT column list and `params!` tuple. Pass `visibility` through from `SqliteStore::save_attestation` callers (the rest is Task 4's domain).
- Extend `core/src/storage/sqlite.rs:596-653` (`search`) to accept an optional `visibility_filter: Option<Visibility>`. When `Some(v)`, append `AND a.visibility = ?` to the WHERE clause. `SearchResult` struct gains a `visibility: Visibility` field.
- Export `Visibility` from `core/src/storage/mod.rs` alongside `WriteMode`.

**Edge cases:**
- `Visibility::from_str("Public")` (capital P) — `WriteMode::from_str` is case-sensitive per the existing impl; mirror that strict behavior. Anything other than `"private"` or `"public"` returns `Err`.
- Test DB seeded with `visibility` already present via `CREATE TABLE` in `lib.rs` — migration's `attestations_has_column` probe returns `true`, ALTER is skipped, COMMIT is a no-op. Verify the second open does not panic.
- `search` called with `Some(Visibility::Private)` — supported (authenticated owner can search their own private rows). Filter clause works for both variants.

**Implementation hints:**
- Follow `migrate_write_mode_column`'s 7-step recipe at `sqlite.rs:282-350` literally — including the `BEGIN IMMEDIATE` for concurrent-opener safety and the COMMIT/ROLLBACK envelope.
- Use the index `idx_attestations_visibility ON attestations(visibility)` — single-column. Composite indexes are not needed because `recall` filter is on visibility alone (`bearer_auth_middleware` already filters owner_pubkey via WHERE elsewhere).
- For the trait signature extension: `Visibility` must be `Send + Sync` (it's an enum, derives `Copy` — trivially so).
- Lock discipline (patterns.md): the migration holds `BEGIN IMMEDIATE` for the whole COMMIT path. No `.await` inside. This matches the existing migrate_write_mode_column pattern — do not add async.
