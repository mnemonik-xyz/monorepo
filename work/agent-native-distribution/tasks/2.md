## Description

Single owner of all `mcp/src/mcp.rs` edits in Wave 1 (per tech-spec wave-conflict resolution). Add four new MCP dispatcher arms (`prompts/list`, `prompts/get`, `resources/list`, `resources/read`) consuming the build-time manifest constants from Task 1. Extend `initialize` response capabilities (`prompts: {}`, `resources: {}`) and add `embedder: { model_id, model_version, dim }` derived from `state.embedder`. Enrich every entry in `tool_definitions()` description by appending the corresponding manifest's `Purpose+Trigger` section. Extend `ALLOWLIST_METHODS` in `oauth/mod.rs` so the four new discovery methods are anonymous-OK.

## What to do

- In `mcp/src/mcp.rs:519-547` (`handle_request_with_resolved_mode` dispatcher): add four new arms — `"prompts/list"`, `"prompts/get"`, `"resources/list"`, `"resources/read"`. Each returns MCP-spec-conformant JSON built from the build-time constants generated by Task 1.
- In `mcp/src/mcp.rs:526` (`initialize` arm): extend `capabilities` to include `prompts: {}` and `resources: {}`. Add new `embedder: { model_id, model_version, dim }` field at the response root. Source values from `state.embedder.model_id()` (existing trait method at `core/src/embed/mod.rs:10`), `state.embedder.dim()` (existing trait method), and a NEW compile-time-baked `EMBEDDER_MODEL_VERSION: &str` constant defined in `mcp/src/lib.rs` and set to `concat!(env!("CARGO_PKG_VERSION"), "-fastembed-", core::embed::FASTEMBED_VERSION)` so the value is deterministic per-build and includes the crate's pinned fastembed version (a separate `pub const FASTEMBED_VERSION: &str = "5.x.y"` constant added to `core/src/embed/mod.rs` matching the actual pinned version from `core/Cargo.toml`). The `Embedder` trait does NOT have a `model_version()` method today; we expose the version at the binary level rather than per-impl.
- In `mcp/src/mcp.rs:427-497` (`tool_definitions()`): for each of the 6 existing tools (whoami, sign_memory, verify, prove_identity, recall, check_pending), append the corresponding manifest's `PURPOSE_PLUS_TRIGGER` to the existing `description` field. Drift between manifest body and tools/list description is now physically impossible (single markdown source).
- In `mcp/src/oauth/mod.rs:1235`: extend `const ALLOWLIST_METHODS: &[&str]` from `["initialize", "tools/list", "ping"]` to also include `"prompts/list"`, `"prompts/get"`, `"resources/list"`, `"resources/read"`.
- Update the comment block at `oauth/mod.rs:1226-1234` to reflect the four new allowlisted methods.
