# Task 14: Post-deploy verification

## Required Skills

- `/skill:post-deploy-qa` — [skills/post-deploy-qa/SKILL.md](~/.claude/skills/post-deploy-qa/SKILL.md)

## Description

Live-environment verification against the production `mcp.mnemonik.xyz` server (post-Task-13 redeploy) and the published `@mnemonik-xyz/mcp` npm package. Walk the four user flows from user-spec "Как должно работать" against the live deploy.

## What to do

- **Hosted-server discovery smoke (anonymous):**
  - Run `npx @modelcontextprotocol/inspector https://mcp.mnemonik.xyz/mcp` and visually verify the prompts list, resources list, and enriched tool descriptions look correct (no truncation, no placeholder tokens). Screenshot to `work/agent-native-distribution/logs/working/task-14/inspector.png` for the release checklist.
  - Also: `curl -X POST https://mcp.mnemonik.xyz/mcp -H 'Content-Type: application/json' -d '{"jsonrpc":"2.0","id":1,"method":"prompts/list","params":{}}' | jq '.result.prompts | length'` → `7`.
  - `curl -X POST https://mcp.mnemonik.xyz/mcp -H 'Content-Type: application/json' -d '{"jsonrpc":"2.0","id":2,"method":"resources/list","params":{}}' | jq '.result.resources | length'` → `7`.
  - `curl -X POST https://mcp.mnemonik.xyz/mcp -H 'Content-Type: application/json' -d '{"jsonrpc":"2.0","id":3,"method":"initialize","params":{}}' | jq '.result.embedder'` → non-empty object with `model_id`, `model_version`, `dim`.
- **Anonymous recall against production DB:**
  - Pre-seed a known public attestation via an authenticated `sign_memory { mode: "participate", visibility: "public", content: "post-deploy-fixture <UUID>", ... }` call (use a maintainer JWT or run the test as a logged-in dev). Capture the `attestation_id`.
  - Anonymously: `curl -X POST https://mcp.mnemonik.xyz/mcp -H 'Content-Type: application/json' -d '{"jsonrpc":"2.0","id":4,"method":"tools/call","params":{"name":"mnemonic_recall","arguments":{"query":"post-deploy-fixture <UUID>","limit":5}}}' | jq '.result.results[0]'` → should match the seeded attestation_id.
  - Pre-seed another private attestation with the same query string. Anonymous recall must NOT return it.
- **Fresh-machine install smoke (manual, ~10 min):**
  - On a clean macOS machine (ideally a brand-new user account or a fresh VM):
    1. `npm install -g @mnemonik-xyz/mcp` — verify install succeeds, no postinstall warnings.
    2. `mnemonik-mcp install --check` — verify shows the install plan against any host configs present, mtime unchanged afterward.
    3. `mnemonik-mcp install` — verify writes entries, output ends with `If any of these agents is already running, please restart them.`.
    4. Open Claude Code (or Cursor or Claude Desktop). Verify mnemonik tools appear in the `/mcp` menu or equivalent.
    5. In an agent session, ask "What can mnemonik help me with?" — agent should reach for the help skill and respond with the manifest content (verifies skill propagation reached the host).
    6. Try airplane mode (turn off WiFi). Ask the agent to attest a local thing. Verify the local sign succeeds via `~/.mnemonic/attestations.db` row appearing with `write_mode='local'`.
- **Doctor on the fresh machine:**
  - `mnemonik-mcp doctor` — verify all 6 checks pass on the fresh machine (host config: configured; mcp.mnemonik.xyz/health: ok; binary integrity: ok; local SQLite: rw; identity: accessible; token file: absent (= ok, will OAuth on first participate call)).
  - Corrupt one of the fixtures (e.g., overwrite the cached binary with random bytes) — verify doctor catches it: exit 1, binary-integrity check fail, repair hint present.
- **Production health checks:**
  - `curl -fsS https://mcp.mnemonik.xyz/health` → 200, `{"status":"ok"}`.
  - `ssh claude@<VPS> 'sudo systemctl status mnemonic-mcp'` → active (running), no restart loop (NRestarts=0).
  - `ssh claude@<VPS> 'sudo journalctl -u mnemonic-mcp --since "5 minutes ago" -p err'` → empty.

Write the verification report at `work/agent-native-distribution/logs/working/task-14/verification-report.md` with per-step pass/fail + screenshots/transcripts.
