# Task 13: Deploy (tag + publish)

## Required Skills

- `/skill:deploy-pipeline` — [skills/deploy-pipeline/SKILL.md](~/.claude/skills/deploy-pipeline/SKILL.md)

## Description

Tag a release and let GitHub Actions publish all artifacts: `mnemonic-mcp` binary tarballs + `SHA256SUMS` + attestation (per Task 8) to the GitHub Release, and `@mnemonik-xyz/sdk` + `@mnemonik-xyz/cli` + new `@mnemonik-xyz/mcp` to npm via Trusted Publishing. Also: redeploy the mcp.mnemonik.xyz VPS to pick up the new server-side changes (skill manifests + prompts/resources/initialize endpoints + visibility filter + confirmation gate). Update `packages/mcp/dist/binary-version.json` to point at the new tag so the shim downloads the matching artifacts.

## What to do

- **Sync `EMBEDDER_MODEL_VERSION` (process check per Task 2)**: verify the string literal in `mcp/src/lib.rs` matches `mcp/Cargo.toml` version + the fastembed version reported by `cargo tree -p fastembed | head -1`. Update the literal if Cargo.lock's fastembed version drifted since the last release. This is the only sync gate; missing it means `initialize.embedder.model_version` ships stale.
- Bump versions:
  - `mcp/Cargo.toml` (binary) — choose v0.2.0 or next semver based on existing release history; check `git tag -l 'v*'` for current state.
  - `core/Cargo.toml` (core lib, if its public API changed via the new Visibility export and trait sig change in Task 3 — semver minor at minimum).
  - `packages/sdk/package.json` — only if SDK changed (likely not for this feature).
  - `packages/cli/package.json` — only if CLI changed (likely not for this feature; Task 6 didn't modify it).
  - `packages/mcp/package.json` — first-time publish; start at the same version as the binary tag for consistency.
- Update `packages/mcp/dist/binary-version.json` to point at the new tag (e.g., `{"tag": "v0.2.0", "artifacts": {...}}`).
- Update CHANGELOG.md (if it exists; else create a brief entry under `work/agent-native-distribution/`).
- Pre-publish dry-run: `cd packages/mcp && npm pack --dry-run` — verify the tarball contents are correct (includes `dist/`, `package.json`, no extraneous files).
- **Verify Trusted Publishing for `@mnemonik-xyz/mcp`** is configured on npm.com — log in to npm.com, navigate to the package settings page once published, add `mnemonik-xyz/monorepo` workflow `release.yml` as a trusted publisher. **If this is a brand-new package not yet published**: first publish may need a one-time manual `npm publish` from a developer machine with valid credentials to "create" the package on the registry before Trusted Publishing can be added (npm requires the package to exist). This is the standard first-time gotcha; document if encountered.
- Commit version bumps + binary-version.json + CHANGELOG.
- `git tag v<x.y.z> && git push origin v<x.y.z>`. The push triggers release.yml.
- Watch CI: GitHub Actions tab. Confirm:
  - `build-linux` and `build-macos` succeed (per task 8 fixes; if Linux still has libdbus issues per user-spec R4, only macOS artifacts matter for v1).
  - `release` job emits `SHA256SUMS` and the attestation step succeeds.
  - `publish-npm` succeeds (sdk + cli skipped if no version change).
  - `publish-mcp-shim` succeeds (publishes new package).
- After CI green: redeploy mcp.mnemonik.xyz VPS:
  - `bash scripts/deploy/deploy-main-to-prod.sh` (SSH'd into the VPS, rebuilds + restarts the systemd service).
  - Watch the journalctl output for any startup errors.
  - Verify `curl -fsS https://mcp.mnemonik.xyz/health` returns `{"status":"ok"}`.
  - Verify the new methods are live: `curl -X POST https://mcp.mnemonik.xyz/mcp -H 'Content-Type: application/json' -d '{"jsonrpc":"2.0","id":1,"method":"prompts/list","params":{}}' | jq '.result.prompts | length'` → `7`.
