# Task 9: Code Audit

## Required Skills

- `/skill:code-reviewing` — [skills/code-reviewing/SKILL.md](~/.claude/skills/code-reviewing/SKILL.md)

## Description

Full-feature code quality audit across all source files created or modified by Tasks 1-8. Audit is **analysis-only** — produces a report; if findings emerge, the feature-execution lead spawns a fixer agent and this auditor becomes a reviewer for the fix.

## What to do

Read the source files from each implementation task and review holistically for cross-component issues. Focus areas:

- **SQLite lock discipline** (patterns.md): no `.await` held across `rusqlite::Connection` mutex; no `.await` held across `DashMap` shard guards (Task 4's confirmation ledger). Both lock classes must be released before any async boundary.
- **Arc<McpState> singleton compliance**: confirmation ledger, embedder, sqlite store all live on the single `Arc<McpState>`; no duplicate construction in mcp-stdio vs run_http paths (per Decision 6).
- **Error code conventions** (mcp/src/mcp.rs:93-228): new typed errors from Task 4 follow the existing `data: { kind, ... }` discriminator convention; no overlap of `code+kind` pairs.
- **No `unwrap()` outside tests** (patterns.md). All fallible paths return `anyhow::Result` or typed `JsonRpcError`.
- **Manifest content quality** (Task 1): each manifest in `mcp/assets/skills/*.md` has substantive Purpose + Trigger content (no placeholder tokens). `mnemonik-attest.md` has both positive and negative trigger examples per R8 mitigation.
- **HMAC binding correctness** (Task 4): the byte tuple consumed by `mac.update()` exactly matches the documented `content_hash || owner_pubkey || visibility || expires_at || jti`. No accidental field reordering, no missing fields, no length-confusion vulnerabilities (e.g., if `content_hash` is variable-length and concatenated without a length prefix, an attacker could potentially forge a token whose binding shifts a byte from one field into another — verify length-stable encoding).
- **Atomic single-use enforcement** (Task 4): `DashMap::remove_if` is used, not `contains_key + remove` which would TOCTOU-race.
- **JWT-required-at-mint** (Task 4): `request_public_write_confirmation` handler signature takes a non-optional `Claims` parameter; not in `ALLOWLIST_METHODS`.
- **Visibility re-resolution after escalation** (Task 5): the soft-fall path actually re-runs `resolve_visibility` against the now-participate mode, so a malicious `mode=local + visibility=public + allow_fallback=true + no_confirmation_token` request cannot bypass the gate.
- **MNEMONIC_HOSTED_ENDPOINT gating** (Task 5): default endpoint is compile-time-baked; env var only read when `--allow-custom-endpoint` is set; stderr warning emitted otherwise.
- **`gh attestation verify` argv pinning** (Task 7): the `child_process.spawn` argv contains exactly the three required flags (`--owner`, `--repo`, `--signer-workflow`). No silent omission.
- **zip-slip hardening** (Task 7): tar extraction filter actually rejects paths resolving outside the cache directory; symlink entries are skipped, not extracted-then-removed.
- **Atomic config write** (Task 7): install-hosts.ts writes to `<candidate>.mnemonik.tmp` and `rename`s. No window where a host process could read a partial file.
- **release.yml permissions** (Task 8): `id-token: write` and `attestations: write` only on the jobs that need them. No accidental org-wide elevated scope.

Write the audit report to `work/agent-native-distribution/logs/working/task-9/audit-report.md` summarizing findings by severity (critical / major / minor) with file:line citations.

If no findings: write a brief "all clear" report with explicit confirmation that each focus area was checked.
