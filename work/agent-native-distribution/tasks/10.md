# Task 10: Security Audit

## Required Skills

- `/skill:security-auditor` — [agents/security-auditor.md](~/.claude/agents/security-auditor.md)

## Description

Full-feature security audit across all source files created or modified by Tasks 1-8. Analysis-only; findings trigger a fixer + reviewer cycle if necessary.

## What to do

Audit for OWASP Top 10 plus protocol-specific concerns. Each item is a focus area; for each, verify the implementation actually closes the threat, or document the residual risk.

- **Anonymous discovery surface expansion** (Task 2): the four new MCP methods (`prompts/list`, `prompts/get`, `resources/list`, `resources/read`) leak only manifest content + embedder fingerprint. Verify nothing tenant-scoped (no `owner_pubkey`, no count of attestations, no recent-write summaries) escapes via the new arms. Verify the `resources/read` URI scheme `mnemonik://skills/<name>.md` is constrained — no path traversal (e.g., `mnemonik://skills/../../etc/passwd`).
- **Visibility filter SQL injection** (Tasks 3, 4): the `WHERE visibility = ?` clause uses parameterized rusqlite binding, not `format!()`. Verify no `format!("WHERE visibility = '{}'", ...)` patterns leaked through.
- **HMAC confirmation token correctness** (Task 4):
  - Binding tuple covers `content_hash || owner_pubkey || visibility || expires_at || jti`. If any field is variable-length, verify length-stable encoding (length-prefix or fixed-width separators).
  - HMAC secret is generated by `rand` from a cryptographically secure source (not `rand::thread_rng` if that's not the secure variant; prefer `OsRng` or equivalent).
  - HMAC secret is process-scoped (regenerated per `McpState::build()`), not persisted.
  - Cross-owner replay: consume re-validates `claims.sub == bound_owner_pubkey`. Verify Task 4's implementation actually checks this, not just HMAC reconstruction (in case the implementer derived `owner_pubkey` from request body instead of `claims.sub` at consume).
  - Concurrent consumption: `DashMap::remove_if` is the only consume path, not separate `contains_key` then `remove` (which is TOCTOU-vulnerable).
  - Background eviction prevents unbounded growth under abuse (`request_public_write_confirmation` flood).
- **JWT-required at mint** (Task 4): `request_public_write_confirmation` NOT in `ALLOWLIST_METHODS`. Anonymous mint is impossible.
- **Token file permissions** (Task 6): `~/.mnemonic/token.json` is mode `0o600` after write. Atomic tempfile + rename (no half-written window). Malformed JSON degrades to None, never panics.
- **MNEMONIC_HOSTED_ENDPOINT redirection vector closure** (Task 5, Decision 12): without `--allow-custom-endpoint`, env var is ignored even if set. Stderr warning emits exactly once at startup, doesn't leak token bytes.
- **allow_fallback + visibility-rejection bypass closure** (Tasks 4, 5, Decision 4): construct the attack — `mode=local + visibility=public + allow_fallback_to_participate=true + no public_write_confirmation`. Trace through the code; verify the post-escalation re-resolution returns `-32095`. Verify NO code path lets this combo successfully chain-write.
- **Soft-fall stderr leakage** (Task 5): the warning line on escalation does NOT include token bytes, JWT contents, content secrets, or anything beyond the documented `{pubkey_truncated} {content_hash_truncated} visibility=<v>` format.
- **gh attestation verify argv pinning** (Task 7): the `--owner mnemonik-xyz --repo mnemonik-xyz/monorepo --signer-workflow .github/workflows/release.yml` flags are passed to `child_process.spawn` exactly as documented. Verify there's no fallback path that calls `gh attestation verify` WITHOUT the publisher pins (e.g., if the first call fails, no "retry without pins" loop).
- **`gh` CLI absence behavior**: if `gh` is missing, the install errors out with clear message; does NOT fail-open (no fallback to "SHA256 only" verification).
- **zip-slip hardening** (Task 7): the `tar.extract` filter is empirically tested against malicious fixtures (paths resolving outside cache dir, symlinks).
- **Install host-config writes** (Task 7, Decision 9):
  - `lstat` symlink check refuses symlinks whose targets escape `$HOME`.
  - Atomic tempfile + rename used; no partial-write window.
  - No path traversal in candidate paths (they're hardcoded constants, not derived from user input).
- **No `unwrap()` in production paths** (patterns.md). All fallible paths use `Result`.
- **No secrets in logs** (patterns.md): grep all `tracing::*!` calls + `eprintln!` in modified Rust files; grep `console.*` in Node shim; verify no JWT bytes, no token contents, no HMAC secrets escape.
- **release.yml permissions blast radius** (Task 8): each job's `permissions:` block is minimal. `id-token: write` only on jobs that mint OIDC tokens. No `contents: write` on jobs that don't need to write.
- **No admin override / god-key path** (user-spec hard rule): grep all new code for any conditional that grants special access based on an env var, hardcoded pubkey, or compile-time constant. There must be NO `if pubkey == ADMIN_KEY` or equivalent anywhere.

Write the audit report to `work/agent-native-distribution/logs/working/task-10/audit-report.md` with severity, file:line citations, and explicit threat-model reasoning for each finding.
