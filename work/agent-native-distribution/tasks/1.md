# Task 1: Skill manifests + build-time projection

## Required Skills

- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Create the seven skill manifests for `mnemonik-help`, `mnemonik-init`, `mnemonik-recall`, `mnemonik-attest`, `mnemonik-checkpoint`, `mnemonik-verify`, `mnemonik-status` under a new `mcp/assets/skills/` directory. Wire a `build.rs` build script that parses each manifest's `## Purpose` and `## Trigger` H2 sections and emits compile-time string constants for downstream use by Task 2 (`tool_definitions()` enrichment + `prompts/get` + `resources/read`). Single source of truth — markdown is the only place these strings live.

## What to do

- Create `mcp/assets/skills/` directory (it does not exist today per code-research §7).
- Write seven manifests. Each has H1 title, `## Purpose` (1-2 sentences), `## Trigger` (positive AND negative examples — critical per user-spec R8), `## Context to gather`, `## Tool` (the underlying MCP tool name + argument shape), `## Guardrails`. For `mnemonik-attest` specifically: trigger boundary must distinguish consequential decisions (commit landed, design choice recorded) from transient scratch.
- Write `mcp/build.rs` that scans the assets directory at build time, parses each file's H2 sections, and emits a Rust module containing one `pub const` per manifest with three slots: `FULL_MARKDOWN: &str`, `PURPOSE_PLUS_TRIGGER: &str`, `PURPOSE_ONE_LINER: &str`. The generated module is `include!()`-able from `mcp/src/mcp.rs`.
- Add a build-time check: if `mcp/assets/skills/` is missing a file referenced by any constant, OR if any manifest is missing `## Purpose` / `## Trigger`, the build fails with a clear message.

## TDD Anchor

- `mcp/tests/skill_manifests.rs::all_seven_manifests_parse` — assert that the build-time-generated module exposes exactly 7 manifest constants with non-empty bodies for each of the three slots.
- `mcp/tests/skill_manifests.rs::no_placeholder_tokens_in_manifests` — assert that no manifest body contains literal `TBD|TODO|XXX|FIXME` (catches half-finished content shipping).
- `mcp/tests/skill_manifests.rs::attest_manifest_has_negative_triggers` — assert that `mnemonik-attest`'s `## Trigger` section contains at least one negative example (the load-bearing guardrail per user-spec R8).
- `mcp/tests/skill_manifests.rs::build_fails_on_missing_purpose_section` — temp-fixture test: copy assets to tempdir, drop the `## Purpose` line in one manifest, run `cargo build` via `cargo test --no-run`-style harness, assert build failure message names the offending file.

**Edge cases:**
- Build script run from different working directories — use `CARGO_MANIFEST_DIR` env var for stable paths
- Build script must `println!("cargo:rerun-if-changed=mcp/assets/skills");` so cargo re-runs on manifest edits
- Manifest body may contain backticks, code blocks, links — emit the strings via `concat!()` of escaped fragments OR use `include_str!()` and let the consumer slice

**Implementation hints:**
- Simplest approach: `build.rs` uses `std::fs::read_dir` + line-based parsing (`str::split` on `\n##`). Avoid pulling a heavy markdown parser as a build dep for this — line slicing is sufficient and deterministic.
- Emit one `pub const SKILL_<NAME>_FULL: &str = "...";` etc. per skill in a generated `skills_generated.rs` file written to `OUT_DIR`.
- For `mnemonik-attest.md` trigger examples — base them on user-spec's positive/negative pairing: positive = "user committed code change, design decision recorded, research conclusion written down"; negative = "user is iterating on draft code, intermediate scratch, private content user marked off-record". Capture in the manifest body, not just in code comments.
