# Task 12: SEO — build-time prerender of static routes

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Реализуем real crawl coverage из Decision 4 (tech-spec) и Сценария 6 / Q3
(user-spec): для статических публичных маршрутов (`/`, `/ledger`, `/analytics`,
`/blog`) сборка должна эмитить настоящий статический HTML с корректным `<head>`
(title / description / canonical / OG / JSON-LD), чтобы краулеры и
соц-превью получали реальный контент, а не пустой SPA-shell.

Head hoisting в React 19 (`<Seo>` из T5) даёт per-route meta только на пути
гидрации в браузере — для краулеров этого недостаточно (user: «real crawl
coverage»). Эта задача добавляет build-time prerender-шаг, который рендерит
указанные маршруты в статический HTML на этапе `npm run build`, **захватывая
вывод React 19 head hoisting** в финальный `<head>` каждого `dist/.../index.html`.

Динамический `/blog/:slug` рендерится Rust-сервером — это отдельная задача (T17),
не входит в scope.

## What to do

1. Выбрать самый лёгкий prerender-подход, совместимый с React 19 + Vite 6 SPA
   (например `vite-plugin-prerender`, postbuild-обход `vite preview` через
   puppeteer, или Vite SSG). Критерий выбора: минимум новых зависимостей,
   не требует запущенного backend, захватывает head hoisting React 19.
   Зафиксировать выбор и отвергнутые варианты в `decisions.md`.
2. Добавить prerender только для статических маршрутов `/`, `/ledger`,
   `/analytics`, `/blog`. `/blog/:slug` НЕ включать (это SSR на Rust, T17).
3. Встроить шаг в build pipeline в `webapp/package.json` так, чтобы существующий
   поток `tsc -b && vite build` и WASM-настройка (`mnemonic-core` npm-пакет,
   `build:wasm` escape-hatch) не сломались. Prerender идёт ПОСЛЕ `vite build`.
4. Убедиться, что prerender не требует запущенного backend: статические страницы
   рендерятся на graceful-fallback sample-данных (`sample:true`) ИЛИ на
   empty-state — оба варианта допустимы для crawl-shell (Decision 2).
5. Сохранить CSP без изменений — не добавлять внешние origin'ы/скрипты/шрифты.
6. Добавить конфиг/скрипт prerender в `webapp/` (например
   `webapp/scripts/prerender.*` или секцию в `vite.config.ts`).
7. Написать тест/скрипт-ассерт (TDD): после сборки `dist/ledger/index.html`
   (и аналоги) существуют и содержат ожидаемые head-теги маршрута.

## Details

**Files:**
- `webapp/package.json` — добавить prerender в `build` (после `vite build`,
  напр. `"build": "tsc -b && vite build && node scripts/prerender.mjs"` или
  плагин в vite). Любую новую зависимость — в `devDependencies`. НЕ трогать
  `optionalDependencies` (oxide/lightningcss) и блок `build:wasm`.
- `webapp/vite.config.ts` — при выборе плагинного подхода добавить плагин в
  `plugins: [...]`; не ломать существующий `react()`, `tailwindcss()`, `server`
  proxy и `test` секции.
- `webapp/scripts/prerender.*` (NEW, если postbuild-скрипт) — обход списка
  маршрутов, рендер в `dist/<route>/index.html`.
- `webapp/src/test/prerender.test.ts` (NEW) — ассерт существования файлов + тегов.

**Dependencies:** depends_on T5 (`src/lib/seo.tsx` — `<Seo>` компонент с head
hoisting и JSON-LD). Маршруты `/ledger`, `/analytics`, `/blog` добавляются в
`App.tsx` задачей T9 (Wave 2) — к моменту запуска этой задачи они уже должны
существовать в роутере; если маршрут отсутствует, catch-all `App.tsx`
(`<Navigate to="/" replace />`) отрендерит Landing вместо целевой страницы —
проверить, что целевые маршруты реально зарегистрированы перед prerender.

**Edge cases:**
- `BrowserRouter` (не Hash) — prerender должен резолвить путь через history API
  (puppeteer-навигация на `/ledger`) или статический рендер с указанием
  `location`. Убедиться, что рендерится нужный маршрут, а не редирект на `/`.
- Backend недоступен на этапе билда — клиенты (`ledger.ts`/`blog.ts`) должны
  отдать sample/empty-state, не вешать билд (таймаут/catch). Если выбран
  puppeteer-обход `vite preview`, дать prerender дождаться сетевого fallback.
- React 19 head hoisting: убедиться, что снапшот HTML берётся ПОСЛЕ гидрации/
  применения `<Seo>`-тегов, иначе `<head>` будет пустым (ждать title/meta).
- Cross-platform: oxide/lightningcss native bindings ставятся по платформе
  (см. комментарий optionalDependencies) — не закреплять prerender на конкретную
  ОС; puppeteer/headless chromium увеличивает CI-вес — взвесить против
  vite-plugin-prerender / SSG.

**Implementation hints:**
- Самый лёгкий путь обычно — postbuild prerender статических роутов через
  headless-рендер `vite preview` ИЛИ Vite SSG-подход без отдельного браузера;
  выбрать по весу зависимостей и надёжности захвата head hoisting.
- Список маршрутов держать в одном месте (массив), переиспользуемом и для
  `sitemap.xml`, если удобно (но sitemap — отдельная задача T17/T9).
- CSP: prerender только генерирует статику, не добавляя источников; проверить,
  что в выходном HTML не появились inline-скрипты с внешними src.
