# Task 3: Analytics page (attestations over time)

## Required Skills

Перед выполнением задачи загрузи:

## Description

Build the public **Analytics** page (`/analytics`) — Scenario 2 of the feature:
attestations-over-time. The user opens `/analytics` and sees a custom hand-built
SVG time-series of attestations (on-node vs on-chain split), a range toggle
(30d / 90d / 12m), and summary counters (total on-node, total on-chain, unique
owners). The line animates on load (line-drawing) and respects
`prefers-reduced-motion`.

This is a **Wave 2 frontend page** task. The typed data client
`fetchAttestationTimeline(range)` already exists in `src/lib/ledger.ts` (Wave 1,
DONE) and returns `AttestationTimeline` with sample fallback. The sample-data
generator `sampleTimeline()` and the `<Seo>` component are produced by **Task 1**
(its dependency) — do not re-implement them here.

Per **Decision 3**, NO charting library is installed and none may be added; the
chart is a bespoke SVG that fits the forensic "Evidence Ledger" aesthetic and
adds zero bundle weight. Per **Decision 2**, when the backend endpoint is absent
the client returns `sample: true` data, so this page must render a clear "sample /
not live" banner in that case and never appear to lie about live data.

This task does NOT touch `App.tsx`, `SiteHeader.tsx`, or `SiteFooter.tsx` — the
route registration and nav links are owned by **Task 5** (T9). This task only
creates the page (and optionally a self-contained chart component) and consumes
the shared `SiteHeader`/`SiteFooter`/`<Seo>`.

## What to do

1. Create `webapp/src/pages/Analytics.tsx` — the `/analytics` page in the Evidence
   Ledger aesthetic (dark background, mint = on-node, Solana-purple = on-chain,
   hairline rules, mono tabular numerals). Match the existing tone from
   `Landing.tsx` (technical, factual, no marketing fluff, no emojis).
2. Compose the page from the shared `SiteHeader` + `SiteFooter`, and render `<Seo>`
   (from Task 1's `src/lib/seo.tsx`) with a unique title, description, canonical,
   and JSON-LD for the analytics route.
3. Fetch data via `fetchAttestationTimeline(range)` from `src/lib/ledger.ts`.
   Manage `range` state (default `30d`), loading / empty / error states, and a
   `sample` banner shown when the returned `AttestationTimeline.sample === true`.
4. Build the custom SVG time-series (in `Analytics.tsx`, or a self-contained
   `webapp/src/components/TimelineChart.tsx` if it keeps the page readable):
   - Area/line of attestations over time with separate on-node and on-chain series.
   - X-axis: dates (day buckets for 30d/90d; month-ish labels for 12m). Y-axis:
     counts. Gridlines rendered as hairlines.
   - Animate line drawing with the existing `.animate-draw` utility, setting the
     `--draw-len` CSS custom property to the path length; reduced motion is already
     honored by the utility's `@media (prefers-reduced-motion: reduce)` rule — do
     not add a competing animation that ignores it.
5. Range toggle: 30d / 90d / 12m. Selecting a range refetches and re-renders. The
   toggle must be keyboard-accessible (real `<button>`s or radio group, visible
   focus, `aria-pressed`/`aria-current` on the active option).
6. Summary stat cells: `total_on_node`, `total_on_chain`, `unique_users`, rendered
   in mono with `tabular-nums` (the project already sets `font-variant-numeric:
   tabular-nums` on mono in `index.css`; the Tailwind `tabular-nums` utility also
   works). Reuse a `Stat`-style cell consistent with `Landing.tsx`.
7. Accessibility: the chart container has `role="img"` + a descriptive
   `aria-label` summarizing the trend (e.g. totals and direction over the selected
   range), so screen readers get the gist without the SVG geometry.
8. Write the vitest spec (see TDD Anchor) before implementing.

Do NOT register the route or add nav links — Task 5 owns `App.tsx` /
`SiteHeader.tsx` / `SiteFooter.tsx`. Do NOT add any dependency.

  `<main>` + `SiteFooter`; render `<Seo>`; hold `range` state + fetched

- `webapp/src/components/TimelineChart.tsx` (NEW, optional) — self-contained SVG
  chart. Create only if it keeps `Analytics.tsx` readable; otherwise keep the SVG
  inline. Keep the component pure (props in: buckets + dimensions; SVG out) so the
  geometry is easy to unit-test.
- `webapp/src/pages/Analytics.test.tsx` (NEW) — vitest spec per TDD Anchor.

**Dependencies:**
- **Task 1** must land first: it provides `sampleTimeline()` (appended to
  `ledger.ts`, currently referenced but not yet defined) and `src/lib/seo.tsx`
  (`<Seo>`). `fetchAttestationTimeline` itself already exists. Wave 2.
- No npm packages. React 19, react-router-dom 6, Tailwind 4, vitest 2 + jsdom
  (`vite.config.ts` → `test.environment: "jsdom"`, `setupFiles:
  ["./src/test/setup.ts"]`) are already in place.

**Data contract (from `ledger.ts`, do not redefine):**
- `fetchAttestationTimeline(range: "30d" | "90d" | "12m"): Promise<AttestationTimeline>`
- `AttestationTimeline = { buckets: TimelineBucket[]; total_on_node: number; total_on_chain: number; unique_users: number; sample: boolean }`
- `TimelineBucket = { date: string /* ISO day */; on_node: number; on_chain: number }`

**Edge cases:**
- `buckets` empty → empty state, not a broken/zero-size SVG.
- Single bucket → still render (point/short segment), no divide-by-zero on x-scale.
- All-zero counts → flat baseline, y-axis still sensible (avoid NaN from max=0).
- Range switch while a previous fetch is in flight → ignore the stale response
  (cancellation/last-write-wins flag like `Landing.tsx`'s `cancelled` pattern).
- `sample: true` → banner must be visible; never imply data is live.
- `prefers-reduced-motion` → no motion; `.animate-draw` already returns `animation:
  none`, so just rely on it — don't add a JS-driven animation that bypasses it.

**Implementation hints:**
- Follow `Landing.tsx` patterns: `useEffect` data fetch with a `cancelled` flag,
  the `Stat` cell shape, mono uppercase tracked labels, hairline borders
  (`border-white/5`), `bg-white/[0.02]` panels. Mint = `accent-primary` (on-node),
  Solana-purple = `accent-secondary` (on-chain).
- Compute the SVG path with a manual linear scale (min/max date → x, 0/maxCount →
  y) inside a fixed `viewBox`; render gridlines as thin `<line>`/`<path>` with low
  opacity. To drive `.animate-draw`, set inline `style={{ "--draw-len": length }}`
  (cast via `as React.CSSProperties`) and apply `stroke-dasharray`/`dashoffset` per
  the `@keyframes draw` contract in `index.css`.
- For `aria-label`, summarize: e.g. "Attestations over the last 30 days: N on
  node, M on chain" — computed from the totals so it stays truthful.
- Test pattern: `vi.mock("../lib/ledger", ...)` to return a deterministic timeline;
  `vi.mock("../components/SiteFooter", ...)`; wrap in `<MemoryRouter>`; use
  `findBy*`/`waitFor` for the async resolve. If `<Seo>` (Task 1) renders head tags,
  it should be a no-op in jsdom — mock it if it complicates the test.
