# Проектный контекст знаний (versioned, Arweave-anchored)

## Зачем

Чат на сайте (`/chat`) должен отвечать на вопросы о Mnemonic Protocol,
опираясь на актуальную базу знаний — документацию и Whitepaper — и
**различать версии проекта**: уметь ответить «как было в релизе X» или
«на конкретный момент времени».

Сейчас (после фикса #173) чат снова получает контекст, но:

- база знаний на проде хранится только в SQLite (`STORAGE_MODE=local`) —
  она **не заякорена** на Arweave + Solana, хотя весь смысл протокола в
  этом;
- нет понятия «версия знаний» — нельзя спросить «что было в whitepaper
  v0.2» против текущего;
- вебапп не умеет тянуть знания из Arweave и проверять их — он просто
  ходит в серверный `/chat`.

## Что хотим

1. **Индексация** всех `docs/**/*.md` + Whitepaper → компрессия
   (TurboQuant) → подпись → **сохранение на Arweave + якорь в Solana**
   через Mnemonic MCP (то, ради чего протокол и существует).
2. Каждый засеянный кусок знаний помечается **версией релиза** и
   **временной меткой**, и под каждый посев формируется **манифест
   релиза** (один Arweave-tx как точка входа), перечисляющий все куски.
3. Чат умеет принимать необязательный параметр `release` / `as_of` и
   отвечать строго по знаниям этого релиза / момента времени; по
   умолчанию — последний релиз.
4. Вебапп: выбор версии, получение знаний из Arweave по манифесту,
   распаковка и проверка (verifiable), затем RAG.

## Границы / решения, которые нужны от владельца

- **Финансирование Arweave/Solana**: реальный якорь требует
  `STORAGE_MODE=full` и пополненного keypair (SOL + Irys). До пополнения
  машинерия версий/манифеста работает в `local` (синтетические `local:`
  tx) — то есть фичу можно собрать и протестировать без затрат, а
  «включить on-chain» отдельным шагом.
- **Модель извлечения** (см. tech-spec, Decision R): серверный RAG по
  SQLite (точный, дешёвый) vs полностью клиентский RAG по Arweave
  (доверительный, но менее точный из-за квантизации). Рекомендация —
  серверный RAG + Arweave для верифицируемости/версий, клиентский режим
  как опция позже.
