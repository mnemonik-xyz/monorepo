## Implementation evidence — 2026-10-02

Native source scans retain prior pages and distinguish exhausted, partial, failed and budget-limited results.
The restore command reports diagnostics and returns failure for an incomplete scan after retaining valid imports.
Client recovery preserves original envelopes and complete plaintext for supported memory and sealed formats.
Unsupported kinds and missing keys produce explicit errors.

SDK V1 checkpoints authenticate owner, scope, trusted authors and heads.
Encrypted backups require the independently preserved owner public key and passphrase.
Memory graph completeness requires author and envelope-digest pins for heads and every ancestor.
This avoids treating arbitrary legacy memory IDs as content-addressed references.
See [recovery workflow and limits](../../../docs/recovery-checkpoints.md).

SDK TypeScript checking and strict core-library clippy passed.
Coverage includes key loss, wrong owner, mutable input, missing ancestry, forks, cycles, same-ID substitution and source limits.
