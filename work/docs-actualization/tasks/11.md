# Task 11: Add lychee CI workflow (.github/workflows/docs-link-check.yml)

## Required Skills

Before starting, load: `/skill:code-writing` — [SKILL.md](/Users/syi/.claude/skills/code-writing/SKILL.md)

## Description

Create `.github/workflows/docs-link-check.yml` running `lycheeverse/lychee-action@v2` on push to `dev`/`main` and on PR, scoped to `docs/**` and `*.md` paths only. Uses `--offline` flag (no external URL checks). Job name `lychee-link-check`. No matrix; single `ubuntu-latest` run. Job must exit 0 (broken internal link → fail). Independent of docs content tasks; can run in parallel with W4 doc edits since it touches only `.github/workflows/`.

## What to do

1. **Create** `.github/workflows/docs-link-check.yml` with the following structure (~30 lines):
   ```yaml
   name: Docs link check

   on:
     push:
       branches: [main, dev]
       paths:
         - 'docs/**'
         - '*.md'
         - '.github/workflows/docs-link-check.yml'
     pull_request:
       paths:
         - 'docs/**'
         - '*.md'
         - '.github/workflows/docs-link-check.yml'

   concurrency:
     group: docs-link-check-${{ github.ref }}
     cancel-in-progress: true

   jobs:
     lychee-link-check:
       name: lychee
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - uses: lycheeverse/lychee-action@v2
           with:
             args: --offline --no-progress 'docs/**/*.md' 'README.md' 'docs/WHITEPAPER.md'
             fail: true
   ```

2. **Validate locally** if lychee is installed (`which lychee`): `lychee --offline docs/ README.md docs/WHITEPAPER.md` should exit 0 against the current tree (after Wave 3 promotion). If lychee is not installed locally, skip this step — CI will validate.

3. **Verify the workflow file syntax** is well-formed YAML: `python -c "import yaml; yaml.safe_load(open('.github/workflows/docs-link-check.yml'))"` or `yq '.' .github/workflows/docs-link-check.yml` returns parseable.

4. **Commit** as `ci: add lychee link-check workflow for docs`. (Note: this is a chore-style commit, but `ci:` scope is more conventional for workflow-only changes; either is acceptable per `patterns.md`.)
