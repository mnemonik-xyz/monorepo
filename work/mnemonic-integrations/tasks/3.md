# Task 3: Webapp WASM build pipeline

## Required Skills

Before starting, load: `/skill:infrastructure-setup` — [SKILL.md](/Users/syi/.claude/skills/infrastructure-setup/SKILL.md)

## Description

Wire the `core/` Rust crate (which gains a `wasm` feature in Task 2) into the Vite/React webapp build so that the frontend can call WASM-bound identity helpers (`generate_keypair`, `sign_attestation_bundle`, etc.) directly from the browser. Today `webapp/package.json` has no WASM tooling, no `@mnemonic/core` dependency, and no `wasm-pack` invocation; `webapp/vite.config.ts` only declares the React + Tailwind plugins and a dev proxy. After this task, running `cd webapp && npm run build` produces a `dist/` containing both the JS bundle and the generated WASM artifact, and the WASM JS shim is importable from `webapp/src/wasm/` as a regular ES module.

This task is infrastructure-only: it does not write any application code that calls into WASM (Task 6 does), and it does not implement the Rust bindings themselves (Task 2 does). The deliverable is a reproducible build pipeline plus the documentation hook that `cargo install wasm-pack` is a developer/CI prerequisite.

## What to do

1. Create the build script `webapp/scripts/build-wasm.sh`. It should `set -euo pipefail`, change to the repo root (so the `core` path is resolvable from anywhere), then invoke `wasm-pack build core --target web --out-dir webapp/src/wasm --release --features wasm`. Make it executable (`chmod +x`).
2. Add a `build:wasm` script to `webapp/package.json` that runs `bash scripts/build-wasm.sh`, and rewrite the existing `build` script so it runs `build:wasm` first — typical form: `"build": "npm run build:wasm && tsc -b && vite build"`. Leave `dev`, `preview`, `test:e2e` unchanged.
3. Create `webapp/.gitignore` (the file does not yet exist) including at minimum `node_modules/`, `dist/`, and `src/wasm/` so the generated `.wasm` + JS shim never get committed.
4. Open `webapp/vite.config.ts` and confirm Vite imports the `wasm-pack`-emitted ES module without changes. If it does, leave the file alone. If smoke testing reveals a MIME-type or top-level-await issue, add the minimum fix (e.g. `optimizeDeps.esbuildOptions.target = 'esnext'` or `vite-plugin-wasm`); document the deviation in `decisions.md`.
5. Document `cargo install wasm-pack` as a developer/CI prerequisite. Add a short note to `webapp/package.json` (`"//": "Requires wasm-pack: cargo install wasm-pack"`) or to the project's `deployment.md` if a `Prerequisites` section already exists.
6. Verify with the smoke command in Verification Steps.

## Details

**Files:**

`webapp/scripts/build-wasm.sh` (new) — minimal, repo-root-anchored:
```bash
#!/usr/bin/env bash
set -euo pipefail
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
REPO_ROOT="$(cd "$SCRIPT_DIR/../.." && pwd)"
cd "$REPO_ROOT"
wasm-pack build core --target web --out-dir webapp/src/wasm --release --features wasm
```

`webapp/package.json` — current `build` is `tsc -b && vite build`; rewrite to `npm run build:wasm && tsc -b && vite build` and add `"build:wasm": "bash scripts/build-wasm.sh"` to the `scripts` block. No new runtime dependencies are required — the WASM shim is consumed via a relative path import (`import init from './wasm/mnemonic_core.js'`).

`webapp/.gitignore` (new) — at minimum:
```
node_modules/
dist/
src/wasm/
```

`webapp/vite.config.ts` — leave untouched on the first attempt. `wasm-pack --target web` emits a JS shim that Vite handles natively in modern versions; only intervene if the smoke build surfaces a concrete error.

**Dependencies:**
- This task is wave 1, parallel with Tasks 1 and 2. It does not depend on Task 2 to *create* (the script and package.json wiring stand alone), but `npm run build:wasm` only succeeds after Task 2 has added `#[wasm_bindgen]` exports and the `wasm` feature on `core/Cargo.toml`. Coordinate the smoke verification accordingly — run it after Task 2 merges, not before.

**Edge cases:**
- `wasm-pack` not installed locally: surface a clear error in the build script (`command -v wasm-pack || { echo "install wasm-pack: cargo install wasm-pack"; exit 1; }`) — optional polish.
- Vite's default `assetsInclude` already covers `.wasm`. If a `MIME 'application/wasm'` error appears in the dev server, add `vite-plugin-wasm` and update `vite.config.ts`; record the deviation.
- `webapp/src/wasm/` must NOT be checked in. If a contributor accidentally commits it, the gitignore entry catches future runs but the existing files require manual `git rm -r --cached`.
- `tsc -b` may complain about untyped imports from `./wasm/`. If so, add `webapp/src/wasm/index.d.ts` with `declare module './wasm/mnemonic_core.js'` or rely on `wasm-pack`'s emitted `.d.ts` (it ships one by default with `--target web`).

**Implementation hints:**
- Run `wasm-pack build core --target web --out-dir webapp/src/wasm --release --features wasm` manually once before scripting it, to confirm the exact output and catch any feature-flag issues early.
- Keep the script tiny and `set -euo pipefail` — CI must fail loudly if `wasm-pack` is missing.
- Use `npm run build:wasm` not `bash scripts/build-wasm.sh` directly in CI configs so the package.json remains the single source of truth.
