# Task 2: WASM bindgen wrappers in core (incl. attestation signing)

## Required Skills

Before starting, load: `/skill:code-writing` — [SKILL.md](/Users/syi/.claude/skills/code-writing/SKILL.md)

## Description

Add a new module `core/src/wasm/mod.rs` exposing five `#[wasm_bindgen]` functions that the webapp calls from the browser to manage Ed25519 keypairs and produce COSE_Sign1 attestations entirely client-side. The wrappers compose existing primitives in `core/src/identity/mod.rs`, `core/src/codec/canonical.rs`, `core/src/codec/hash.rs`, and `core/src/codec/sign.rs` — no business-logic changes anywhere else in `core/`.

The five exports are:

1. `generate_keypair() -> JsValue` — creates a fresh `solana_sdk::signature::Keypair` and returns its 64-byte secret as a JSON object `{ "secret": [u8; 64], "pubkey_base58": String }`.
2. `sign_challenge(keypair_json: JsValue, challenge: &[u8]) -> Vec<u8>` — restores keypair from JSON, calls `identity::sign_bytes`, returns the 64-byte Ed25519 signature.
3. `sign_attestation_bundle(content: &str, embedding_bytes: &[u8], content_hash: &[u8], owner_pubkey: &str, keypair_json: JsValue) -> Vec<u8>` — builds the attestation JSON, runs it through `codec::canonical::to_canonical_cbor(artifact, schema)` with the appropriate `ArtifactSchema` (e.g., `crate::codec::schema::MEMORY_V1`), blake3-hashes via `codec::hash::hash_bytes`, and signs via `codec::sign::sign_cose(canonical_cbor, &keypair)`, returning the COSE_Sign1 bytes that a native verifier (`codec::sign::verify_artifact`) can validate.
4. `export_keypair_json(keypair_json: JsValue) -> String` — serializes a keypair JSON object to a downloadable string for backup.
5. `import_keypair_json(json_str: &str) -> Result<JsValue, JsValue>` — parses a JSON backup, validates the secret length and that the embedded pubkey matches, returns the keypair JSON or a descriptive error (never panics).

The entire module is gated by `#[cfg(target_arch = "wasm32")]` AND a new `wasm` feature flag in `core/Cargo.toml`. Native builds (workspace `cargo build`) must not pull in `wasm-bindgen` and must not include the module. `wasm-bindgen-test`-driven tests run only on `wasm32-unknown-unknown` via `wasm-pack test --headless --chrome`.

This task is a foundation for Task 4b (browser-mediated signing) and Task 6 (sign-approval page) — both depend on `sign_attestation_bundle` being callable from the browser.

3. **Implement `core/src/wasm/mod.rs`** with the five functions above. The same `#[cfg(...)]` guard wraps the file body. Use `serde-wasm-bindgen` (not `serde_json::to_value` → `JsValue::from_serde`) for JS interop — the latter is deprecated. Reuse `identity::sign_bytes`, `identity::verify_signature` (note: takes `&Pubkey` — parse base58 via `pubkey_str.parse::<solana_sdk::pubkey::Pubkey>()` first), `codec::canonical::to_canonical_cbor(artifact, schema)` (requires an `ArtifactSchema` arg — import the matching constant from `crate::codec::schema`, e.g. `MEMORY_V1`), `codec::hash::hash_bytes` (the actual exported helper — there is no `codec::hash::blake3` function), and `codec::sign::sign_cose(canonical_cbor, &keypair) -> Result<Vec<u8>, String>`. Errors from `import_keypair_json` must be returned as `Err(JsValue::from_str(msg))`, never `panic!` or `unwrap`.

4. **Mirror the canonical-CBOR field layout** used by the native MCP flow when building the bundle inside `sign_attestation_bundle`. The actual field set and order is defined by `ArtifactSchema::cbor_field_order` in `core/src/codec/schema.rs` — pick the schema constant whose layout matches the bundle (likely `MEMORY_V1`, but verify against the schema definitions and `mcp/src/tools.rs::sign_memory` before locking it in). Pass the schema as the second argument: `to_canonical_cbor(&artifact_json, &MEMORY_V1)?`. The schema-driven encoding is what guarantees byte-determinism and round-trip compatibility with the native verifier.

5. **Write 7 `wasm-bindgen-test` unit tests** at the bottom of `core/src/wasm/mod.rs`, gated by `#[cfg(test)]` plus the same wasm32+feature cfg, per the Testing Strategy in tech-spec:
   - keypair gen produces a valid 64-byte Ed25519 secret with matching base58 pubkey
   - `sign_challenge` round-trip: sign a 32-byte challenge, parse the base58 pubkey to `solana_sdk::pubkey::Pubkey`, verify the signature with `identity::verify_signature(&pubkey, challenge, &sig)` and assert true
   - JSON export → import round-trip preserves both secret and pubkey
   - two `generate_keypair()` calls produce distinct keys (no fixed seed leak)
   - `import_keypair_json("not-json")` returns `Err`, not panic
   - after a simulated page reload (just call `generate_keypair()` twice in the same test), entropy is non-zero and the two keys differ — proves `getrandom` `js` feature is wired and Web Crypto provides entropy
   - `sign_attestation_bundle` round-trip with the native verifier: build a bundle in WASM, then call `codec::sign::verify_artifact(&cose_bytes, Some(&content_hash))` and assert `result.valid`, `result.cose_signature`, and `result.content_integrity` are all true. This proves the WASM-produced COSE_Sign1 is byte-compatible with the native verification path.

6. **Verify natively first:** `cargo build --workspace` (no `--features wasm`) must succeed and must not download `wasm-bindgen` — the wasm feature is off by default. Confirm with `cargo tree -p mnemonic-core | grep -E "wasm-bindgen|js-sys"` returning empty.

7. **Verify on wasm32 target:** `cargo build -p mnemonic-core --features wasm --target wasm32-unknown-unknown` must succeed.

8. **Run wasm-bindgen tests:** `wasm-pack test --headless --chrome core --features wasm` exits 0 with all 7 tests passing.

**Dependencies:**

**Edge cases:**
- `getrandom` without the `js` feature compiles on wasm32 but panics at runtime (`unable to fill randomness`). The `js` feature is mandatory.
- `solana_sdk::signature::Keypair` may pull non-WASM-compatible transitive deps. If wasm32 build fails on a `solana-sdk` feature, narrow to `solana-sdk = { version = "2.2", default-features = false }` or use `ed25519-dalek` directly for the wasm path. Document any deviation in `decisions.md`.
- `wasm-bindgen` version is pinned `=0.2.95` because mismatched runtime/cli versions break loading. Do not bump.
- Do not add `console_error_panic_hook` in production paths — the task is panic-free by contract. It may be wired in tests only if helpful for diagnostics.
- `wasm-pack` must be installed (`cargo install wasm-pack`) before running smoke. CI install is added by Task 7.

**Implementation hints:**
- Keep `core/src/wasm/mod.rs` under ~250 lines including tests. Helpers like a private `keypair_from_json(JsValue) -> Result<Keypair, JsValue>` reduce boilerplate.
- Prefer `serde-wasm-bindgen` over `JsValue::from_serde` (deprecated since wasm-bindgen 0.2.84).
- For the bundle CBOR construction, copy the field-build sequence from native `sign_memory` exactly — any drift breaks the cross-verifier round-trip in Task 7's `roundtrip_cose_via_http_proxy.rs`.
- Run the native build first; it's fast and surfaces feature-flag mistakes immediately.
