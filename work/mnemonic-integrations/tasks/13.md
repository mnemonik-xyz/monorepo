## Description

Acceptance testing gate before deploy. Run the full local test suite, walk through every MUST item from `user-spec.md` and every Acceptance Criterion from `tech-spec.md`, execute the manual smoke checklist on a clean laptop, and produce a pass/fail report appended to `decisions.md`. This is the last quality gate before Task 14 (Deploy); any FAIL here blocks the deploy task and routes the issue back to a fixer.

This task does not modify any source files — it only verifies the work delivered by Tasks 1-9 (implementation) and integrates findings from Tasks 10-12 (code, security, test audits). Output is a single structured report that the deploy task reads to confirm the green light.

## Details

**Environment for the local-server run:** `EMBED_PROVIDER=fastembed` (built with `--features local-embed`) downloads a ~22MB ONNX model on first run and caches it for subsequent runs. The mock embedder is `#[cfg(test)]`-only and is not selectable via `EMBED_PROVIDER` (`mcp/src/config.rs` only accepts `fastembed` and `openai`). `STORAGE_MODE=local` uses SQLite only and synthetic `local:` tx IDs. Mint `TEST_JWT` from the OAuth-flow test fixture or with the helper added in Task 4 — do not hand-craft a token.

**Test list cross-check:** the integration tests named in step 1 are the contract for what Tasks 1-9 must deliver. If any test is missing from `mcp/tests/`, that is itself a FAIL in step 1 — record the missing test by filename and route to the owning task's fixer.

**Audit-finding integration:** before producing the report, read the `## Code Audit (Task 10)`, `## Security Audit (Task 11)`, and `## Test Audit (Task 12)` sections of `decisions.md`. Any finding flagged "blocks deploy" must be reflected as a FAIL in this report unless a follow-up commit has demonstrably resolved it (cite the commit SHA).

**Edge cases:**
- A flaky test that passes on retry is still a FAIL — document the flake, do not silently retry.
- If `npm run build:wasm` requires a wasm-pack toolchain that is not installed, document the prerequisite in the report and treat as FAIL until the deploy host reproduces a green build.
- If MCP Inspector version `0.6.x` reports protocol-version mismatch with the server, pin the inspector version per `tech-spec.md` and rerun.

**Implementation hints:**
- Run automated steps first (cheap, fast feedback). Only proceed to the manual walk-through and smoke checklist once steps 1-5 are green.
- Use a fresh shell and `git status` clean working tree before starting — stale build artefacts have masked regressions in past features.
- Kill the local MCP server (step 5) before running the smoke checklist on the same machine to avoid port collisions.
