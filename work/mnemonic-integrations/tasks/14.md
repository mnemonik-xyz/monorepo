# Task 14: Deploy hosted MCP + webapp

## Required Skills

Before starting, load: `/skill:deploy-pipeline` — [SKILL.md](/Users/syi/src/sessions/2/.claude/skills/deploy-pipeline/SKILL.md)

## Description

Deploy the hosted MCP server to `mcp.mnemonik.xyz` and the webapp (landing + install-hub + identity panel + `/sign/<id>` route) to production after Task 13 (Pre-deploy QA) passes. This is the production cut-over for the `mnemonic-integrations` feature: once both endpoints are live, Cursor / Claude.ai users can complete the OAuth install flow via Smithery, and webapp visitors can sign memories with a browser-held keypair.

Two parallel sub-tasks under one wave-5 unit:

1. **MCP server deploy** — pull `dev`, rebuild release binary on the existing VPS, add the new `MCP_JWT_SECRET` env var (Decision 11), restart `mnemonic-mcp.service`, tail logs to confirm clean startup. The `mcp.mnemonik.xyz` nginx server-block and SSL cert were already provisioned in Task 6, so this task only re-deploys the binary and updates env.
2. **Webapp deploy** — build the Vite bundle (with the WASM workspace), publish either via Cloudflare Pages (`wrangler pages deploy dist/`, or auto-deploy on push to `dev`/`main`) or via `rsync` to `/home/claude/monorepo/webapp/dist/` on the VPS, and verify the CSP header is sent on responses.

Smithery listing was already submitted in Task 6; this task only verifies the install-deeplink resolves to `mcp.mnemonik.xyz` after the new MCP is live. Per Deviation 7, the server keypair is NO LONGER required for the hosted MCP (signing happens client-side); confirm `mcp.env` does not pin a server keypair for the OAuth flow.

## What to do

**MCP server deploy (VPS at `claude@150.251.147.215`):**

1. SSH to the VPS: `ssh claude@150.251.147.215`.
2. Update sources: `cd /home/claude/monorepo && git pull origin dev`.
3. Build release binary: `source ~/.cargo/env && cargo build --release -p mnemonic-mcp --features local-embed`.
4. Update `/home/claude/mcp.env` to add `MCP_JWT_SECRET`. Generate and append in a single one-liner so the env var name and value land on the same line:

   ```bash
   echo "MCP_JWT_SECRET=$(openssl rand -base64 32)" >> /home/claude/mcp.env
   ```

   Keep `STORAGE_MODE=local`, `PAYMENT_MODE=none`. Do not echo the secret to the terminal as a separate step — the redirect above writes it directly. Verify with `grep -c MCP_JWT_SECRET /home/claude/mcp.env` (must print `1`) and `grep MCP_JWT_SECRET /home/claude/mcp.env | grep -c '='` (must also print `1`, confirming `KEY=VALUE` format on a single line).
5. Confirm the `mcp.mnemonik.xyz` nginx server-block and Let's Encrypt cert from Task 6 are in place. First verify the server-block actually exists in the nginx config — `grep mcp.mnemonik.xyz /etc/nginx/sites-available/mnemonic` must return the `server_name` line. If absent, Task 6 did not deploy the block; abort this task and re-run Task 6 before proceeding. Then run `sudo nginx -t && ls /etc/letsencrypt/live/mcp.mnemonik.xyz/` to confirm syntax and cert presence. Do NOT re-run `certbot --nginx -d mcp.mnemonik.xyz` — it was executed once in Task 6.
6. Reload service: `sudo systemctl daemon-reload && sudo systemctl restart mnemonic-mcp`.
7. Verify active: `sudo systemctl status mnemonic-mcp` shows `active (running)`.
8. Tail logs ~30s with `journalctl -u mnemonic-mcp -f --since "1 min ago"` and confirm no panic, no `MCP_JWT_SECRET` value printed, no `MNEMONIC_KEYPAIR_PATH` error (per Deviation 7 the hosted server should not require it for the OAuth flow).

**Webapp deploy:**

1. From the repo root: `cd webapp && npm install && npm run build:wasm && npm run build`.
2. Pick one publishing route and execute it:
   - **Cloudflare Pages (preferred per `deployment.md`):** `wrangler pages deploy dist/ --project-name mnemonic-webapp` — or, if auto-deploy on push to `dev`/`main` is wired in `.github/workflows/deploy.yml`, push the merge commit and wait for the workflow to finish. Confirm the deploy URL is mapped to `mnemonik.xyz`.
   - **VPS nginx (fallback):** `rsync -av --delete webapp/dist/ claude@150.251.147.215:/home/claude/monorepo/webapp/dist/` then `ssh claude@150.251.147.215 'sudo nginx -t && sudo systemctl reload nginx'`.
3. Verify CSP header is sent on responses: `curl -sI https://mnemonik.xyz/install | grep -i content-security-policy` returns one matching header line.
4. Confirm the webapp nginx server-block (the `mnemonik.xyz` block — NOT the `mcp.mnemonik.xyz` subdomain block) has an SPA fallback so client-side routes resolve to `index.html`. Run `grep -E 'try_files\s+\$uri\s+\$uri/\s+/index\.html' /etc/nginx/sites-available/mnemonic` (or wherever the `mnemonik.xyz` server-block lives) and confirm at least one match. Without this directive, `/install` and `/sign/<id>` will return 404, and Cursor / Claude.ai redirects to `/sign/abc123` from the OAuth flow will break. If the block is on Cloudflare Pages instead of nginx, confirm `_redirects` (or `wrangler.toml` SPA mode) routes unknown paths to `/index.html` with status 200.
5. If a new `.github/workflows/deploy.yml` was needed for Cloudflare auto-deploy, commit it on a `feat/deploy-workflow` branch with the standard `feat(ci):` scope; do NOT add it inside this task without a separate PR review.

**Edge cases:**
- If `git pull origin dev` reports merge conflicts on the VPS, abort and inspect — do not force-pull. The VPS working tree should be clean before deploy.
- If `cargo build --release` runs out of memory on the 4GB VPS (per `deployment.md` Known Issues), confirm the 4GB swap from Server Setup is active (`swapon --show`).
- If `wrangler pages deploy` fails because `CLOUDFLARE_API_TOKEN` is unset on the workstation, fall back to the VPS `rsync` route — do not paste the token into a shell.
- If `journalctl` shows `MNEMONIC_KEYPAIR_PATH` is required and startup aborts, that contradicts Deviation 7 — stop, do not paper over it; raise the contradiction in `decisions.md` under "Task 14 — deploy" before touching env.
- CSP header must NOT contain `'unsafe-eval'` (security-auditor finding from Task 10 audit wave). Re-confirm during smoke.

**Implementation hints:**
- Generate the JWT secret on the VPS (not a workstation) so it never leaves the box. Use the single-line redirect from "What to do" step 4 — `echo "MCP_JWT_SECRET=$(openssl rand -base64 32)" >> /home/claude/mcp.env` — which atomically emits a valid `KEY=VALUE` line. Do NOT split this into two appends (writing `MCP_JWT_SECRET=` first, then piping `openssl rand` output) — that produces two malformed lines and breaks env loading.
- For the webapp build, `npm run build:wasm` must succeed before `npm run build` — Vite imports the WASM package as a workspace dep.
- Tail `journalctl -u mnemonic-mcp -f` in a second SSH window during the restart so any panic surfaces immediately.
- The `/sign/test-uuid` smoke check must return 200 even with no pending bundle — the SPA renders an "unknown bundle" state. If it returns 404, the SPA fallback (`try_files $uri $uri/ /index.html`) is missing from nginx.
