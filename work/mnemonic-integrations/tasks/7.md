## Required Skills

Before starting, load: `/skill:code-writing` — [SKILL.md](/Users/syi/.claude/skills/code-writing/SKILL.md)

## Description

Replace the current internal-state view-switching in `webapp/src/App.tsx` (a `useState<View>` toggle between `LandingPage` and `ChatPage`) with URL-based routing via `react-router-dom@^6.27.0` (a new webapp dependency, see Decision 8 / Deviation 4). The existing chat demo at `/` moves to `/chat` and keeps its current behavior verbatim. Three new routes are added on top of the WASM bindings produced by Task 3:

- `/` (Landing) — protocol pitch + a single "Get started" CTA that navigates to `/install`. Tone: technical/precise per `ux-guidelines.md`.
- `/install` (install-hub) — deeplink buttons for Cursor, VS Code, Claude.ai (paste-URL modal) plus an inline identity panel with Generate / Import / Export keypair actions backed by WASM (`generate_keypair`, `import_keypair_json`, `export_keypair_json`) and a DID/pubkey display in base58. The page also wires `sign_challenge` for the OAuth challenge-signing step that establishes the JWT during install (read by other Install-flow components).
- `/sign/<correlation_id>` (sign-approval) — the page Cursor / Claude.ai redirects users to after a `mnemonic_sign_memory` call (see tech-spec Decision 4 + Decision 12). Fetches the pending bundle from `GET /api/pending/<id>` with the existing JWT, shows a monospace content preview + length indicator + mm:ss countdown until the 5-minute TTL expires, and offers "Sign with my Mnemonic identity" / "Reject" buttons. Sign calls WASM `sign_attestation_bundle(content, embedding_bytes, content_hash, owner_pubkey)` and posts `{correlation_id, cose_signed_bytes, signer_pubkey}` to `POST /api/sign-callback`.

A strict CSP is added to the webapp HTML so the in-browser keypair stays protected against XSS (Risks table — XSS row, Decision 8).

**Edge cases:**
- No identity in localStorage when landing on `/sign/<id>` → redirect to `/install` with a notice; do not let users land on a Sign page without a key.
- Bundle already expired (`GET /api/pending/<id>` returns 410) → render an explicit "expired" state with a "back to AI tool" CTA per Risks table abandonment row.
- Bundle was already signed (second visit returns 410) → same expired state.
- `signer_pubkey ≠ jwt.sub` (server returns 403 on POST) → show error and do not retry; encourage user to import the correct key.
- WASM module fails to load (404, MIME type) → page shows a single retry button instead of a blank screen.
- React Router v6 catch-all: add `<Route path="*" element={<Navigate to="/" replace />} />` so unknown URLs land on Landing.

**Implementation hints:**
- Keep `App.tsx` very thin — just `<BrowserRouter>` + `<Routes>`. Don't reuse the old `view` state.
- `useParams<{ correlationId: string }>()` for the Sign route — validate UUID shape before calling the API.
- localStorage keys: `mnemonic.identity` (full JSON), `mnemonic.jwt` (token from OAuth flow). Centralize in `webapp/src/lib/storage.ts` if both reuse the same accessor.
- The countdown timer: derive from server-provided `expires_at` (epoch ms), recompute on `setInterval(_, 1000)`; clear on unmount.
- Match design tokens already used by `LandingPage.tsx` (Tailwind classes from `webapp/index.css` + `tailwind.config.js`) — the brand surface is `bg-background text-text-primary`.
