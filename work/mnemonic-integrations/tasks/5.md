# Task 5: Browser-mediated signing infrastructure

## Required Skills

Before starting, load: `/skill:code-writing` — [SKILL.md](/Users/syi/.claude/skills/code-writing/SKILL.md)

## Description

Replace the current server-side `mnemonic_sign_memory` pipeline with a browser-mediated, deferred-signing flow per Decision 12. The hosted MCP server stops holding any signing key for AI-tool-originated calls — it only embeds content, builds the canonical-CBOR bundle, parks it in a bounded in-memory store keyed by `correlation_id`, and returns a webapp `approve_url` to the AI tool. The user's browser fetches the bundle, signs it with the WASM keypair (Task 2), and posts the COSE_Sign1 bytes back; the server verifies the signature against `jwt.sub`, persists the attestation, and atomically evicts the entry. This collapses per-call server CPU to a single embed plus CBOR build, eliminates the server-side signing-key single-point-of-trust, and removes the DDoS-magnet incentive on `sign_memory`.

The task introduces a new `mcp/src/pending.rs` module hosting `PendingBundles` (LRU + TTL + per-user soft cap), rewrites `mcp/src/tools.rs::sign_memory` to dispatch into it instead of completing inline, and registers two new authenticated Axum routes on the existing `/api/*` surface. Stdio transport is **not** affected — local CLI flows continue to sign with the local keypair (the rewritten `sign_memory` branches on transport via the JWT-presence check that Task 4 provides).

## What to do

1. **Verify `lru = "=0.12.5"` dep is present in `mcp/Cargo.toml`.** Task 4 owns the `lru` dep addition. Run `cargo tree -p lru` to confirm a single resolved version before starting; do **not** re-add the dep in this task. If Task 4 has not landed it, block on Task 4 rather than introducing a duplicate edit and a merge conflict.

2. **Create `mcp/src/pending.rs`** with a `PendingBundles` struct that internally holds an `lru::LruCache<String, PendingEntry>` (capacity 10000) plus a `HashMap<String, usize>` tracking per-`jwt_sub` count for the soft cap. Wrap in `tokio::sync::Mutex` (held only for the brief insert/lookup/evict critical sections — never across `.await` for I/O). `PendingEntry` holds `{jwt_sub: String, content: String (≤ 32 KB), embedding: Vec<f32>, content_hash: String (blake3 hex per `core::codec::hash::hash_bytes` return type), canonical_cbor: Vec<u8>, metadata: serde_json::Value (≤ 4 KB), exp: chrono::DateTime<Utc>}`. Note: `embedding` is the raw `Vec<f32>` returned by `Embedder::embed`, **not** the TurboQuant-compressed bytes — `save_attestation` requires `&[f32]` (per `core/src/storage/sqlite.rs::save_attestation`), and re-embedding on callback is forbidden (CPU + drift risk). Public API: `insert(jwt_sub, entry) -> Result<String, PendingError>` returns the new UUIDv4 `correlation_id` or `PendingError::PerUserCapExceeded` (mapped to HTTP 429); `get(correlation_id, jwt_sub) -> Result<&PendingEntry, PendingError>` (404 if missing/expired, 403 if `jwt_sub` mismatch); `consume(correlation_id, jwt_sub) -> Result<PendingEntry, PendingError>` removes-and-returns atomically (single-use). All paths reject expired entries (TTL 300s, checked against `entry.exp` on each access; eager sweep on `insert` removes any expired heads while iterating). Validate content + metadata size limits at `insert` time; oversized inputs return `PendingError::OversizedPayload` (HTTP 413).

3. **Register `pending: Arc<PendingBundles>` in `McpState`** at `mcp/src/mcp.rs:48-99`. Initialize from `mcp/src/main.rs` startup (an `Arc::new(PendingBundles::new(10_000, Duration::from_secs(300), 50))`).

4. **Rewrite `mcp/src/tools.rs::sign_memory`** (currently lines 48-171). New signature accepts the `&PendingBundles` and an `Option<&str> jwt_sub` (None for stdio/local-keypair callers, Some for HTTP+JWT callers). Behavior split:
   - **HTTP/JWT path** (`jwt_sub.is_some()`): embed content via `embedder.embed(content)`, run `compressor.compress(&embedding)`, build the same artifact `serde_json::Value` as today **but with `producer` set to `did:sol:<jwt_sub>` and a placeholder `artifact_id`** that is the soon-to-be `correlation_id`, call `to_canonical_cbor(&artifact, &schema::MEMORY_V1)` to produce the bytes, blake3-hash them via `core::codec::hash::hash_bytes`, store the entry via `PendingBundles::insert`, return `serde_json::json!({"status": "awaiting_signature", "approve_url": format!("https://mnemonik.xyz/sign/{}", correlation_id), "correlation_id": correlation_id, "expires_in": 300})`. **No COSE signing, no Arweave, no Solana, no SQLite write happens here.**
   - **Stdio path** (`jwt_sub.is_none()`): preserve the existing inline pipeline byte-for-byte (sign with local `keypair`, write Arweave/Solana for `full` mode, persist via `save_attestation`). This keeps stdio backward-compat.

5. **Add `GET /api/pending/{correlation_id}` route** in `mcp/src/mcp.rs` (or a new `mcp/src/api.rs` if cleaner — at author's discretion, but registration goes through `mcp.rs`'s router build). Auth required: middleware extracts `jwt.sub`; on mismatch with stored `jwt_sub` return 403. Response body is the unsigned `canonical_cbor` bytes with `Content-Type: application/cbor` (per Decision 7, base64 wrapping is webapp's responsibility when posting back). Returns 410 Gone when the entry is expired or already consumed.

6. **Add `POST /api/sign-callback` route**. Body schema: `{"correlation_id": String, "cose_signed_bytes": String (base64), "signer_pubkey": String (base58)}`. Auth required. Validation order:
   1. Look up entry; return 410 if missing/expired/consumed.
   2. Assert `signer_pubkey == jwt.sub`; else 403.
   3. Decode `cose_signed_bytes` from base64; call `core::codec::sign::verify_artifact(&cose_bytes, Some(&entry.content_hash))` — returns `Result<VerificationResult, String>` where `VerificationResult { valid: bool, signer: String, content_hash: String, .. }`. Assert `result.valid == true && result.signer == signer_pubkey` (the recovered Ed25519 signer string-equals the body's `signer_pubkey`, which step 2 already proved equals `jwt.sub`). Any failure → 401.
   4. **Atomic** `consume` — pop the entry from the LRU under the same lock used for the lookup, so a concurrent second callback cannot pass step 1.
   5. Persist via `store.lock().unwrap().save_attestation(...)` using `entry.content`, `content_hash`, `entry.embedding`, `owner_pubkey = jwt.sub`, synthetic `local:` tx IDs (Decision 4). Return `{"status": "ok", "attestation_id": <uuid>}`.
   - Replay: a second callback for the same `correlation_id` finds the entry already consumed and returns 410 Gone.

7. **Create `scripts/test-deferred-sign-flow.sh`**: full-flow helper that (a) runs `bash scripts/test-oauth-flow.sh` to obtain a JWT (Task 4 produces this script), (b) POSTs `tools/call mnemonic_sign_memory` and parses the `correlation_id`, (c) `GET /api/pending/<id>` to fetch the bundle, (d) signs with a test Ed25519 keypair using a small `cargo run --example sign_pending` helper (or inlined `python` Ed25519 if simpler — author choice, document in script header), (e) POSTs `/api/sign-callback`, (f) calls `tools/call mnemonic_recall` and asserts the persisted memory is returned. Exit non-zero on any failure.

8. **Wire routes** in `mcp/src/mcp.rs`'s router builder alongside the existing `/api-keys`, `/balance`, `/deposit` routes (auth middleware is added by Task 4). Document the new endpoints in the file's module-level doc comment.

**Dependencies:**
- Task 2 (WASM bindgen) is required because the integration test will reuse the same `sign_attestation_bundle` primitive via a native equivalent (or a small test helper). The native-side equivalent already exists as `core::codec::sign::sign_artifact` — the test signs with a test keypair directly.
- Task 4 (OAuth + middleware) is required: this task assumes JWT extraction has already populated request extensions with `jwt.sub`. If Task 4 is incomplete, the HTTP integration tests cannot mint valid JWTs.
- Shared file conflict: `mcp/src/tools.rs`, `mcp/src/mcp.rs`, `mcp/src/main.rs` — also touched by Task 4. Wave 2 task ordering: Task 4 lands first (and owns the `mcp/Cargo.toml` `lru` dep addition), then this task rebases on top and consumes the dep.

**Edge cases:**
- Clock skew: `chrono::Utc::now()` is the single source of truth for both `exp` set on insert and the comparison on get/consume. No external time service.
- Lock discipline: `tokio::sync::Mutex<Inner>` rather than `std::sync::Mutex` because Axum handlers are async; the critical section is bounded (no `.await` inside). The `save_attestation` SQLite call in the callback handler MUST happen **after** the LRU lock is released — drop the guard explicitly before the SQLite block.
- Embedding stored in pending entry: field is `embedding: Vec<f32>` (clone of `embedder.embed(content)` output). On callback, pass `&entry.embedding` directly to `save_attestation`. **Never** store the TurboQuant-compressed bytes in `PendingEntry` — they exist transiently to feed the canonical-CBOR build, then are dropped. **Never** re-embed on callback (CPU waste + drift risk).
- COSE verification path: the callback verifies `cose_signed_bytes` against `entry.content_hash` (hex). `verify_artifact` returns `Result<VerificationResult, String>` (struct, not tuple) with fields `valid`, `signer`, `content_hash`, `payload`, `cose_signature`, `content_integrity`, `algorithm_valid`. The handler asserts `result.valid && result.signer == signer_pubkey`; any deviation maps to HTTP 401. Internal hash check is already covered by `verify_artifact` because `expected_hash` is passed in.
- 32 KB / 4 KB limits use UTF-8 byte length, not char count.
- Error mapping: every `PendingError` variant has a single `StatusCode` mapping; document in module doc.

**Implementation hints:**
- Use `lru::LruCache::new(NonZeroUsize::new(10_000).unwrap())`.
- For the per-user counter: increment on `insert`, decrement on every removal path (`consume`, TTL eviction, LRU eviction). LRU eviction is tricky — use `LruCache::peek_lru` + manual `pop` rather than push-and-let-it-evict, so the eviction site can decrement the counter for the displaced `jwt_sub`.
- When testing TTL, `tokio::test(start_paused = true)` + `tokio::time::advance` is the standard pattern; verified in existing `mcp/tests/` setup.
- For the helper script's keypair-signing step, the cleanest path is `cargo run -p mnemonic-mcp --example sign_pending` (add a tiny example file under `mcp/examples/sign_pending.rs`) — keeps Rust-only, no Python dependency.
