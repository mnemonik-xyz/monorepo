# Task 1: Trajectory schemas in `mnemonic-core`

## Description

Register `STEP_V1`, `VERDICT_V1`, `TRAJECTORY_V1` in `core/src/codec/schema.rs`,
following the existing `ArtifactSchema` / `cbor_field_order` pattern. Gate the new
`ArtifactType` variants and constants behind cargo feature
`trajectory-experimental`. Do NOT mutate any existing schema or field order.

## What to do

1. Add `trajectory-experimental` feature to `core/Cargo.toml`.
2. Add three `ArtifactType` variants: `Step` ("step"), `Verdict` ("verdict"),
   `Trajectory` ("trajectory") — with `as_str` / `from_str` arms.
3. Add schema constants (fields per tech-spec §Schemas):
   - `STEP_V1`: required incl. `trajectory_id, seq, prev_hash`; optional
     `verdict_hash, parents, metadata, tags`. `prev_hash` MUST be inside
     `cbor_field_order` (it is part of the signed payload).
   - `VERDICT_V1`: required `step_hash, status, judge`; optional `score,
     proof_ref, proof_kind, rationale`.
   - `TRAJECTORY_V1`: required `trajectory_id, step_count, batch_root`; optional
     `verdict_coverage, chain_valid, is_final`.
4. Extend `get_schema` with the three new `(type, 1)` arms.

## TDD anchors

- `schema::tests::trajectory_schema_lookup` — all three resolve at v1.
- `schema::tests::step_prev_hash_in_field_order` — `prev_hash` ∈ cbor_field_order.
- `schema::tests::cbor_field_order_covers_required` — extend existing loop to
  include the three new schemas (all required fields present in order array).

## Done when

- `cargo build --features trajectory-experimental -p mnemonic-core` succeeds.
- `cargo build --workspace` (no feature) still green — proves gating.
- `cargo test --features trajectory-experimental -p mnemonic-core codec::schema`
  green.
- No diff to `MEMORY_V1` or any existing schema's `cbor_field_order`.
