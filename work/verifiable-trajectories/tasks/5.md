# Task 5: MCP tools — attest_step, attest_verdict, verify_trajectory

## Description

Expose the trajectory capability over MCP in `mcp/src/tools.rs`. Reuse the
existing signing pipeline and the `correlation_id` / `check_pending` deferred-sign
plumbing for decoupled prove (ERC-8301 `onAgentStep` / `onAgentProve`).

## What to do

1. `mnemonic_attest_step` — params `{trajectory_id, content, seq?, mode?}`. Auto
   sets `prev_hash` from `store.trajectory_head(trajectory_id)`; if `seq` omitted,
   use head+1 (0 for new trajectory). Signs `STEP_V1` and buffers it into the
   current bundle. **Checkpoint flush:** on every Nth step (or a timer) flush the
   bundle to Arweave and anchor an interim `TRAJECTORY_V1` checkpoint root
   carrying `prev_root`. `local` mode = client cache only (no push);
   `participate` = bundle pushed + anchored.
2. `mnemonic_attest_verdict` — params `{step_hash, status, score?, proof_ref?,
   proof_kind?, rationale?}`. Signs `VERDICT_V1` with the **caller (judge)**
   keypair. REJECT if `judge_pubkey == producer of step_hash` (decisions.md).
   Support deferred attach via `correlation_id`.
3. `mnemonic_verify_trajectory` — params `{trajectory_id}`. Runs
   `lineage::verify_chain` (backend-agnostic, against `ArweaveStore`) +
   `merkle::trajectory_root` over all checkpoints. Returns `{chain_valid,
   broken_at, verdict_coverage, batch_root, proofs[], safe_to_settle}` where
   `safe_to_settle = chain_valid && verdict_coverage == 1.0 && no reject verdicts`.
   The final trajectory summary is written as an **Arweave artifact + anchor** —
   never a server table (stateless MCP).
4. Register all three in the MCP tool list / JSON-RPC dispatch.

## TDD anchors

- `tools::tests::attest_step_links_prev_hash` — second step's prev_hash == first's
  content_hash.
- `tools::tests::verdict_by_producer_rejected` — judge==producer → error.
- `tools::tests::verify_trajectory_happy` — 3 steps + distinct-judge passes →
  chain_valid, coverage 1.0, safe_to_settle true.
- `tools::tests::reject_verdict_blocks_settle` — one reject → safe_to_settle false.
- `tools::tests::checkpoint_flush_anchors_interim_root` — N+1 steps → two bundles,
  second checkpoint's `prev_root` links the first.
