# Task 3: Per-trajectory Merkle batch root

## Description

Extend `core/src/merkle.rs` with an **order-preserving** root over a trajectory's
ordered step hashes (leaf index = `seq`). Distinct from the existing
`commitment_root`, which sorts + dedups (set semantics). See decisions.md.

## What to do

1. Add `trajectory_root(ordered_step_hashes: &[String]) -> [u8; 32]` — leaves in
   given order, NO sort, NO dedup. Reuse existing domain-separation constants
   (`0x00` leaf / `0x01` node) and odd-node promotion. Empty ⇒ existing empty
   sentinel.
2. Add `trajectory_prove(ordered, index) -> Option<(root, Vec<ProofStep>)>` for a
   step by its `seq` index. Reuse existing `verify(leaf_hex, proof, root)` — it is
   order/position-aware via the proof steps.
3. Document in the module header that two root functions coexist with different
   invariants (set vs ordered) and MUST NOT be unified.

## TDD anchors

- `merkle::tests::trajectory_root_order_sensitive` — reordering hashes changes
  the root (contrast: `commitment_root` would not).
- `merkle::tests::trajectory_inclusion_roundtrip` — prove(i) → verify == true for
  every i.
- `merkle::tests::trajectory_wrong_leaf_fails` — verify with a foreign leaf → false.
- `merkle::tests::trajectory_single_and_empty` — n=1 and n=0 edge cases.

## Done when

- `trajectory_root` is order-sensitive and reuses domain separation.
- Inclusion proofs verify for all indices; tampered/foreign leaves fail.
- Tests green; workspace build green.
