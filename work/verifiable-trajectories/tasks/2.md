# Task 2: Chain verifier — materialize `chain_valid`

## Description

Implement ordered-chain verification in `core/src/lineage/`. Today
`chain_valid: Option<bool>` is always `None` ("full verification done
separately"). Make it real for trajectories.

## What to do

1. Add `pub struct ChainVerification { chain_valid: bool, broken_at: Option<u64>,
   verified_steps: usize, total_steps: usize }`.
2. Add `verify_chain(store, trajectory_id) -> Result<ChainVerification>`:
   - Load steps for `trajectory_id` ordered by `seq`; assert dense `0..n`
     (missing/duplicate `seq` ⇒ `chain_valid=false`, `broken_at=first gap`).
   - For each `i>0`: `step[i].prev_hash == step[i-1].content_hash`.
   - For each step: recompute canonical CBOR → blake3 == `content_hash`, and
     `codec::sign::verify_artifact(cose_bytes, Some(content_hash))` ok.
   - `seq==0` must have `prev_hash == None`.
3. In `LineageResult` trajectory walks, set `chain_valid: Some(...)` from the
   verifier instead of leaving `None`.

## TDD anchors

- `lineage::tests::valid_chain_verifies` — 3 signed steps, linked → `true`.
- `lineage::tests::reordered_chain_fails` — swap seq 1↔2 → `false`, broken_at set.
- `lineage::tests::tampered_content_fails` — mutate step content → hash mismatch.
- `lineage::tests::missing_seq_fails` — drop seq 1 → dense-range assertion fails.
- `lineage::tests::genesis_with_prev_hash_fails` — seq 0 carrying prev_hash → false.

## Done when

- `verify_chain` covers ordering, linkage, hash, signature, genesis cases.
- `chain_valid` is materialized (no longer hardcoded `None`) for trajectories.
- Tests green under `--features trajectory-experimental`; workspace build green.
