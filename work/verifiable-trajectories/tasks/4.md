# Task 4: Decentralized step store — Arweave bundles + stateless verify

## Description

Per decisions.md (2026-06-27): keep everything, decentralized, no DB on the MCP
side. Canonical storage is Arweave ANS-104 bundles; the MCP server is a
stateless bundler-relay + verifier. `SqliteStore` is demoted to an optional
local cache, never the canonical store. The unit of write is a **bundle**, not
a step.

## What to do

1. New `ArweaveStore` impl of `AttestationStore` in `core/src/storage/`
   (feature `trajectory-experimental`). Each step → an ANS-104 data item tagged
   `trajectory_id`, `seq`, `owner_pubkey`, `prev_hash`, `verdict_hash`,
   `content_hash`. A checkpoint's data items are packed into one bundled tx.
2. Bundling: prefer Irys/Bundlr client; if rejected, a ~150 LOC in-house ANS-104
   data-item encoder (note the choice in decisions.md). BYO wallet — the Arweave
   signer is supplied by the caller, not the server.
3. Retrieval methods over Arweave GraphQL: `steps_for_trajectory` (tag query,
   ordered by `seq`), `trajectory_head` (max seq + content_hash), `find_by_tx`.
   No server-side persistence on the canonical path.
4. `upsert_trajectory_root` writes the `TRAJECTORY_V1` summary as its own
   Arweave artifact + anchors `batch_root` (Solana SPL Memo today). Checkpoint
   roots reference the prior root (root-of-roots chain).
5. Keep `SqliteStore` working behind a `local-cache` opt-in only; default
   canonical path touches no DB.
