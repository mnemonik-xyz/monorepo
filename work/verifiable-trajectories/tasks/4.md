# Task 4: Decentralized step store — Arweave bundles + stateless verify

## Description

Per decisions.md (2026-06-27): keep everything, decentralized, no DB on the MCP
side. Canonical storage is Arweave ANS-104 bundles; the MCP server is a
stateless bundler-relay + verifier. `SqliteStore` is demoted to an optional
local cache, never the canonical store. The unit of write is a **bundle**, not
a step.

## What to do

1. **Extend the existing ANS-104 code** in `core/src/arweave/mod.rs` from
   single data items to **multi-item bundles**: a checkpoint's steps become data
   items laid out in `seq` order (so the bundle manifest root == Task 3's
   `trajectory_root`), each tagged `trajectory_id`, `seq`, `owner_pubkey`,
   `prev_hash`, `verdict_hash`, `content_hash`. Reuse the existing Irys signer /
   deep-hash path (don't rewrite it).
2. New `ArweaveStore` impl of `AttestationStore` in `core/src/storage/`
   (feature `trajectory-experimental`) over that bundling. BYO wallet — the
   Arweave signer is caller-supplied, not the server's.
3. Add an Arweave **GraphQL tag-query** read path (new to `arweave/`):
   `steps_for_trajectory` (ordered by `seq`), `trajectory_head` (max seq +
   content_hash), `find_by_tx`. No server-side persistence on the canonical path.
4. `upsert_trajectory_root` writes the `TRAJECTORY_V1` summary as its own
   Arweave artifact + anchors `batch_root` (Solana SPL Memo today); each
   checkpoint carries `prev_root` (root-of-roots chain).
5. Keep `SqliteStore` behind a `local-cache` opt-in only; the default canonical
   path touches no DB.
