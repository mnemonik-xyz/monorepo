# Task 4: Storage — trajectory columns + migrations

## Description

Add trajectory persistence to `core/src/storage/sqlite.rs` using the existing
idempotent migration style (`ALTER TABLE ... ADD COLUMN` guarded by a
`PRAGMA table_info` check, matching how `owner_pubkey` / `write_mode` were added).
No backfill; legacy rows keep NULL trajectory fields.

## What to do

1. Migrate `attestations`: add `trajectory_id TEXT`, `seq INTEGER`,
   `prev_hash TEXT`, `verdict_hash TEXT`. Add index
   `idx_attestations_trajectory ON (trajectory_id, seq)`.
2. New table `trajectory_roots(trajectory_id TEXT PRIMARY KEY, batch_root TEXT,
   step_count INTEGER, chain_valid INTEGER, verdict_coverage REAL,
   anchored_tx TEXT, created_at TEXT)`.
3. Store methods: `insert_step` (sets trajectory fields), `trajectory_head`
   (max seq + its content_hash, for `prev_hash` auto-fill), `steps_for_trajectory`
   (ordered by seq), `upsert_trajectory_root`. All parameterized `rusqlite`.
4. Respect lock discipline: never hold the `Mutex<Connection>` across `.await`.

## TDD anchors

- `storage::tests::migration_idempotent` — run migration twice → no error.
- `storage::tests::insert_and_order_steps` — out-of-order inserts read back by seq.
- `storage::tests::trajectory_head_tracks_max_seq` — head returns latest hash.
- `storage::tests::legacy_rows_null_trajectory` — pre-existing rows unaffected.

## Done when

- Migration is idempotent and additive; existing tests still pass.
- New methods covered; `cargo test -p mnemonic-core storage` green.
- `cargo clippy --workspace --all-targets -- -D warnings` clean.
